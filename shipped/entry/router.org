* Entry

Orgasmic rules live in the `/orgasmic` skill (`shipped/skills/orgasmic/`:
`SKILL.md` plus `references/`). Managers: invoke the skill; orgasmic is
opt-in, not an ambient discipline. This output remains for dispatched workers
and CLI-only agents.

** Wake marker
The exact injected marker =: 'ORGASMIC_MANAGER_WAKE_V1'= is a machine wake,
not shell input or user prose. Treat it exactly as =/orgasmic resume=: read the
same brief and immediately continue the next clear action. It carries no task,
project, or instruction text and must not be interpreted as a new command.

** Worker route
A strict dispatched-worker brief names role (implementer, planner, reviewer,
or griller), task id, read/write scope, and acceptance or evidence
expectations. Startup: read the task heading, then `project.org` and
`gotchas.org`, then only the referenced conventions and source files. Verify
graph state through the daemon CLI, naming the project
(`orgasmic task get --project <name> <ID>`), not through the worktree's frozen
`.orgasmic/` snapshot. Finish with `orgasmic dispatch finalize`.

** Write rules
`.orgasmic/` state writes go through the `orgasmic` CLI, never hand-edits. If
the CLI or daemon is unavailable, stop and keep `.orgasmic/` read-only.

** Retired content

nothing, and they look exactly like live configuration.
