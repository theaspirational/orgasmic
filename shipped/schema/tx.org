#+title: orgasmic tx schema (property-drawer-only)
#+version: 1

* SCHEMA tx
:PROPERTIES:
:VERSION: 1
:END:

** Required properties on every tx
- :TX_ID:        globally unique within the file
- :TIME:         org timestamp [YYYY-MM-DD Day HH:MM:SS]
- :TYPE:         from the tx type vocabulary (below)
- :ACTOR:        git config user.email of the operator
- :MACHINE:      hostname

** Key shape on every tx property (TASK-ZKZBF.1, documented TASK-ZKZBF.2)
Every property key — required, per-type, and =--extra= — is =UPPERCASE_SNAKE=
and must match =[A-Z][A-Z0-9_]*=: open vocabulary, closed case. Tx readers
(=extra()= and friends) match keys byte for byte, so a lowercase or
hyphenated key (=:kind:=, =:blocks_ship:=) would be recorded and never read.
Every ledger writer, including =orgasmic tx record --extra=, refuses one at
parse time. Historical agent-authored lowercase extras in older ledgers are
dead weight nothing reads; do not copy the habit — record new extras
uppercase.

*** Run lifecycle
- run.created
- run.failed             (stage completion watcher; =<stage>.failed= with stage "run")

Fresh recovery/resume also reuses =run.created= to record the replacement run
and the generation it continues (TASK-6AYEJ.2). Without it the dispatch
generation cannot resolve the replacement, and a worker finalize from the
recovery run leaves =dispatch-status= showing =[unreported]= forever. Extras:
- :RUN_ID:         replacement run id acquired by the recovery
- :ORIGIN:         =recovery=
- :ORIGIN_RUN_ID:  run id the recovery replaces
- :ACTION:         =resume_native_fork= | =start_recovery_run=
- :KIND:           worker role carried over from the terminal contract

Not emitted for =reattach_tmux=, which preserves the run id and so needs no link.

Dispatch-cycle records:

The authoritative dispatch lifecycle stays in project =tx/YYYY-MM.org=. The
complete routed type set is:
- =manager.dispatch_started=
- =run.created=
- =implementer.commit_pending=
- =implementer.reported=
- =reviewer.reported=
- =architector.reported=
- =implementer.done=
- =reviewer.done=
- =architector.done=
- =fixer.done=
- =manager.dispatch_aborted=
- =manager.dispatch_orphaned=

**** manager.dispatch_started
Properties in addition to the required base properties:
- :PROJECT: project id
- :TASK: task id; subtask paths such as =TASK-ZYPJC.5.1= are valid
- :KIND: =implementer= | =reviewer=
- :WORKTREE: absolute git worktree path
- :BRANCH: branch name created for the dispatch
- :BRIEF_PATH: brief file path (project-relative in committed tx); lives under =<project_root>/.orgasmic/tmp/dispatch/<task-stem>/=. Legacy alias =:CODEX_BRIEF_PATH:= is still read.
- :MODEL: model id, verbatim in the harness's own vocabulary and never validated or defaulted by orgasmic (legacy alias =:CODEX_MODEL:= still read)
- :EFFORT: reasoning effort label, verbatim in the harness's own vocabulary and never validated or defaulted by orgasmic (legacy alias =:CODEX_EFFORT:= still read)
- :STARTED_AT: org timestamp; normally the same value as =:TIME:= for easy grepping
- :WORKER_PID: optional detached child pid; omitted when the tx is appended before spawn (legacy alias =:CODEX_PID:= still read)
- :GOAL_ID: optional active goal id from =goal.org=
- :LIVENESS: optional parent commit sha for crash recovery
- :REASON_INITIAL: optional free text describing dispatch scope
- :NEXT: optional manager follow-up intent, for example =fix-implementer-watch-then-integrate= or =reviewer-watch-then-fix-or-close=

**** implementer.commit_pending
Signal emitted when a cli dispatch run completes with =RunComplete= but the worktree still has uncommitted changes. The manager inspects and decides whether to commit on behalf of the implementer.

Properties in addition to the required base properties:
- :PROJECT: project id
- :TASK: task id
- :RUN_ID: supervisor-assigned run id
- :WORKTREE: absolute git worktree path
- :HAS_UNCOMMITTED: =yes= | =no=

**** implementer.reported / reviewer.reported / architector.reported
The WORKER's own completion record, emitted by =orgasmic dispatch finalize=
(dec_3M7M0). It says "this worker is finished, its report is written, its lease
is released" — it does NOT close the dispatch, which stays open in
=dispatch-status= (flagged =[reported]=) until the manager runs
=dispatch-close=. Before TASK-6AYEJ finalize emitted the =*.done= types below
instead, which closed the dispatch before the manager had read the report, so
worktree/branch cleanup never ran and =:MERGE_SHA:= recorded the worker's own
branch tip. Historical worker-authored =*.done= entries stay valid and stay
closed; there is no migration.

Required properties in addition to the base tx properties:
- :PROJECT: project id
- :TASK: task id
- :RUN_ID: supervisor-assigned run id (how the scan pairs this with its =manager.dispatch_started=)
- :WORKTREE: absolute git worktree path

Optional properties:
- :SHA: the worker's own commit on its branch, when =--commit= was passed. Never =:MERGE_SHA:= — nothing has merged at this point.
- :REPORT_PATH: repo-relative path where the worker report will live after close (=.orgasmic/tasks/<ID>/dispatches/<started_tx>/report.md=). Close promotes =last.txt= there (TASK-QGWK7); until then the streaming sink remains under =tmp/=.
- :REASON: optional free text

**** implementer.done
Emitted by the MANAGER via =dispatch-close= after reading the report, merging,
and deciding, or after accepting a successful report-only dispatch. This is the
record that closes the dispatch.

Required properties in addition to the base tx properties:
- :PROJECT: project id
- :TASK: task id
- :CLOSED_TX: =TX_ID= of the matching =manager.dispatch_started=

Exactly one completion shape is required:
- Source change: :MERGE_SHA: merge commit sha and :BRANCH: branch that landed
- Report only: :REPORT_ONLY: =true=; no merge sha or landed branch is recorded

Optional properties:
- :REPORT_PATH: repo-relative path of the promoted worker report (=.orgasmic/tasks/<ID>/dispatches/<CLOSED_TX>/report.md=). Written automatically when close promotes the tmp artifacts (TASK-QGWK7). The harness =stdout.log= sits beside it; this property always names =report.md=.
- :WORKER_COMMIT: optional commit sha produced by the worker on its branch (legacy alias =:CODEX_COMMIT:= still read)
- :WORKER_SESSION: optional worker session id (legacy alias =:CODEX_SESSION:= still read)
- :MODEL: model id mirrored from =manager.dispatch_started= (legacy alias =:CODEX_MODEL:= still read)
- :EFFORT: effort label mirrored from =manager.dispatch_started= (legacy alias =:CODEX_EFFORT:= still read)
- :WALL: optional free-form duration string
- :TOKENS: optional integer token count
- :FILES_CHANGED: optional integer
- :INSERTIONS: optional integer
- :DELETIONS: optional integer
- :BUILD_GATE: optional free text describing build or test verification
- :GOAL_ID: optional active goal id
- :REASON: optional free text describing what landed
- :CLEANUP_STATUS: =ok= | =worktree_failed= | =branch_failed= | =partial= | =worktree_missing= | =cleanup_already_run=
- :CLEANUP_ERROR: optional one-line cleanup failure detail

**** reviewer.done
Required properties in addition to the base tx properties:
- :PROJECT: project id
- :TASK: task id
- :CLOSED_TX: =TX_ID= of the matching =manager.dispatch_started=
- :VERDICT: =clean= | =has-issues= | =blocks-ship=
- :REPORT_PATH: path to the review report. Prefer the auto-promoted
  =.orgasmic/tasks/<ID>/dispatches/<CLOSED_TX>/report.md= (TASK-QGWK7). A manager may
  still pass a curated path via =--property REPORT_PATH==; that overrides the
  auto value while the promoted =last.txt= remains on disk.

Optional properties:
- :WORKER_SESSION: optional worker session id (legacy alias =:CODEX_SESSION:= still read)
- :MODEL: model id mirrored from =manager.dispatch_started= (legacy alias =:CODEX_MODEL:= still read)
- :EFFORT: effort label mirrored from =manager.dispatch_started= (legacy alias =:CODEX_EFFORT:= still read)
- :WALL: optional free-form duration string
- :TOKENS: optional integer token count
- :BLOCKS_SHIP: =yes= | =no=
- :FINDINGS_TOTAL: integer
- :FINDINGS_BY_SEVERITY: free-form summary
- :FINDINGS_BY_KIND: free-form summary
- :REVIEWED_DIFF: git range or path-limited range reviewed
- :RECOMMENDED_SUBTASKS: space-separated task ids, or =-= when none
- :GOAL_ID: optional active goal id
- :REASON: optional free text describing review result
- :CLEANUP_STATUS: =ok= | =worktree_failed= | =branch_failed= | =partial= | =worktree_missing= | =cleanup_already_run=
- :CLEANUP_ERROR: optional one-line cleanup failure detail

**** manager.dispatch_aborted
Properties in addition to the required base properties:

- :REASON: required explanation of why the dispatch aborted

- :CLEANUP_STATUS: =ok= | =worktree_failed= | =branch_failed= | =partial= | =worktree_missing= | =cleanup_already_run=

*** Artifact lifecycle
- artifact.created      (artifact folder + artifact.org written for the first time)
- artifact.submitted    (artifact.mdx written or replaced; may follow artifact.created on the same submit)
- artifact.comment.added (a feedback comment appended to reviews.org)
- artifact.comment.resolved (a feedback comment marked resolved + consumed)
- artifact.regenerated  (declared; no write path in TASK-ZEFEY — reserved for TASK-EDQPG)

Properties for =artifact.created=:
- :PROJECT:       project id
- :ARTIFACT_ID:   ART-XXXXX
- :TITLE:         artifact title
- :SUBJECT_NODES: space-separated node ids (arch_XXX, dec_XXX, …)
- :PROMPT:        escaped single-line prompt text

Properties for =artifact.submitted=:
- :PROJECT:       project id
- :ARTIFACT_ID:   ART-XXXXX
- :VERSION:       integer version number written

Properties for =artifact.comment.added=:
- :PROJECT:       project id
- :ARTIFACT_ID:   ART-XXXXX
- :CID:           CID-<hex8> unique comment id
- :AUTHOR:        email | agent.<kind>
- :VERSION:       artifact version the comment is anchored to
- :ANCHOR:        JSON anchor object (default ={​}=)
- :RESOLUTION_TARGET: optional CID this comment resolves

Properties for =artifact.comment.resolved=:
- :PROJECT:       project id
- :ARTIFACT_ID:   ART-XXXXX
- :CID:           CID of the resolved comment
- :RESOLVED_BY:   actor email / agent id

Properties for =artifact.regenerated= (reserved; no write path yet):
- :PROJECT:       project id
- :ARTIFACT_ID:   ART-XXXXX
- :FROM_VERSION:  integer version before regeneration
- :TO_VERSION:    integer version after regeneration
