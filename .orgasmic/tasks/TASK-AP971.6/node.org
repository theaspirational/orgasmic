** Question
Which artifact-store code becomes the shared node kernel, and what is its API (read node, append journal, comment, consume-on-regenerate hooks)? Prototype: sketch the module boundary by refactoring artifacts in place on a throwaway branch.
** Resolution
Prototyped 2026-08-22 on the throwaway branch ap971-prototype (commit 41a1faf): crates/orgasmic-core/src/node_kernel.rs — compiles, 3 unit tests + a real-data test that parses all 873 migrated nodes (0.25s).
Boundary: the kernel lives in orgasmic-core (the CLI reads nodes without the daemon). It is pure over file contents — the daemon writer keeps owning every byte — except create_node_dir, whose mkdir IS the id-collision check (.3). API: node_dir / create_node_dir / node_org_header / journal_header; Node + parse_node (one heading: id, title, state=TODO keyword, properties, free body); JournalEntry + parse_journal / journal_entry_block / append_entry (tx drawer grammar + prose body, AP971.1); edit_comment_body (in place, stamps :EDITED_AT:; caller does OCC), tombstone_comment (drops prose, keeps the entry), consume_open_comments → (new content, consumed ids) = the regenerate hook (.10).
artifacts.rs → kernel map: artifacts_dir/artifact_dir→node_dir; new_artifact_id/validate_art_id→mint_node_id(descriptor)+create_node_dir; artifact_org_content/update_artifact_org→node.org header + node write (artifact props stay artifact's); reviews_org_header/comment_org_block/append_comment→journal_header/journal_entry_block/append_entry (CID→TX_ID, ANCHOR/RESOLUTION_TARGET/REPLY_TO→extras, CONSUMED kernel-owned); parse_comments→parse_journal filtered ty=comment; consume_all_open_comments→consume_open_comments; load_artifact/load_project_artifacts→parse_node + dir listing. Stays artifact-only: BLOCK_TYPES, validate_mdx, launch address, versions_dir, artifact.mdx, the RESOLVED axis (set_comment_resolved). The kernel has no regenerate runner and no type knowledge: descriptors (.2) and the supervisor path (.10) sit above it.
