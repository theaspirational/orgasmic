** Description
Battle-test F5 (and the observability half of F4): =parse_errors= reaches agents only as a global opaque count in =/daemon/status= — aggregated across all registered projects, with no project/file/node/reason attribution and no way to tell whether it reflects live reindexing. The structured list already exists (=IndexSnapshot.parse_errors=, crates/orgasmic-daemon/src/index.rs:350, populated via =push_parse_error= with file+reason) but is never exposed. =orgasmic doctor= (crates/orgasmic-cli/src/doctor.rs:35) checks install health only. No reindex verb exists — only boot-time =Index::rebuild= — so the battle-tester restarted the daemon just to confirm a fix. Repeated identical index WARNs spam the daemon log on every pass.

Fix:
- =orgasmic status --errors= (and/or =doctor --project <id>=): list parse errors with project / file / node / property / reason.
- =orgasmic reindex [--project <id>]= verb triggering a rebuild and returning fresh per-project counts.
- Deduplicate repeated identical index WARNs in the daemon log.

An agent should never need to grep ANSI-colored daemon logs to find its own mistake.

** Acceptance Criteria
- [ ] An induced dangling ref is fully attributable (project/file/node/reason) from the CLI alone.
- [ ] =reindex= clears the count after a fix without a daemon restart; per-project counts in output.
- [ ] Identical WARNs emitted once per rebuild, not once per pass.
