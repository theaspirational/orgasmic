** Description

=shipped/prompt-studio/conventions/manager-dispatch.org= carries
=** The standing worker matrix=: a per-stage table pinning =--model= and
=--effort= values, introduced as "Use these unless the task gives you a reason to
deviate".

=shipped/prompt-studio/prompt-specs/manager.org= points every manager at that
convention by name from four separate places, and no live project copy shadows it
(=.orgasmic/conventions/= holds only =concurrent-writer.org= and
=decision-graph.org=).

TASK-0JY7M just landed the opposite policy in =shipped/entry/router.org=: the
manager ASKS the operator once per session, nothing is stored, and a pinned model
identifier is model knowledge that stays per-dispatch. So a manager reading both
now gets two contradictory instructions, and the stored one is the more
convenient to follow.

** Why this is P1 rather than tidying

dec_WDR5K item 9 removed every model and effort identifier from orgasmic code and
config, deliberately, so that vendor model bumps require no orgasmic change. This
table is exactly that knowledge, surviving in shipped content — which is
distributed with the runtime and read by every manager.

It is also STALE in a way that is actively dangerous right now: the matrix says
=--mode tmux= ("mode changed to tmux 2026-07-29"), and on the currently installed
daemon (=57e35de=) tmux has NO pane liveness channel, so a tmux dispatch dies on
the wall clock regardless of progress. That is the defect that destroyed the
TASK-FZB6T.1 worker report on 2026-08-02. A manager following the matrix as
written today would reproduce it.

Note what is NOT in conflict: the matrixs reviewer row already specifies a
different vendor on the review side, which AGREES with TASK-0JY7M item 3. The
conflict is items 1 and 2 — the ask, and the no-storage rule — not reviewer
independence.

** Work

- Remove the pinned =--model= / =--effort= columns, or the table entirely, and
  point at the routers =** Agent selection= section as the single source.
- Keep whatever is genuinely durable and vendor-free: that reviewers run a
  different harness family, that review and risky stages carry an explicit
  effort, that flags are always passed rather than inherited.
- Re-check the =--mode= guidance against reality rather than copying it: tmux is
  only safe once the runtime carries TASK-4CSMY, and the convention should say
  what makes it safe rather than naming a mode.
- Sweep the rest of =shipped/prompt-studio/= for other stored model identifiers
  while there; this one was found by accident.

** Acceptance

- No model or effort identifier remains in shipped content (a grep for
  vendor-model shapes over =shipped/= is clean, and can be the regression).
- Router and convention state one policy; a manager reading both cannot come away
  with contradictory instructions.
- The transport guidance names the property that makes a transport safe, not a
  mode that was safe on one date.
