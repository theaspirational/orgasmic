** Two surviving classes, and the bigger one was named by nobody
1. *Wrapped verbatim* (2 sites). =code_spans= rule (3) requires an org
   ==verbatim== span to close on the same line.
2. *FRAGMENT* (4 sites). =invocations_in_span= only emits an invocation for a
   span containing the literal token =orgasmic=. Prose that names a flag and a
   value without respelling the whole command — which is how conventions
   normally reference a flag — is structurally unreachable. The stage-E
   implementer named class 1 as residual risk; *nobody named class 2*, and it is
   twice the size.

** Scope
*** F1 — reach the invisible sites (the main item)
- Fragment class: when a span names a =VALUE_ENUM_FLAGS= flag with a concrete
  value but no =orgasmic= token, still check it — either resolve against the
  nearest preceding =orgasmic= invocation in the file, or check the value against
  the UNION of that flag's =possible_values= over all leaves declaring it. A union
  check still catches =architector= and =BOGUSKIND=.
- Wrapped class: let rule (3) join a line to the next when the delimiter does not
  close and the span already contains =orgasmic=.

*** F2 — the floor's message misdiagnoses its most likely trip
=MINIMUM_ENUM_VALUE_COMPARISONS = 6= against exactly 6 compared, and the message
says "the extractor or help-entry parser is broken, *not the prose*". Measured:
a legitimate prose reword at =init.md:81= drops the count to 5 and trips the
floor — where that diagnosis is flatly wrong. An engineer who trusts it hunts in
the parser, finds nothing, and lowers the constant. *That is exactly how this
gate gets re-vacuumed.* Keep the floor; fix the message to name both causes and
PRINT the sites still compared, so the two are distinguishable in one read.
Landing F1 also buys real headroom.

*** F3 — =--flag=value= does not survive org verbatim
=enum_values_in_tokens= handles =--flag=value= correctly (proven in a
=#+begin_src= block), but =code_spans= rule (3) splits org verbatim spans on
===, so the equals form in the corpus's DOMINANT markup is truncated before the
new code sees it. Measured: ==orgasmic id mint --class=architecture== yields 0
value failures — =architecture= is the RETIRED class — and the run only goes red
on the count floor, with F2's misleading message.

*** F4 — =--verdict= is a real clap enum and is not in =VALUE_ENUM_FLAGS=
=manager dispatch-close --verdict= renders
=[possible values: approve, approve-with-follow-ups, reject]=, and shipped prose
discusses verdict values at =manager-dispatch.org:336,343=. A =--verdict approvedd=
typo inside a real invocation yields 0 failures. This is the measured cost of
leaving =VALUE_ENUM_FLAGS= hand-maintained, and the argument for deriving it from
the binary's own help — any flag whose entry renders a bracket.

*** F5 — assertion order hides real regressions
The count assertion (=:296=) fires before the value assertion (=:302=). An edit
that both drops a site and introduces a bad value shows only "the extractor is
broken"; the real retired-value regression stays hidden until the count is fixed.
Assert =failures.is_empty()= first, or report both in one panic.
