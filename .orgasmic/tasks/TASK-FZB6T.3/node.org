*1. HIGH, BLOCKS SHIP — the fence is not exclusion.*
=writer.rs:543,975,1315=, =api.rs:7358=, =run_history.rs:993,1051=.

=FenceSession= drops the cached handle ONCE; the next =SessionAppend= simply
reopens the same path. =compact_one_file= archives the bytes it read, stages the
replacement, does ONE final fingerprint check, and renames. An append that opens
and writes between that check and the =rename= lands on the original inode,
which the rename immediately orphans — and the replacement excludes it while the
archive PREDATES it, so rollback cannot recover it either.

The previous round declared this a narrowed, acceptable residual. The reviewer
rejects that with a reason worth repeating: *the archive demonstrably predates
the append it is claimed to recover*, so the "rollback recovers it byte for
byte" argument does not hold for this window. It is also a realistic lifecycle
edge, not a theoretical one — a persisted terminal driver event can make a file
eligible BEFORE the supervisor appends its final =Lifecycle::Release=.

FIX: a writer-owned reservation/lease held until compaction or rollback
COMPLETES. While held, appends for that path queue or fail BEFORE opening.
Release only after rename and journal completion. Add a scheduled
append-at-pre-rename regression proving the final lifecycle line either lands in
the replacement or the transaction refuses.

*2. HIGH, BLOCKS SHIP — the manifest format changed and broke rollback in BOTH
directions.* =run_history.rs:283,1277,1355=.

This round replaced the durable manifest's defaulted =results= array with a
defaulted =files= array, with NO format version and NO compatibility decoder.
So:
- a current runtime reading a TASK-FZB6T.1 manifest ignores =results=, defaults
  =files=[]=, fences nothing, and rollback returns SUCCESS having restored
  nothing;
- an older runtime reading a new manifest does the symmetric thing and also
  reports a successful no-op.

A silent successful-empty rollback is the worst possible failure for the one
mechanism whose entire job is to make deletion recoverable. This is a REGRESSION
introduced by the fix round, not a pre-existing gap.

FIX: version the manifest and support the immediately preceding =results= shape.
Never default a non-empty plan to a successful empty rollback — fail loudly
instead. Both-direction migration tests.

*3. HIGH, BLOCKS SHIP — the structural scanner does not validate JSON.*
=run_catalog.rs:1861,1913,1784=, =run_history.rs:1163=.

=JsonScan::skip_value= accepts any non-empty primitive token and =JsonScan::string=
accepts invalid escapes and control bytes. So
=({"kind":"driver_event","event":{"type":"text_chunk","payload":truX}})= is
INVALID JSON, is classified =rendered_tui=, and =build_compacted= drops its raw
bytes. The nested-key collision from round 1 is genuinely fixed; the fail-closed
rule is not. A malformed legacy record sitting in the skipped middle of an
otherwise terminal pane session gets deleted without ever being proven valid.

FIX: a streaming parser/visitor that VALIDATES every token while retaining only
top-level =kind= and =event.type=, or make the scanner fully validate strings,
escapes, UTF-8, numbers and literals. Regressions for invalid literal, invalid
escape, raw control byte, and byte-for-byte preservation.

*4. MEDIUM — dec_BBPW4 is internally contradictory and needs a DESIGN decision.*
=run_catalog.rs:38,596,1108,1223,1435=.

The tombstone is terminal only for one live =RunCatalog=. The catalog is
explicitly disposable, so an absent/corrupt/foreign-version snapshot is rebuilt
from session bytes, and =verify_worktree_authority= returns =Verified= whenever
the recorded path currently holds a same-project checkout. Therefore
prune -> tombstone -> catalog loss -> path reuse REVIVES the attach candidate.
Snapshot semantic validation also omits =worktree_authority=, so a valid
snapshot can carry a contradictory verdict.

"Disposable derived cache" and "a tombstone never revives" cannot both be true
without a durable authority source OUTSIDE the cache. Pick one and make
dec_BBPW4 say it: either persist terminal tombstones in authoritative lifecycle
state, or stop calling the catalog disposable. Rebuild and foreign-version tests
must cover prune -> tombstone -> catalog loss -> path reuse.

*5. MEDIUM — the re-cut TASK-FZB6T.1 injection does not pin what it claims.*
