* CANCELLED TASK-TH906 manager dispatch --effort is silently dropped for every non-claude harness, and the ledger records it as fact anyway
:PROPERTIES:
:ID: TASK-TH906
:PRIORITY: P1
:END:

** Description
=orgasmic manager dispatch --harness codex --effort high= records =:EFFORT: high=
on the =manager.dispatch_started= tx and =:EFFORT_OVERRIDE: high= on the
=run.created= tx, *and never passes the value to the harness.*

=crates/orgasmic-drivers/src/modes/tmux.rs:989-994= pushes =--effort= only inside
the =if is_claude= block. The non-claude branch at =:1004-1011= pushes =--model=
and nothing else:

: if matches!(harness, "codex" | "cursor-agent" | "hermes") {
:     if let Some(model) = cfg.model.as_ref() { … push "--model" … }
: }

=modes/rmux.rs:1817-1828= has the identical shape — model for everyone, effort
for claude only.

*And =--effort= is not even the right flag for codex.* =codex --help=
(codex-cli 0.144.5) exposes =-m/--model= and =-c/--config <key=value>=; there is
no =--effort=. Reasoning effort is =-c model_reasoning_effort="high"=. So the
push would not have worked had it been reached.

** Measured, not inferred
Dispatch =tx-20260808-orgasmic-5485= (TASK-2QK4P.1.1.1 reviewer, codex, tmux) was
given =--model gpt-5.6-sol --effort high=. Both tx entries record =high=. The
worker's own pane footer read:

: gpt-5.6-sol xhigh · ~/.orgasmic/worktrees/orgasmic/task-2qk4p.1.1.1-review

=~/.codex/config.toml= on this machine carries =model_reasoning_effort = "xhigh"=,
which is what the run actually used. *The flag was dropped and the ledger asserts
otherwise.*

** Why this is P1
1. *The ledger is the product's evidence surface.* An effort recorded but not
   applied makes every dispatch comparison across efforts meaningless, and there
   is no way to tell after the fact which runs honoured the flag.
2. *The manager protocol echoes driver/harness/model/effort after each dispatch.*
   That echo is read by the operator as a statement of what ran. It was false
   here and the manager had no way to know.
3. It is silent. No warning, no refusal, no =unsupported=.

** Acceptance
1. Either PASS the effort to every harness that accepts one — for codex that is
   =-c model_reasoning_effort=<value>=, not =--effort= — or REFUSE the dispatch
   by name when the harness cannot take it. Do not record a value that was not
   applied.
2. If a harness genuinely has no effort control, =dispatch= must say so at
   dispatch time and the tx must not carry =EFFORT=/=EFFORT_OVERRIDE=.
3. Same treatment for =--model= on any harness that ignores it, and the same
   audit for the =rmux= path, which has the identical claude-only gate.
4. A regression per supported harness asserting the launch argv actually carries
   the requested effort, or that the dispatch was refused. =tmux.rs:3238-3255=
   already does this for claude; it has no codex counterpart, which is why the
   gap survived.
5. Check whether =cursor-agent= and =hermes= have effort controls too — they are
   in the same =matches!= arm.
