Two populations are never fixed: (a) an ordinary project checkout that carries =.orgasmic/= committed in its own tree (branch main etc.) — the majority of orgasmic-using repos; (b) an =orgasmic=-branch ledger with no remote. Those repos keep committing a 3 MB derived board.org into user history.
Open design question (decide first): should the DAEMON run =git rm --cached= in a repo it only observes (a mutating git op on the user index), or should this be an explicit operator verb (=orgasmic project migrate= / doctor --fix) plus a doctor warning? The manager leans to the explicit verb + doctor warning: the daemon must not rewrite a user repo index it does not own.
