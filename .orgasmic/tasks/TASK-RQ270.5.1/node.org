** The defect — the gate is already vacuous, not merely able to become so
=possible_values_for_flag= (=crates/orgasmic-cli/tests/cli_parity.rs:246=, with
=:682=) only finds =[possible values: ...]= when the bracket sits on a line that
also contains the flag name. That is clap's *compact* option layout. When an
option's help text is long, clap switches to the *two-line* layout — flag on one
line, description plus the bracket on the next — and the function returns =None=.
=None= is then treated as "free-string flag, skip".

Measured by the reviewer against the built binary, driving the test file's own
functions verbatim:

: possible_values_for_flag(id-mint help,          "--class")  = Some([task, decision, term, artifact])
: possible_values_for_flag(node-body-set help,    "--kind")   = Some([decision, ..., handoff])
: possible_values_for_flag(manager-dispatch help, "--kind")   = None   <-- HAS [possible values: implementer, reviewer]
: possible_values_for_flag(dispatch-close help,   "--status") = None   <-- HAS [possible values: done, aborted]
: possible_values_for_flag(dispatch-close help,   "--verdict")= None   <-- HAS [possible values: approve, ...]

*Across the whole 141-invocation shipped corpus the gate compares exactly 5
values*, all from =id mint= and =node body set= — the two commands whose help
happens to be short enough for the compact layout.

** The proof that it is live, not theoretical
Replaying the test's exact loop over a copy of =shipped/= with one token changed:

: ############ BASELINE ############
: SKIPPED (possible_values=None): manager-dispatch.org: `orgasmic manager dispatch ... --kind implementer ...` flag --kind

=architector= is the worker kind THIS EXCISION REMOVED. Shipped prose telling

** The ruling
=None= currently conflates three cases: (a) a genuinely free-string flag, (b)
clap's multi-line layout, (c) a help-format change. Case (b) is the common one in
this CLI and is live today. *Separate them.*

- Parse =--help= as option ENTRIES rather than lines: on seeing an option line,
  accumulate following lines until the next entry at the same indent, then look
  for the bracket in the whole entry. =split_help_entry= (=cli_parity.rs:366=)
  already does this shape of work for
  =every_flag_and_argument_has_a_description= — reuse it rather than writing a
  second parser.
- Make *"flag not found in the help at all"* a FAILURE, distinct from "flag found,
  no bracket" (= genuine free-string).

The reviewer offered an acceptable alternative if entry parsing is judged too
fragile: invert the default — fail on "flag not found", and maintain a small
explicit allow-list of free-string flags. *Either is fine. Silently skipping is
not.*
