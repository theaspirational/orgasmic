** Description
The babysitter (=babysitter-stall-detector=) is a companion run attached by
explicit manager dispatch when the resolved worker template declares
=:BABYSITTER_WORKER:=. It is not the deleted task-state auto-spawn watcher from
dec_WC1PW, and this task must not reintroduce implicit worker spawns from task
lifecycle transitions.

The companion babysitter has never actually done its job: in practice it either
died at boot (=Not logged in= under the acp-stdio claude harness) or sat idle
until the stall detector reaped it. Investigation [2026-06-11] found the
intervention path is also unwired independent of auth:

- =flush_babysitter_summary= in =supervisor.rs= -- the function that packages
  the implementer's coalesced events into a =BabysitterSummaryChunk= every 50
  events / 60s -- is only ever called from tests. No live daemon loop forwards
  summaries to the babysitter run.
- Its four tools (=poke_implementer=, =escalate_to_human=,
  =restart_implementer=, =record_finding=) are an acp-stdio/ACP concept with no
  delivery channel on the TUI drivers.

As an interim, companion attach was disabled by removing =:BABYSITTER_WORKER:=
from all 17 default worker configs, and =babysitter-stall-detector.org= was
repointed from acp-stdio/sonnet to rmux/claude/=claude-haiku-4-5= (an
authenticated path) so it at least boots and is watchable. This task makes the
explicit-dispatch companion babysitter real, then restores default worker
=:BABYSITTER_WORKER:= declarations without reviving the removed task-state
watcher.
