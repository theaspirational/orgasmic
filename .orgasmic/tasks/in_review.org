** Description

Stage A (TASK-RQ270.1) removed the ability to PRODUCE architecture content but
left three live documents advertising that ability. Found by the TASK-RQ270.2.1
review and confirmed by the manager against the code.

** The three false claims

- =README.md:31= — "architector authors the architecture graph (source paths,
  typed edges, per-node test gates)", presented as a live pipeline stage.
- =ui/README.md:49= — "Pipeline stages post to =/grill=, =/architect=, and
  =/plan=".
- =shipped/entry/router.org:8= — "worker role: implementer, *architect*, planner,
  reviewer, or griller".

** What the code actually says now

- =crates/orgasmic-cli/src/manager.rs:28-39= accepts only implementer and
  reviewer dispatches.
- =crates/orgasmic-daemon/src/api.rs:3603-3610= treats =architect= as retired and
  exposes only grill and plan stage specs.
- =crates/orgasmic-daemon/tests/integration.rs:2261-2286= PINS =/api/architect=
  as a retired route.
- No architect or architector prompt spec exists under
  =shipped/prompt-studio/prompt-specs/=.

** Why the third one has teeth

=shipped/entry/router.org= is compiled into every worker prompt. So every
dispatched worker currently receives a role list naming a producer the product
cannot launch. The other two mislead humans; this one misleads every agent the
system starts.

** The judgement this task owes

Whether =architect= must survive in the router as a LEGACY RECOGNITION path — so
a reattached or historical run whose prompt names that role still routes — or
whether nothing consumes it and it simply goes.

Do not guess. Find the consumer or prove there is none, and say which. If it must
stay, it is described explicitly as legacy with the consuming compiler/reattach
path named, never presented as a live role.

** Not in scope

- Surviving =architector= strings in ledger and schema paths: DELIBERATE
  historical-read compatibility (the parent task's coupling map calls this out as
  the one place naive deletion breaks history).
- =architect= mentions in =verify/= artifacts: they describe past behaviour.
- UI type and view references to architecture: stage C owns those.

** Acceptance

- No current-facing document or shipped doctrine claims an architect or
  architector can be produced, dispatched, or POSTed to.
- If the router keeps the token, it says legacy and names what consumes it.
- A bare, repository-wide =architect=/=architector= search is run and its
  survivors are each classified as history, verification artifact, or legacy
  recognition — with the classification recorded, not just the count.

=== The router decision was made on evidence, which is why this was dispatched

=shipped/entry/router.org= as a LEGACY RECOGNITION path. The implementer hunted
the consumer instead of guessing, and concluded there is none.

*Manager verified the load-bearing half independently.* Every =ENTRY_ROUTER_REL=

the token either.

*And the test that could have pinned it does not.*

and it pins only that section. It does not pin the worker-role list.
