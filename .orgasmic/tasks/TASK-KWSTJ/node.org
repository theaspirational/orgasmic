Implementation boundary:
1. `GET /api/runs` must never await unbounded driver work. Terminal tombstones do no attach probe; genuine attach probes share one absolute deadline, have capped concurrency, and are aborted/joined on timeout.
2. Inventory construction must not parse multi-megabyte transcript bodies to answer lifecycle questions. Read a bounded lifecycle summary/catalog representation; legacy fallback may inspect a capped prefix/tail and must classify uncertainty conservatively. No per-failed-run whole-board rescan.
3. Exact recorded run ids use `/runs/:id` and `/runs/:id/release`; `dispatch-close` and explicit-id finalize never enumerate `/runs`. Legacy records without a run id retain a safe reachability fence.
4. Add stage metrics/logs for file count, bytes inspected, attach count/timeouts, classification counts, and total inventory latency without logging transcript content or local secrets.

Source-backed cause, measured on the same real corpus (release build, read-only, non-mutating):
- Whole-transcript enumeration read 2.239 GiB / 428,992 envelopes in 3.08 s per pass, and the recovery-origin index re-read the whole board again whenever a failed tombstone existed, on top of serial driver attach probes.
- Bounded lifecycle scan reads 26.67 MiB in 95.3 ms over the same 198 files (135 truncated, 0 parse errors): 86x fewer bytes, 32x faster, and inside the 250 ms warm target.

Fix, on top of the preserved TASK-JN5Q1 patch (its focused gates rerun green before any new edit):
- `orgasmic_core::scan_session_lifecycle` reads a prefix/tail byte window (128 KiB + 64 KiB by default) and retains only lifecycle-relevant envelopes, rejecting transcript lines from their raw bytes without parsing. Budget sized from the real corpus: the furthest a lifecycle-deciding line ever sat was 56 KiB from the start and 13 KiB from the end.
- Truncation is conservative: `final_envelope_retained` gates the terminal-release decision, so a still-writing run is never tombstoned from a stale retained lifecycle line, and a missing acquire still classifies `ambiguous`.
- Inventory (`classify_session_dir`), the recovery-origin index (through the same pinned-directory, device/inode-validated fd), and `resolve_run_session_path` all use the bounded scan. Boot auto-reattach deliberately still reads whole files; that is TASK-5P60H's slow-start scope.
- `InventoryStageMetrics` (file count, on-disk bytes, bytes inspected, truncated/unreadable counts, attach probes started/timed out, origin-index files and bytes, per-classification counts, duration) is emitted as a `tracing::debug!` and returned on `GET /api/runs` as `inventory`. Counts and byte totals only: no session paths, transcript text, prompts, or credentials.
