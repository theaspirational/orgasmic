** Description

A worker dispatched over the rmux driver gets a PATH whose FIRST entry is the
rmux shim directory, e.g.
=/var/folders/.../rmux-shim-2d4a7c8363aa8a2b/=. That directory contains a file
named =tmux= which is a SYMLINK TO =~/.local/bin/rmux=.

So inside any rmux dispatch, =tmux= on PATH is not tmux. =real_tmux_on_path()=
correctly refuses it, =tmux_spawn_usable_for_test()= returns false, and the ten
tmux-gated tests in the daemon lib DO NOT RUN. A real tmux exists at
=/opt/homebrew/bin/tmux= (3.6a) and is shadowed.

** How it surfaced, twice, independently

- TASK-FZB6T reviewer (rmux/codex): "The daemon tooling sentinel failed at exit
  101 because =tmux_spawn_usable_for_test= returned false and reported 10
  mux-gated tests not run. =tmux -V= itself reports 3.4, so this is classified
  environment-blocked at live-session creation, not a source regression."
- TASK-4CSMY.1 implementer (rmux/claude): measured the cause, stripped the shim
  directory from PATH and unset =TMUX=/=TMUX_PANE=, after which "the sentinel
  passes and all ten tmux-gated tests run". It ran every tmux-touching gate that
  way, and noted that without it "the tmux arms would have reported =ok= while
  skipping".

Neither worker was looking for this. Both found it because
=required_test_tooling_is_present= exists.

** Why this is P1 rather than a curiosity

The standing dispatch transport on this host is rmux — it is the only pane
transport with a liveness channel in the installed daemon — so this applies to
essentially every worker we run right now.

The failure mode is SILENT-BY-DEFAULT. The sentinel is the only thing standing
between us and a worker truthfully reporting "N/N focused tests green" while ten
tmux tests never executed. That is precisely the shape of evidence failure this
project has been chasing all week: a green that means less than it appears to.

It is also NOT the PATH theory TASK-R2HDN measured false. That one was about
=~/.local/bin= being ABSENT. This is the opposite: =~/.local/bin/rmux= PRESENT
under the name =tmux=, ahead of the real binary.

** Acceptance

- An rmux dispatch does not shadow a real =tmux= binary for the worker process.
  Decide the mechanism deliberately: the shim exists for a reason, so either
  scope it so it is only consulted by the rmux client path, name it something
  that is not =tmux=, or append rather than prepend it and let a real tmux win.
- Whatever the fix, a test proves that a worker environment produced by the rmux
  driver resolves =tmux= to a binary that =real_tmux_on_path()= accepts when one
  exists on the system PATH.
- =required_test_tooling_is_present= keeps failing loudly when tooling really is
  missing — do not weaken the sentinel to make this go away. It is the only
  reason we know.
- Record the trap in =gotchas.org= (blocked on TASK-WPC6G for a write verb; a
  hand edit is currently the only route).
