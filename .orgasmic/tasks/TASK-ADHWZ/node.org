** Description

Three distinct =orgasmic task create= calls were issued concurrently against
the same project and =backlog.org= on 2026-07-29. All three returned success:

- TASK-95SGV.1 → =tx-20260729-orgasmic-3946=
- TASK-JQ8AV.1 → =tx-20260729-orgasmic-3948=
- TASK-FZB6T.1 → =tx-20260729-orgasmic-3947=

Immediately afterwards, only TASK-JQ8AV.1 existed in =backlog.org= and the
daemon returned 404 for updates to the other two. The missing headings had to
be recreated sequentially with new idempotency keys. This is silent successful
write loss at the daemon's structured state authority boundary.

** Acceptance

- Reproduce with deterministic concurrent creates of distinct task ids that
  target the same state file.
- Every successful response has exactly one durable heading and matching tx
  after the requests finish and after reindex/restart; no last-writer-wins loss.
- Serialize or compare-and-swap the entire read/transform/write transaction at
  the central writer boundary, not at individual CLI callers.
- Cover concurrent create/create, create/update and update/update operations
  against the same Org file, including response loss and idempotent retry.
- A stale transform must retry from the new file version or fail explicitly;
  it must never report success for content absent from the committed file.
- Preserve the existing sanctioned git/human concurrent-writer rules and tx
  inode-swap protection.
- Add an injection proof and run focused writer/API tests, fmt, and clippy with
  warnings denied. Do not run any billed harness test.
