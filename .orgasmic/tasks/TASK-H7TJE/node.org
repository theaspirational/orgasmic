** Description
From the TASK-G64ZH.1.1 review, F-2 (MEDIUM, test) and F-3 (LOW), both on the
=last_open_err_kind= throttle that TASK-G64ZH.1.1 added for R-4.

** F-2 — the throttle test passes with the throttle DELETED
=logging.rs:1535-1571=. The test asserts =open_attempts == 2= and
=last_open_err_kind == Some(Other)=. IT NEVER CAPTURES STDERR, so it does not
assert that anything was or was not emitted. Delete the early return in
=note_open_failure= (=:462-469=) so it reports on EVERY attempt, and the test
stays green.

This is the SAME DEFECT CLASS as R-3 (the self-referential backoff test) in the
test added by the round that fixed R-3 — which is worth noticing on its own: the
chain has now produced three tests that assert the shape of a mechanism rather
than its effect.

** F-3 — alternating error kinds defeat the throttle
=logging.rs:462-469=. Emission is gated purely on
=last_open_err_kind != Some(kind)=, so any alternation emits on every attempt:
=EACCES= <-> =EMFILE= under fd pressure, or =NotFound= <-> =IsADirectory= while a
path is being recreated. At the 60s cap that is ~1440 lines/day into the
unrotated =daemon.err.log= — precisely the rate R-4 was filed to bound.

Non-blocking for R-4's own reason: still bounded per unit time by the retry rate,
and no worse than the pre-throttle behaviour R-4 itself called non-blocking.
Requires a genuinely flapping failure mode, which is rare.

** Direction
- F-3: add a =last_open_report_at: Instant= floor, so emission requires
  =kind != last || now >= last_report + REOPEN_BACKOFF_CAP=.
- F-2: capture stderr in the test and assert the EFFECT — that the second
  same-kind attempt emits nothing — rather than asserting the bookkeeping field.

** Acceptance
- Deleting the throttle's early return makes a test FAIL.
- An alternating-kind failure emits at a bounded rate, and a test pins it.
