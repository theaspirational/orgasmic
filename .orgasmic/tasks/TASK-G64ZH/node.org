** Description
Filed from the TASK-ZBYH3.1 review. The relocated double-write is fixed, but the
F3 retry that fixed the silent-freeze introduced a new unbounded-growth path, and
the discriminator is still a proxy with concrete failing cases both directions.

** F1 — HIGH — the reopen retry is unbounded, and worse than a bare per-line open
=logging.rs:327-331= calls =try_open_durable()= whenever
=durable == None && durable_path == Some=, with nothing damping it. The failure
path additionally parks =bytes_written= at =max_bytes + 1= (=:466=, =:456=,
=:409=) so =maybe_rotate= re-enters on the next line too. Per-line cost in the
stuck state, all under the sink mutex every tracing line contends:

| step | syscalls | stderr |
| =try_open_durable= in the write path (=:330=) | =create_dir_all= + =open= | 1 |
| =maybe_rotate= -> =highest= scan (=:419-425=) | up to =keep-1= = 31 =stat= | — |
| =maybe_rotate= -> =rename= fails ENOENT (=:446=) | =rename= | 1 |
| =maybe_rotate= -> =try_open_durable= again (=:455=/=:462=) | =create_dir_all= + =open= | 1 |

Plus *four* =record_drop()= per line, so =dropped_log_writes= inflates ~4x and
stops being comparable across incidents.

*Reproduced 1:1 from the project's own test stderr* — =failed_reopen_after_roll_counts_drops_and_retries=
(2 writes -> 2 open attempts) and =rotation_failure_does_not_propagate_and_counts_a_drop=
(2 writes -> 2 rename attempts). Neither test enables rotation AND a missing
handle together, which is why neither surfaces the compound 3-writes-per-line cost.

*Why this matters and is not a nit:* on persistent =EMFILE=, or
=daemon.out.log= replaced by a directory, or =EACCES= on the logs dir, the daemon
writes ~3 error lines to =daemon.err.log= for every tracing line. =daemon.err.log=
is rotated by nothing, pruned by nothing, and checked by no =doctor= probe. *That
is the exact unbounded-unrotated-growth shape TASK-ZBYH3 and TASK-ZBYH3.1 exist to
remove, at ~3x the original rate.* The pre-fix permanent silent freeze was also
wrong; this trades one bad failure mode for another.

Fix: add =next_reopen_attempt: Instant= (or an attempt count with exponential
backoff, 1s -> 60s cap) to =SinkState=; emit the stderr note once per backoff
window, not per line; and *skip =maybe_rotate= entirely while
=state.durable.is_none()=* so the reopen path owns the retry instead of both
paths retrying independently.

** F2 — MEDIUM — =is_terminal()= is a proxy; answer it by construction instead
It answers "is fd 1 a tty", not "will this write land somewhere nothing rotates".
It is correct for every shipped launch path — launchd =StandardOutPath=
(=daemon_service.rs:372=, rendered =:848=), systemd =StandardOutput=append:=
(=:935=), the Windows wrapper =serve >> "..."= (=:972=, where it WORKS and the old
inode check was =cfg(not(unix)) -> false=), and the detached fallback
(=daemon_lifecycle.rs:435-461=) — but it fails both directions:

- *False positive, restores the defect class:* any pty-backed capture —
  =script -q typescript orgasmic serve=, =unbuffer=, or =docker run -t= with the
  default unrotated =json-file= driver. fd 1 is a tty, the mirror lives, every
  line double-written into something nothing rotates. Not reachable in this repo
  today (=scripts/publish-runtime.sh:301= runs docker without =-t= and never runs
  =serve=), but it is the honest answer to "is this a proxy".
- *False negative, a live silent behaviour change from main:*
  =orgasmic serve | tee=, =serve > file=, or CI capturing serve through a pipe.
  On main the pipe's inode != the durable inode so the mirror survived and the
  operator saw tracing; now it is suppressed with no message saying where the
  output went. Both in-repo consumers are safe (=scripts/soak.sh:451-473= and
  =crates/orgasmic-cli/tests/daemon_lifecycle.rs:29-47=) because the startup
  banner uses =writeln!(io::stdout(), ...)= at =main.rs:2245-2256= and bypasses
  the tracing sink — so piping =serve= now yields the banner and nothing else.
  Operator-ergonomics regression, not a broken gate.

*The exact answer exists at the call site, because orgasmic writes its own
service definitions.* Pass it explicitly — =serve --no-log-mirror= (or
=ORGASMIC_LOG_MIRROR=off=) in the launchd =ProgramArguments=, the systemd
=ExecStart=, and the Windows wrapper — and keep =is_terminal()= only as the
fallback heuristic for supervisors orgasmic did not write. That converts the three
shipped paths from "answered by proxy" to "answered by construction".

** F3 — MEDIUM — the tty branch is untested
All four new tests drive the NON-tty side (=logging.rs:576= and =:697= both dup2
fd 1 to a file). Inverting the condition at =logging.rs:184=, or a refactor that
gated purely on =durable_path.is_some()=, would silence interactive
=orgasmic serve= and keep all 9 tests green. The "interactive serve still prints"
acceptance bullet has no automated evidence. Same shape as the parent ruling's F7
— one half of the production discriminator is still unpinned.

Fix: make the predicate injectable (a =fn() -> bool= in =SinkState=/=resolve_mirror=,
or a =MirrorGate= enum) and assert both branches; or =openpty(3)= and dup the slave
onto fd 1 inside the existing =STDOUT_REDIRECT_LOCK= (=logging.rs:569=).

** Acceptance
- A persistent open failure costs a BOUNDED number of syscalls and stderr writes
  per unit time, not per log line. Assert the bound.
- =dropped_log_writes= increments once per dropped line, not ~4x.
- =maybe_rotate= does not run while the durable handle is missing.
- The three service definitions orgasmic writes suppress the mirror BY
  CONSTRUCTION, with =is_terminal()= retained only as the fallback.
- Both branches of the mirror gate are asserted, including the tty side.

*Two things carried to the reviewer rather than fixed here.* (1) THE
RENAME-FAILURE BRANCH IS STILL PER-LINE when reopen succeeds: a persistent
failure renaming =daemon.out.log -> .1= leaves =bytes_written= back at the file's
length, still above the threshold, so =maybe_rotate= re-enters on every
subsequent line — up to 31 =exists()= calls, a failing rename, a =record_drop()=
and a stderr write each time. The implementer declared it a residual on the
grounds that F1's acceptance names a persistent OPEN failure; the existing tests
exercise the scenario but assert only that it does not propagate, never that its
cost is bounded. (2) PUTTING =--no-log-mirror= IN THE GENERATED PLIST MAKES A
RUNTIME ROLLBACK A STARTUP FAILURE rather than a degradation: an older binary
rejects the unknown flag and does not start at all. The env form would be ignored
harmlessly by an old binary, and both surfaces are already implemented.
