THE DIAGNOSIS I GOT WRONG, AND HOW
I reported that workers inherit the daemon's $TMUX and so reach the rmux server.
False. The pid I measured was a claude worker — `pgrep -f "orgasmic.*daemon"`
matched its *prompt text*. The real daemon carries no TMUX. rmux sets TMUX on
panes it creates and prepends a shim where tmux -> rmux, so a worker's tmux calls
reach a live server and exit 0. Then the decisive test: a full daemon --lib run
in the manager environment — no shim, no TMUX — reproduced three of the worker's
six failures (528 passed / 5 failed / 451s). Not a worker/manager divergence at
all. Lesson: never identify a process by a pgrep pattern that can match a prompt.
The RRT4T/R2HDN open question is open again, with its leading candidate removed.

MEASURED, and worth not re-deriving
- macOS charges 150-270 ms of Gatekeeper evaluation on the FIRST exec of each
  newly created executable, through one serialized daemon. Warm exec 4 ms. A hard
  link to a warmed file is also 4 ms (the cache key is the inode); a byte-
  identical copy pays 162 ms. And `/bin/sh script` on a fresh file is 5 ms
  against 270 ms for `./script` — the simplest sidestep, and the one to use next.
- The remaining suite pressure is in the rmux test path, not in the converted
  fixtures: syspolicyd burns +281 s of CPU during a 106 s run with rmux present
  and +32 s with it absent. What it is exec-ing has NOT been identified. The rmux
  binary itself is cheap (9.2 ms, 0 ms syspolicyd).

CLI DEFECTS FOUND WHILE WORKING, now understood correctly
`--property KEY=VALUE` writes any key verbatim and the schema reads only a fixed
UPPERCASE set (schema.rs:276-286), matched case-SENSITIVELY. So `write_scope`,
`test_cmd` and `priority` in lowercase are stored where nothing reads them, and
the response echoes them back as changed. The earlier note in this session that
uppercase WRITE_SCOPE was "silently dropped" was wrong — uppercase is the form
that works. `task create` has no --priority flag at all, which is how all seven
tasks filed today came out priority None. Tracked on TASK-HXSW0.
