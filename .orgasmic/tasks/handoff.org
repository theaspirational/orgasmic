THE THREE THINGS TO KNOW BEFORE YOU DO ANYTHING

1. A DISPATCH CAN KILL EVERY OTHER DISPATCH. A worker that runs any daemon
lifecycle verb — =orgasmic daemon start|stop|restart=, =orgasmic restart=,
=orgasmic serve= — rewrites THE ONE REAL USER LAUNCHAGENT regardless of
=ORGASMIC_HOME=, because that path is per-user and not per-home. The daemon
restarts and every live run dies at once. That cost FIVE WORKERS in two events
ten minutes apart tonight. The cause was isolated by elimination (TASK-48SFW):
a ten-minute watch cleared the manager''s own =orgasmic status= polling, and a
lone read-only worker carrying an explicit prohibition then completed untouched,
which cleared the dispatch path. PUT THE PROHIBITION IN EVERY BRIEF until the CLI
refuses it. It has held on every dispatch since.

2. A RED SUITE IS NOT EVIDENCE ABOUT YOUR DIFF UNTIL 8 SECONDS HAVE DISPROVED THE
MACHINE. Reproduced FOUR times tonight on four different trees: the full daemon
lib returns 6-14 failures, and every one passes when re-run alone against the
same already-built binary. The class is always live-mux and process-probe tests.
The discriminator is =syspolicyd=, which has hard-rebooted this Mac twice.
: env -u ORGASMIC_RUN_ID -u ORGASMIC_HOME \
:   target/debug/deps/orgasmic_daemon-<hash> --exact <test> --test-threads=1
The mitigation is NOT free, and the bill came due tonight: a TASK-FZB6T.2
regression reached main and survived a full review round because the author, the
reviewer and the manager all ran FOCUSED filters. Run the full crate suite once
when the machine is calm, then isolate whatever it reddens.

3. A PASSING =orgasmic verify= PROVES THE RED HAPPENS, NOT THAT IT IS THE RIGHT
RED. A re-cut injection passed the manager''s replay while never reaching the
assertions it claimed to pin, because an earlier assertion panicked first. Treat
a PASS as necessary and never sufficient for a RE-CUT artifact; read the patch.
