Verified 2026-07-26 while ruling on reviewer finding 5 on TASK-8W30B.

`.github/workflows/` contains six files — nightly-android, nightly-macos,
nightly-runtime, release-android, release-macos, runtime-bundles. `grep -rn
"cargo test\|cargo nextest" .github/workflows/` returns nothing. No workflow runs
the Rust test suite, clippy or fmt.

Every "gates green" claim in every task Evidence section in this repository is
therefore a local run by whoever happened to run it, on their machine, in
whatever state that machine was in. Nothing re-checks it on merge, and nothing
would catch a regression landed by a contributor who skipped the local run.

This session is a direct illustration. The full suite degrades as it runs
(TASK-8W30B: leaked rmux sessions), a driver test now bills real money and fails
intermittently (TASK-099T6), three daemon tests are known-red, and all of that
was discovered by hand, twice, because two different agents ran the suite in two
different local states and got two different answers.

The reviewer raised the narrow version — the new rmux regression test skips
rather than fails when rmux is absent, so adding `cargo test` to CI naively would
make it green forever without ever creating a session. That is real, but it is
downstream of the larger gap.

Work:
1. Add a CI lane that runs `cargo test --workspace`, `cargo clippy --workspace
   --all-targets -- -D warnings` and `cargo fmt --all --check`.
2. Decide what to do about the three known-red daemon tests before turning the
   lane required — a lane that is red on arrival teaches everyone to ignore it.
3. Decide which live-harness tests may run in CI at all. Some spawn real claude
   and cost money per run (see the gotcha "Asking a harness to prove it can work
   costs real money"); those need an opt-in gate, not a default lane.
4. For tests that skip when their runtime is unavailable, add a required-environment
   mode where a skip is a failure, and provision rmux in whatever lane is
   designated as the gate.

Acceptance:
- a pull request that breaks the workspace suite fails a check
- the suite CI runs is honest about what it did not run, rather than skipping
  silently
- no default CI lane bills the operator for a provider turn
