Raised by the TASK-RWCRN reviewer as an open question. tmux.rs:1789-1824 has the same pane-is-not-an-event-source shape that TASK-RWCRN fixed for rmux, and only polls for session exit, so a tmux-mode TUI run emits no driver events after ready and is released by the 600s stall detector exactly as rmux was. The reviewer AGREED with leaving tmux out of the rmux-scoped RWCRN fix — tmux has no existing output subscription to reuse, so adding capture polling there would widen both risk and retention scope, and the standing worker matrix is rmux — but flagged that tmux/claude, tmux/codex, tmux/cursor-agent and tmux/hermes remain in orgasmic_drivers::SUPPORTED and are documented as usable. Either give tmux an equivalent liveness signal, or stop advertising tmux pairs as safe for runs longer than 600s. Depends on the shape TASK-RWCRN.1 settles: if pane observation moves from lines to raw bytes, tmux should adopt the same contract rather than inventing a second one.
