** 1. HIGH — `auto` still guesses from environment, and the test protects the bug

`crates/orgasmic-drivers/src/adapters/claude.rs:584`.

`resolve_credentials` selects `BareApiKey` whenever a configured `api_key_env` or
an inherited `ANTHROPIC_API_KEY` is present (`claude.rs:586-599`). It never calls
`claude auth status` to choose the tier and never reads `authMethod`; `auth status`
runs only *after* the resolver has already picked `NativeLogin`
(`claude.rs:301-315`).

So an operator with `authMethod: claude.ai` **plus a stale non-empty key** is
admitted, spawned with `--bare`, prevented from using the working keychain
credential, and fails after lease/session/dispatch ownership has been committed —
the exact failure this task was filed to remove. The bare preflight returns
`Unsupported` for every non-empty key (`claude.rs:633-644`, pinned by
`1352-1363`), so nothing catches it.

Worse, the existing test uses an obviously fake non-empty key and asserts it
selects `--bare` (`claude.rs:1220-1241`). **The suite currently protects the
failure mode.** Changing that test is part of the fix, not a regression.

This violates "detect, do not guess" and the acceptance criterion that a mode
known to be unusable is rejected before ownership is taken.

Also missing: the second measured live bare channel. There is no
`apiKeyHelper`/settings input or detector anywhere in `ClaudeAcpConfig`
(`claude.rs:127-147`), so a helper-backed operator cannot select the light tier
at all.

** 2. HIGH — the selected mode is a tracing field, not a contract

Both `credential_mode = …` occurrences are `tracing::debug!` fields
(`claude.rs:317-320`, `417-420`).

- No override anywhere: `ClaudeAcpConfig` has none (`claude.rs:127-147`), daemon
  `DriverOverrides` exposes only provider/model/effort
  (`crates/orgasmic-daemon/src/api.rs:3376-3381`), and `DispatchRequest` has no
  credential-mode input (`api.rs:4101-4133`). The manager cannot force
  `NativeLogin` to bypass a stale ambient key, which is the operator escape hatch
  finding 1 needs.
- No persistence: `Lifecycle::RunMeta` has no credential-mode member
  (`crates/orgasmic-core/src/session.rs:320-350`) and `write_run_meta` does not
  write one (`crates/orgasmic-daemon/src/supervisor.rs:1475-1502`).
  `NativeRuntime.launch_argv` can indirectly reveal `--bare` after composition,
  but that is a different lifecycle event and does not satisfy the stated
  contract.

Persist the final **mode string, never credential material**, in a
backward-compatible `RunMeta`, and prove it end to end by reading it back from
the session JSONL.

** 3. MEDIUM — NativeLogin rebuilds only MCP isolation, and says otherwise

`claude.rs:359-365` adds only `--strict-mcp-config`. The measured MCP result is
recorded and the SessionStart-hook gap is candidly documented
(`claude.rs:59-71`) — that candour is good and should be kept.

But the enum documentation says `--bare` also skips LSP, plugin sync,
auto-memory, background prefetches and `CLAUDE.md` discovery
(`claude.rs:39-40`), and nothing records what happens to those under
`NativeLogin`. A subscription worker can therefore run operator hooks and may
auto-load project and user Claude instructions plus background services, with no
record of which gaps were accepted.

Re-measure the exact production argv for MCP, hooks, `CLAUDE.md`, memory,
plugins, LSP and background activity. Add narrow flags where they exist; where
they do not, say so explicitly. Do not infer coverage from
`--strict-mcp-config`.
