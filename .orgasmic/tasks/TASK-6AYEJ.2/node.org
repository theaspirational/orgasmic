** Finding 2 - LOW correctness
manager.rs:3701-3720 and daemon/src/api.rs:7543-7909. The fail-closed RUN_ID rule leaves a legitimate fresh recovery run permanently [unreported]. Initial CLI dispatches write a run.created association carrying RUN_ID and DISPATCH_TX (api.rs:5109-5200), and attach_run_created_to_dispatch stores that original run id (manager.rs:3655-3697). But resume_native_fork and start_recovery_run acquire a REPLACEMENT run and return a new id while preserving the task and terminal contract - and never call the sole record_dispatch_created site, so no replacement association is emitted. dispatch finalize then reports the live replacement id (manager.rs:1218-1221), which cannot equal the open generation's original id, and mark_matching_dispatch_reported now returns without task fallback. Reattach-in-place is unaffected because it preserves the id.

So the answer to the brief's adversarial probe is YES: fresh recovery/resume is a valid mismatch shape, and its manager status never becomes [reported]. The wrong-marking bug was traded for a never-marking bug in this one shape.

FIX DIRECTION: persist a replacement-run-to-manager.dispatch_started generation association for fresh recovery/resume, and match *.reported by that generation rather than by task overlap. Add an end-to-end dispatched-run -> interruption -> recovery -> finalize status test.

** Finding 4 - LOW test
tests/shipped_conventions.rs:49-71. The forced-cleanup guard is both syntax-brittle and blind to realistic dangerous variants. It matches only the adjacent substring 'worktree remove --force', while the ORIGINAL dangerous instruction read 'git worktree remove <path> --force' - which would evade the needle entirely, alone or paired with a generalized 'git branch -D <branch>'. Conversely it requires exactly one occurrence and the exact phrase 'destroys exactly that', so innocent rewording fails it. The convention at manager-dispatch.org:205-227 is currently safe; the guard is the problem. A brittle guard gets deleted the first time it fails spuriously, and then protects nothing.

FIX DIRECTION: replace exact prose matching with a semantic guard that rejects 'git worktree remove' combined with '--force' regardless of intervening arguments, and rejects 'git branch -D' regardless of branch spelling. Permit zero warning literals, or anchor any allowed warning to an explicit structured marker rather than a sentence.
