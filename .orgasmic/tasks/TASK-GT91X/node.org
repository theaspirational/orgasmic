=== CORRECTION (manager, after the fix landed)

Two claims in the text above were wrong, and the implementer disproved both
against the installed codex-cli 0.144.5.

1. "The single same-day rollout carrying originator: orgasmic has source:
   vscode ... an editor session opened in a worktree, not a dispatch." **False.**
   Codex classifies JSON-RPC app-server clients as source: vscode. That rollout
   was orgasmic's own acp-ws driver — the two most recent such rollouts are its
   integration tests. All 306 historical 'orgasmic' rollouts are this route.

2. "The mechanism that used to produce orgasmic has not been identified",
   implying it stopped. **Nothing stopped.** Codex sets the originator by two
   routes: CODEX_INTERNAL_ORIGINATOR_OVERRIDE (env, beats the frontend default
   for any frontend) and app-server initialize.clientInfo.name, which
   adapters/codex.rs has always sent as 'orgasmic'. Route 2 covered acp-ws and
   acp-stdio and never covered the TUI. Confirmed by 'git log --all -S ORIGINATOR'
   returning nothing: orgasmic never used route 1 until this task.

So the gate was never satisfiable on the mux path rather than having regressed.
The filed consequence was accurate; the history was not. Recorded because the
wrong history would have sent a later reader looking for a regression that never
happened.

** Description
Every codex reviewer's transcript is unreachable through the product surface.
`orgasmic run native-transcript <run_id>` returns `not_found` for a rollout that
exists on disk, whose `cwd` matches the worktree exactly, and which started one
second after the run.

Hit live on 2026-07-28 while retrieving the TASK-Z8WEJ reviewer's verdict. That
review returned a substantial BLOCK with two HIGH findings, and the only way the
manager could read it was to hand-parse `~/.codex/sessions/**` in Python. The
product said the transcript did not exist.

=== The gate

`crates/orgasmic-drivers/src/transcript_finder.rs:687`, in
`collect_codex_cwd_matches`:

```rust
if meta.originator.as_deref() != Some("orgasmic") {
    continue;
}
```

**Nothing in the orgasmic codebase ever sets `originator`.** Repo-wide, the
string "orgasmic" as an originator value appears only in `transcript_finder.rs`
itself and in that file's own test fixtures — which is why the unit tests pass:
they construct the very value production never produces.

=== Why this is worse than one missing transcript

Codex emits no `NativeRuntime` lifecycle event (TASK-F9VEZ), so
`lookup.session_id` is `None` and the high-confidence
`find_codex_rollouts_by_session_id` path is unavailable. The cwd+originator scan
is the **only** remaining route, and this gate closes it. Codex runs therefore
have no reachable transcript by any path.

This is dec_WDR5K's sequencing constraint failing in substance: TUI screen
capture was removed on the premise that harness-native JSONL finders would
locate transcripts. For codex the finder finds nothing, so those runs have no
transcript at all — the same shape TASK-VB9DQ established for acp-stdio claude,
now confirmed for codex through a different mechanism.

=== Ask

1. Establish what actually sets `originator` and why it stopped for
   rmux-launched codex. Codex reads an originator override from its
   environment; determine the real name and whether orgasmic ever set it, or
   whether the historical `"orgasmic"` values came from a different launch path
   (acp-stdio) that reviewers no longer use. Report what you found — a wrong
   guess here produces a fix that passes tests and changes nothing in
   production.
2. Set it deliberately on every codex launch path, or stop requiring it. If
   orgasmic can stamp the originator, do that and keep the gate as a strong
   correlator. If it cannot, the gate must go — an unsettable discriminator is
   not a safety property, it is an outage. Do not simply widen the match to any
   originator without saying what now prevents mis-attribution to an operator's
   own codex session in the same directory.
3. The unit tests must stop constructing the value production cannot produce.
   Whatever fixture proves this path must be reachable from a real launch.

=== Acceptance

- Prove it by injection: break whatever now supplies the correlator, watch the
