** Description

=.orgasmic/entry.org= states the write rule plainly: when =orgasmic status=
succeeds, =.orgasmic/= state is written through =orgasmic ...= CLI commands and
never by hand. The active goal repeats it ("never hand-edit .orgasmic state").

=gotchas.org= cannot obey that rule, because it is not on the surface at all:

- =orgasmic node body set|append|unset= takes =--kind= from
  {decision, architecture, glossary, project, task, goal, handoff}. There is no
  gotcha kind, and the file has no node =:ID:= — its headings are bare =**=
  entries under a single =* Gotchas= parent.
- Nothing in =crates/orgasmic-cli/src/= addresses it. The only core reference is
  the scaffold template in =projects.rs:525=.

So the only way to add a gotcha is to edit the file directly, which is exactly
what the previous manager session did in =d1a41c1= (66 added lines, no
=graph.gotchas.edited= tx — the tx entries in that commit are unrelated daemon
writes that happened to be uncommitted).

** Why this matters more than the usual missing-verb gap

=AGENTS.md= routes every agent through =orgasmic entry=, and the entry router
names =gotchas.org= as required reading before source edits. The
manager-dispatch and manager-implementer paths both say to read it first. It is
one of the highest-traffic documents in the project, and it is the one document
no agent can write through the sanctioned path.

The practical consequences are already visible:
- gotcha edits carry no tx, so they are invisible in the ledger and cannot be
  attributed or reverted through the normal surface;
- they bypass the OCC/base-version check, so two concurrent writers silently
  clobber;
- an agent that obeys the write rule literally is forced to DROP the knowledge,
  which is the worst outcome of the three.
