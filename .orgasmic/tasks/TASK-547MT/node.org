** Description
Source: vscode-orsl manager letter 2026-08-22 (operator-forwarded, 40 dispatches over 4 days, orgasmic 0.0.18). Item 9. `dispatch-wait` returned 503 `claim_store_unreadable`; cause: `~/.orgasmic/state/recovery-claims/` missing. mkdir -p + chmod made it intermittent. Every dead wait had to be re-checked with dispatch-status.
Code: crates/orgasmic-daemon/src/recovery_claim.rs read path.
** Expected
- The daemon creates every directory it reads (missing claim dir == empty store, created on first use).
- A wait that loses its connection prints `wait lost — worker state unknown, re-run dispatch-status` and exits non-zero distinct from run-ended.
** Acceptance
- Test: claim store read on a fresh HOME returns empty, not 503; CLI message on connection loss.
** Resolution
Root cause of the 503: the claim store opens `~/.orgasmic/state` and `recovery-claims` via openat; with the daemon at the 256-fd ceiling that open fails EMFILE, which classifies as Unobserved → claim_store_unreadable (an absent recovery-claims dir is already read as an empty store, and Home::ensure creates state/ at boot). Fixed by the fd-leak fix 8bd8287. (b) shipped in 5033cce: a failed dispatch-wait request prints "dispatch-wait lost … worker state unknown, not ended; re-run dispatch-status".
