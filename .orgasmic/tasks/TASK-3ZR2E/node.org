** Description

=adapter_fixtures_cover_public_harness_event_shapes= fails in the parallel
=driver_modes= test binary and passes the isolation rerun. Found by the
TASK-M47E5.1 reviewer, which also identified the mechanism rather than reporting
a shrug.

*Mechanism*: the test mutates the PROCESS-GLOBAL env var
=ORGASMIC_DRIVER_SIMULATE= (=crates/orgasmic-drivers/tests/driver_modes.rs:1646=)
while =installed_harnesses_answer_their_own_readiness_probe= REMOVES it in the
same binary (=:2152=). Cargo runs tests in one process across threads, so the two
race. Both predate TASK-M47E5.1 and neither reviewed file participates.

** This is a test-isolation defect, not a flake to wave through

The registry exists for failures the project is willing to see and not act on.
This one has a known, cheap, local cause: two tests sharing mutable process
state. Registering it would buy a quieter suite at the cost of the signal, and
the fix is smaller than the excuse.

*Deliberately NOT registered in =verify/flake-registry.toml=*, and for the same
reason TASK-37WN7 was initially left out: NO PANIC SIGNATURE WAS CAPTURED. The
reviewer reported the test name and the runner's verdict, not the assertion text.
A signature-less entry makes every future failure of this name read as this known
race, which is exactly the "trains everyone to discount failures" outcome the
registry exists to prevent.

Note the registry behaved correctly here: the unregistered failure was reported
REAL, which is what surfaced it at all.

** Acceptance

- The two tests no longer share mutable process-global state — serialize them, or
  scope the variable to the spawned child rather than the test process.
- Prefer the child-scoped fix if the production code allows it: a test-only
  serialization lock is a constraint future tests must remember, which is the
  same class of maintenance dependency as an enumeration list.
- =scripts/run-tests.sh -p orgasmic-drivers= is green in the PARALLEL run, not
  only in isolation.
- If it is registered instead, capture the panic first and pin the signature.
