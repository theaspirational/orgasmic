** Description

Round-4 reviewer finding 4 (P2, =BLOCKS_SHIP: no=), split out on the reviewers
recommendation so TASK-FZB6T.5 stays scoped to the three blockers.

For a format-1 record, rollback hashes a replacement rebuilt by the CURRENT
=build_compacted= (=run_history.rs:1756-1766=). That reconstruction is only
usually identical to what the format-1 implementation actually wrote: at
=9bee827= the writer classified by the first textual ="type"= match, while
current code uses a validating structural scanner. The current regressions
themselves document shapes whose classification changed — a nested =text_chunk=
before an outer =tool_result= (=run_catalog.rs:4375-4392=) — and historical
raw-control-byte records followed the old classifier while the current scanner
refuses them.

The compatibility test at =run_history.rs:2936-3018= writes an old manifest
SHAPE, but line 2943 creates the compacted live bytes by calling the CURRENT
=apply=. So it proves field-shape compatibility, not that a replacement actually
emitted by the format-1 implementation is recognised.

** Why this is P2 rather than blocking

It is safe-failing. On a real classifier-drift case rollback REFUSES rather than
overwriting, so the archive is not destroyed and no evidence is lost. What is
lost is the promise: legacy rollback is unavailable for exactly the records whose
classification drifted.

** Work

- Decide whether legacy rollback should be supported at all, or whether refusing
  with a clear reason is the honest contract. Record the decision.
- If supported: authorize the live-file decision against bytes the format-1
  implementation actually emitted, rather than against a reconstruction by the
  current compactor.
- If not: make the refusal explicit and named, so an operator sees "this archive
  predates the current classifier" rather than a generic mismatch.
- Either way the compatibility test must build its old compacted bytes with the
  OLD algorithm, not by calling the current =apply=.
