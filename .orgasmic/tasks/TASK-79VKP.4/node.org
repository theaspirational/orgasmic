** Description
During TASK-K9WWM every dispatch-status poll repeated a reclaimable 17 GiB worktree report; the late correction added another 1.7 GiB line. The output is produced automatically even when the operator is polling one live task, so stable cleanup inventory obscures the state change being monitored. TASK-3R3EZ owns repeated missing-path warnings, TASK-SJA9W owns false close advice, and TASK-PAZQ2 owns missing progress clocks. No task owns the default output contract.

Make the default status view task-focused and change-driven. Stable reclaimable inventory should be summarized once, emitted only when it changes, or moved behind an explicit inventory or verbose flag. Machine-readable output must retain the complete information and destructive prune must remain a separate explicit command.

** Acceptance
- Repeated polling of one unchanged live dispatch emits no repeated per-worktree inventory block.
- A newly reclaimable, newly held, or size-changed worktree is surfaced once with a stable identifier.
- An explicit flag returns the full current inventory and exact byte totals.
- Existing orphan, run-liveness, and prune-safety diagnostics remain visible and tested.
