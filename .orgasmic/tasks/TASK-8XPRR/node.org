** Description
TASK-4CSMY gave the tmux driver a pane-liveness channel backed by a private FIFO
in a `tempfile::TempDir` (`pane_output_fifo`, `orgasmic-pane-*` prefix). The
directory is dropped when the watch task ends or is aborted — release, Drop, and
task abort all covered.

The reviewer of that change measured 112 INACTIVE `orgasmic-pane-*` directories
already present in the temp root, in five clusters spanning 15:33-16:28, with no
open `lsof` handles and no surviving `cat` processes. Its own controlled
acquire/release smoke and its explicit Drop-path test each added ZERO entries.

So the production paths clean up correctly and this is NOT a per-run daemon leak.
The residue is from test processes that die without running Drop — the timing
matches the three full-suite runs done during the TASK-4CSMY integration. A
`TempDir` cannot clean up after SIGKILL, and the suite kills process groups.

** Why it is worth a task anyway
It accumulates without bound in `$TMPDIR`, and a directory named after our
driver is the first thing someone will blame when the temp root fills. Two
things are worth deciding rather than leaving implicit: whether the driver
should sweep stale `orgasmic-pane-*` dirs on startup (cheap, bounded, and it
makes the leak self-healing), and whether the tests that spawn panes should reap
their own residue.

** Work
1. Reproduce: run the daemon suite and count `orgasmic-pane-*` before/after.
   Identify which test path leaves them (Drop skipped vs process killed).
2. Decide sweep-on-startup vs test-side cleanup, and say why in the commit.
3. If sweeping: only remove directories with no open handles and an mtime older
   than a conservative floor — never one that could belong to a live run.

** Acceptance
- The mechanism is named with evidence, not inferred.
- A full suite run leaves no unbounded growth in the temp root.
- Nothing can remove a FIFO directory belonging to a live pane.
