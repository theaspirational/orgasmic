** 1. HIGH — four live-rmux tests still accept an inert session (in this diff)

`crates/orgasmic-drivers/src/modes/rmux.rs:3171-3175,3244-3249,3357-3360,3402-3404`.

`f894a7a` converted each test's missing-binary guard to `skip_test_if_missing`
and introduced `assert_not_degraded`, but left the pre-existing
inert-success branches in place. `run_live_session` converts **every** SDK or
daemon startup error into an inert `Ready` (`rmux.rs:765-810`), while the binary
sentinel (`modes/tmux.rs:2532-2542`) only proves a compatible executable exists.

So a compatible `rmux` **plus** an SDK/daemon connection failure makes the
sentinel pass while `live_rmux_session_lifecycle_when_available`,
`live_rmux_streams_output_and_completes_on_exit`,
`live_rmux_session_exports_orgasmic_run_id` and
`live_rmux_process_exit_emits_run_complete_without_text_chunks` all report success
without exercising their named behaviour. That is the false-green class this task
exists to remove, surviving in the very tests it was filed about.

Required: route all four retained inert branches through `assert_not_degraded`.
A live test must fail when acquisition degrades to inert.

** 3. HIGH — the shared environment lock does not cover every availability probe
   (pre-existing)

`crates/orgasmic-drivers/src/adapters/claude.rs:1863-1874,1926-1935`.

`gate_simulates_for_empty_endpoint_stdio_when_claude_missing` holds the shared
lock and sets process-global `PATH=""`.
`real_claude_stream_json_bridge_reports_auth_error` evaluates
`claude_available()` **before** acquiring that same lock. Interleaved, the latter

Required: acquire `test_environment_lock` before **every** availability probe
that can race with process-environment mutation, and hold it through the guarded
test.
