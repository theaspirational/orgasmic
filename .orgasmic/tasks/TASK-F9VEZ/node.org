Filed by TASK-H0TYV (VB9DQ fix round) from the recorded cross-harness matrix. See that matrix for the measurements this rests on.

`CodexAdapter` never overrides `HarnessEventAdapter::native_runtime`, so it takes the trait default `None` (`crates/orgasmic-drivers/src/trait.rs:248`). Verified 2026-07-28: `native_runtime` is implemented in exactly two places in the tree — `adapters/claude.rs:168` and the delegating `modes/acp_stdio.rs:111`.

Codex mints its own identity server-side: `thread.id` is read out of the `thread/start` response in `on_ws_thread_started` (`crates/orgasmic-drivers/src/adapters/codex.rs:198-206`) and surfaced only inside `Ready.capabilities` as `thread_id` (`:225`). `thread_start_params` (`:864-885`) has no id field, so orgasmic cannot pre-mint one the way `--session-id` lets it for claude.

Two consequences, both live:
1. `resolve_recovery_actions` cannot offer `resume_native_fork` for a codex run — there is no validated NativeRuntime session id to resume.
2. dec_Y5MPK item 6 (worker/operator attribution) is not computable for codex. 1457 rollout JSONL files sit under `~/.codex/sessions` on the operator machine (measured 2026-07-28) and none of them can be attributed to an orgasmic dispatch, because attribution is defined as "its session id appears in a NativeRuntime record".

Work:
1. Emit `NativeRuntimeMeta` from the handshake response rather than from launch: provider `codex`, session id = `thread.id`, `session_path` = the rollout file the transcript finder already knows how to locate, and a `resume_argv`/resume params that codex actually accepts. Establish what codex resume looks like before designing the shape — `thread_id` currently flows only into turn params (`:326-410`), and there is no resume call in the adapter today.
2. Confirm the mode carries a NativeRuntime that arrives *after* compose. `modes/acp_stdio.rs` reads `adapter.native_runtime()` immediately after composing the request, which is too early for a value the handshake produces. This is the real blocker and it is shared with TASK-B6D8W (cursor-agent) and TASK-2B215 (hermes).

See also TASK-ZY259: `thread_start_params` also sends `persistExtendedHistory: false`, which is a separate dec_Y5MPK item 4 question and should be settled first since it touches the same call.
