** Question
What does a shipped node-type descriptor declare (required properties, allowed states, regenerate prompt template, UI labeling), where does it live in shipped/, and how does the daemon treat a collection directory with no descriptor?
** Resolution
Grilled with owner 2026-08-22; four decisions. Facts: no descriptors exist today — kinds are a Rust enum (NodeKind), id prefixes a second enum, task states+transitions already a shipped org data file (shipped/schema/state-machine.org), prompt-studio context-packs are org headings with a property drawer; three precedents for shipped-org-with-drawer. Gotchas and conventions have no ids (one prose heading; three prose files).
1. Format and home: one org file per type under shipped/schema/node-types/<collection>.org — a heading with a property drawer plus prose, the state-machine.org / context-pack idiom. Not JSON/YAML.
2. Declares (v1 minimum): :COLLECTION: (dir), :ID_PREFIX:, :LABEL:/:LABEL_PLURAL:, :REQUIRED_PROPERTIES:, :STATES: plus transitions (tasks only today), :REGENERATE_PROMPT: (a prompt-studio spec name), optional reserved file names. No validation DSL beyond required-present and state-in-set.
3. No project-local descriptors in v1 (shipped only; hub packs are the extension route later).
4. Descriptors at cut-over: task, decision, glossary, artifact. Gotchas and conventions stay prose files outside the kernel until someone needs comments on them.
A collection dir with no descriptor gets generic indexing, comments and journals; no states, no regenerate; label = dir name; low-severity lint names it (dec_E01MC).
