** Findings to close
*** F1 (HIGH, BLOCK SHIP) — claim access failures become corrupt evidence, quarantine, and permission to mint
=crates/orgasmic-daemon/src/recovery_claim.rs:586-599=, =:633-640=, =:1110-1140=,
=:2066-2069=; =crates/orgasmic-daemon/src/api.rs:9427-9444=

=ClaimDirectory::open= maps every component-open error other than =NotFound= to
=RecoveryClaimError::CorruptClaim=; =read_regular= does the same for every
claim-file open error other than =NotFound=. Those buckets hold =EACCES=, =EIO=
and descriptor exhaustion — *observation failures* — alongside =ELOOP=/=ENOTDIR=,
which are observed path facts.

=load_recovery_claim= propagates it and =resolve_authoritative_recovery_claim=
reads it as invalid evidence: =quarantine_invalid_claim=, then reconstruct or
=Missing=. *For a PENDING claim there is no committed =RecoveryOrigin= to
reconstruct*, so a failed inventory read can remove the pending claim, the later
POST sees a complete origin enumeration plus no claim, and reaches
=plan_pending_recovery_claim=. An observation failure destroys authority and
mints a competitor.

*** F2 (HIGH, BLOCK SHIP) — a failed =readdir= is returned as a complete name set
=crates/orgasmic-daemon/src/recovery_claim.rs:684-710=, =:1217-1260=;
=crates/orgasmic-daemon/src/api.rs:10725-10747=

=ClaimDirectory::names= calls =libc::readdir= in a loop, breaks on NULL and
returns =Ok(names)=. *=readdir= returns NULL both at end-of-directory and on
error; the only way to tell is to clear =errno= before the call and read it
after.* This code does neither, and it discards =closedir='s return as well.
A third collapse hides in the same loop: =if let Ok(name) = name.to_str()=
*silently drops* an entry whose name is not UTF-8, making the set smaller — the
unsafe direction, for the same reason it was unsafe in round three.

=pending_recovery_claim_owns_session= trusts that vector as complete. If a
transient directory read error hides the pending claim owning a boot candidate,
it answers =ClaimEvidence::Invalid=, and boot enters generic reattach —
=Supervisor::reattach= appends =Reattach= into the immutable prefix the pending
recovery owns. *An irreversible write, and none of the five behavioural-pin
injections reaches it.*
