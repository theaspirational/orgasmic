=== The judgement call reached the OPPOSITE conclusion from the obvious one, correctly

The brief named two lint sites and insisted each be decided separately —
"do not assume one answer covers both". That instruction earned its place.

- =lint_dangling_graph_edges= (now =index.rs:1086=): =arch_= REMOVED from the
  prefix list. This is the carve-out; historical =:IMPLEMENTS: arch_= edges stay
  in the graph and no longer emit dangling-target errors.
- =looks_like_structured_node_id= (=index.rs:1109=): =arch_= *KEPT*, deliberately.

*Manager verified the second, because it is counter-intuitive and I would have
got it wrong.* That predicate has exactly ONE production caller,
=index.rs:1040=, inside the =produces= loop:

: if !looks_like_structured_node_id(target) { artifacts.entry(target.clone())... }

So it decides whether a =:PRODUCES:= value is materialised as a generic ARTIFACT
node. Dropping =arch_= there would make a retired architecture id resolvable
again — as an artifact. Exactly backwards for an excision. The implementer pinned
the consequence with
=arch_like_produced_target_is_not_materialized_as_an_artifact=.

Had the brief said "drop both", this change would have introduced a defect.

=== The finding: a SECOND, independent path to parse errors

The brief asked exactly this — "is the carve-out complete, or only complete for
the case tested?" The answer is incomplete, and the reviewer found the path the
manager and implementer both missed.

The graph-edge carve-out only touches =lint_dangling_graph_edges=. A separate
production path survives:

1. =index.rs:685= scans source markers and runs =lint_project_identity_state=;
   =index.rs:1172= pushes every finding into =parse_errors=.
2. =identity_lint.rs:253= collects architecture identities into the known-id
   universe *only while =.orgasmic/architecture.org= exists* — the loop is gated
   on =path.exists()=.
3. =identity_lint.rs:358= emits =dangling advisory marker `{id}` in {file}= for
   every scanned marker id absent from that universe. *No retired-=arch_=
   carve-out.*

*Manager confirmed the mechanism and measured the blast radius*: *59 scanned
=orgasmic:arch_= marker lines naming 36 distinct ids* across =crates/=, =ui/= and
=scripts/=.

The example that makes it vivid: =crates/orgasmic-daemon/src/index.rs:1= carries
=// orgasmic:arch_C87Z9=, resolved today only because
=.orgasmic/architecture.org:572= defines it. *After stage D, the file that runs
the lint flags itself.*
