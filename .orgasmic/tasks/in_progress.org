** F-A — HIGH — BLOCK SHIP — a boot-time durable-open failure is now TOTAL SILENCE
=logging.rs:142-143=, =:220-222=, =:449=; =lib.rs:906-914=

The chain is unconditional straight-line code:

1. =lib.rs:909= passes =requested_log_mirror(opts.no_log_mirror)=. Under the
   plist / unit / wrapper this diff writes, that is =LogMirror::None=.
2. =init_tracing_to= at =:142-143= does
   =durable_log.and_then(|path| open_durable_log(path).map(|file| (path.to_path_buf(), file)))=.
   When the open fails THE WHOLE OPTION COLLAPSES TO =None= — the path is
   discarded along with the handle.
3. =resolve_mirror= at =:220-222=: =let Some(path) = durable_path else { return mirror; }=.
   With no durable sink it returns the CALLER'S mirror unchanged, and the caller's
   mirror is now =None=.
4. =MirrorState::None=, and =state.durable_path.is_some()= is false at =:449=, so
   not even =record_drop()= fires.

Net: ZERO tracing lines anywhere, ZERO counter movement, one stderr line at boot.

PRE-DIFF the identical failure produced =LogMirror::Stdout= — the old =lib.rs=
passed =Stdout= unconditionally, the same early return preserved it, and every
line landed in launchd's =StandardOutPath= (=daemon.stdout.log=). The existing
green test =stdout_mirror_without_durable_still_writes_when_redirected= proves
that early return hands the caller's mirror straight through; it is the same
return that now yields silence because the caller supplies =None=.

SECOND LEG, SAME ROOT CAUSE: THE NEW BACKOFF IS UNREACHABLE FOR A BOOT FAILURE.
Step 2 discards the path, so =durable_path= is =None=, so =maybe_reopen_durable=
returns early forever (=:393-395=). The daemon runs its whole lifetime with no
durable log and never retries. The 1s->60s retry only covers failures AFTER a
successful boot open. The trigger class F1 names — persistent =EMFILE=, =EACCES=
on the logs dir, =ENOSPC=, =daemon.out.log= replaced by a directory — is exactly
the class that gets none of the fix.

*Fix (preferred):* keep the path when the boot open fails — construct the sink
with =durable: None, durable_path: Some(path)= so =maybe_reopen_durable= owns the
retry at 1s->60s and =record_drop()= fires per dropped line. That is machinery
this chain ALREADY BUILT, merely not wired to the boot path, and it fixes both
legs at once. A cheaper stopgap, if you can argue for it: degrade an explicit
=LogMirror::None= to =Stdout= in =resolve_mirror= when there is no durable sink —
=--no-log-mirror= means "do not double-write", not "log nothing", and with no
durable sink there is nothing to double.

*Run the probe the reviewer could not.* It was a correctly-reported unrun gap: a
read-only reviewer cannot make this fail without an edit or a staged
=ORGASMIC_HOME=. You can. In a THROWAWAY home — and note =ORGASMIC_HOME= is
BANNED inside a dispatch for any =orgasmic= invocation, so drive the daemon
binary directly rather than through a verb that may open a connection — make
=logs/daemon.out.log= unopenable (=mkdir= a directory at that path, or =chmod
000= the logs dir), start with the mirror suppressed, and confirm both the

** F-B — HIGH — BLOCK SHIP — the generated service definitions hard-depend on a binary feature, so a rollback is a launchd crash loop
=daemon_service.rs:845= (plist =ProgramArguments=), =:931= (systemd =ExecStart=), =:972= (Windows wrapper)

The plist this diff writes carries =KeepAlive= =true= and =ThrottleInterval=
(verified at =:851-853=), and =StandardErrorPath= = =daemon.err.log=. An old
binary handed an unknown =--no-log-mirror= exits non-zero from clap before doing
anything, so launchd respawns it every throttle interval FOREVER, writing clap's
usage error into =daemon.err.log= — which nothing rotates and nothing prunes.
Same unbounded-growth shape this chain exists to remove, reached from a third
direction, on top of a daemon that is DOWN rather than degraded.

REACHABILITY IS STRUCTURAL. =write_macos_launch_agent= is reached by every
install and every =orgasmic update=, and it renders from the code of the RUNNING
process — so the plist's contents and the binary on disk have INDEPENDENT
LIFETIMES. =update.rs= keeps one previous install *specifically* so a manual
rollback has a target (verified: =DEFAULT_RUNTIME_RETENTION: usize = 1=, comment
"One previous install is kept so a manual rollback still has a target"). Sequence:
new binary runs =daemon start= -> operator rolls the runtime back manually ->
reboot/login or =launchctl kickstart= -> old binary + unknown flag -> crash loop.
The only symptom is clap usage text in an unrotated log. The automatic rollback
inside =orgasmic update= self-heals only because the running process there is the
OLD binary; the manual path has no such protection.

*Fix:* move the suppression into =EnvironmentVariables= / =Environment== / =set
"…"= — the env form is strictly better here and this diff ALREADY SHIPS THE
PARSER (=env_log_mirror_off=). An old binary IGNORES an unknown env var, and
under launchd =is_terminal()= is false anyway, so a rollback degrades to
IDENTICAL behaviour instead of failing to start. The plist already has an
=EnvironmentVariables= dict, systemd already has =Environment== lines, the
Windows wrapper already has =set "…"= lines — one line each. Keep
=--no-log-mirror= as the interactive/ad-hoc override. Confirm no leakage:
non-=serve= CLI tracing goes through =init_tracing=, which passes
=LogMirror::Stdout= directly and never consults =requested_log_mirror=, so an
inherited =ORGASMIC_LOG_MIRROR=off= cannot silence child =orgasmic= commands —
verify that still holds after your change.

SECOND HALF OF THE SAME FINDING, AND IT NEEDS NO ROLLBACK: the three definitions
embed the string literal =--no-log-mirror= and NOTHING CROSS-CHECKS IT AGAINST
CLAP. The new tests assert the literal against itself; =cli_parity.rs= has no
=serve= coverage; no test anywhere executes =orgasmic serve --no-log-mirror=.
Rename or remove the clap flag and all seven service-definition tests stay green
while every generated definition becomes a start failure. Add a test that runs
the flag through the real =Cli= (or execs it) so the literal and the parser
cannot drift.
