=crates/orgasmic-daemon/src/recovery_claim.rs:1094-1114,1282-1297=

=enumerate_recovery_origin_links= returns =None= only when =read_dir= itself
fails or a directory entry cannot be read. For each readable =*.jsonl= it calls
=index_recovery_origins_in_session=, whose return type is
=IndexedRecoveryOrigins= — *a type with no way to say "I failed"*. Manager-verified

Three error paths, three empty-but-successful results. The outer function then

*The rejected safety state is recreated through the filesystem slow path*: keep

*** F2 (HIGH, BLOCK SHIP) — the bounded scan treats its skipped middle as absence, and the miss is PERMANENT
=crates/orgasmic-core/src/session.rs:1162-1165,1312-1366=;
=recovery_claim.rs:1094-1122,1370-1392=; =supervisor.rs:1383-1395,2309-2341=;
=api.rs:8716-8765,9222-9232=

=SessionLifecycleScan= EXPLICITLY DOCUMENTS that a truncated scan's skipped
middle must be treated as *unknown rather than absent*.
=index_recovery_origins_in_session= ignores =scan.truncated= and returns only
retained links. The new enumerator calls that bounded scanner for every file and
labels the union authoritative.

Round 2 disclosed this and argued "=RecoveryOrigin= is written near the head".
*The condition is real and is not enforced.* The reviewer named the production
mechanism that violates it: =PromptDraft= is written BEFORE =RecoveryOrigin=;
the committed snapshot embedded in =RecoveryOrigin= REPEATS that draft; and the
draft includes *uncapped output from =git diff --stat=*. A large enough diff stat
pushes the envelope past the 128 KiB prefix, or makes the lifecycle line itself
cross that boundary. Add more than 64 KiB of later driver output and it is
outside the tail too. *No size invariant prevents this.*

The consequence is worse than a miss. On that miss the loaded committed claim is
QUARANTINED (=:1385-1392=), and the catalog uses THE SAME bounded scanner, so a
later reconstruction cannot rediscover the link — *the refusal is PERSISTENT, not
the "retry" the code comment claims.* The handler can then reach the no-plan
branch and mint another replacement. So the safety fix produces the very
duplicate authority it exists to prevent, by a second route.

** Acceptance
1. *THE CLASS, FIRST AND STRUCTURALLY.* Make "I did not observe" unrepresentable
   as "I observed nothing". =index_recovery_origins_in_session= must return a
   type that carries completeness, and =IndexedRecoveryOrigins::default()= must
   stop being reachable as an error path. Prefer a shape the COMPILER enforces —
   if the unresolved variant cannot be silently discarded at a call site, round
   four cannot happen the way rounds one through three did. *State how a future
   call site is prevented from re-collapsing it*, and pin that with a test the
   way TASK-QGWK7 round 7 pinned its marker table.
2. F1 closed: per-file open/scan/malformed-lifecycle errors propagate through
   =enumerate_recovery_origin_links=; they never become an empty successful set.
3. F2 closed: =SessionScanBudget::DEFAULT= is never proof of global absence. On
   =scan.truncated= where uniqueness is not provable, do a full streaming
   lifecycle enumeration, or use a source with an explicit completeness
   contract. *Unresolved observation must stay distinct from invalid data* —
   see Open Question 1 below; a transient read failure must not durably destroy
   a valid claim's idempotency.
4. F3 closed: the missing/corrupt branch decides from the same authoritative set.
   =Missing= is safe only after a complete candidate set proves there is no
   authenticated replacement.
5. F4 closed: build ONE complete per-project authoritative snapshot per

   >192 KiB replacement transcript; (c) missing/corrupt reconstruction with the
   replacement's catalog record invalidated. Each must prove the visible claim is
   never returned =Valid= — *and that a single valid live rescue is not

** The reviewer's open questions, carried verbatim as design input
1. *Unknown completeness should not be represented as invalid evidence.* A
   distinct =Unresolved= result should suppress recovery authority WITHOUT
   renaming a valid committed claim; persistent unreadability can otherwise turn
   a transient observation failure into durable loss of idempotency.
2. The cleanest current-tree option appears to be a streaming full lifecycle scan
   on bounded-scan uncertainty, with per-file errors propagated and one
   per-project result shared across the inventory pass. An explicit catalog
   generation can work too, *but only if its completeness contract includes
   invalidation and scan failures rather than merely cache freshness.*
3. The missing/corrupt branch needs its own round even after the committed branch
   is repaired.
