*** F3 (MEDIUM) — F2's residual statement is materially narrower than the code
=crates/orgasmic-cli/src/manager.rs:4196-4208,4291-4353=; subprocess groups at
=:2469-2532,4111-4165=

The new doc comment says =assert_path_names= is re-taken immediately before EACH
git subprocess, narrowing the residual to a subprocess's own pathname
resolution. The code does not do that:
- one assert precedes =worktree_has_uncommitted_changes=; =worktree_head_oid=
  then runs with no new assert;
- one assert precedes =salvage_worktree_onto=, which runs =add=, =write-tree=,
  =commit-tree=, =diff-tree=, =checkout=, another status and the salvage-ref
  commands with no identity assertion between them;
- one assert precedes =git_would_remove_worktree=, which runs =git worktree
  list= FIRST and only afterwards resolves the pathname for =git status=.

So for the deletion-critical clean decision an actor need not fit between an
assert and its immediately following =execve=: it can wait out the whole
worktree-list subprocess, bind a clean decoy for the status call, and bind the
original back before the final assertion. The deletion stays identity-anchored,
but the inode removed can be the dirty unsalvaged one. Either assert directly
before every path-resolving subprocess, or rewrite the statement to describe the
real windows. *A doc comment that overstates a mitigation is the defect class
this project has paid for four times.*
