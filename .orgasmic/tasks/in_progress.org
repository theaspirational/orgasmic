** Description
From the TASK-YN5FJ manager review, section "Manager review and verdict".
CONFIRMED against production, not reasoned.

The default-branch gate requires a =reviewer.done= carrying a non-empty
=VERDICT=. =VERDICT= has NO FLAG — it is settable only through the generic
=--property VERDICT=...=, and it was previously optional, read by
=reviewer_done_stage= only to choose the task's next stage (=.unwrap_or(false)=).

So the refusal text — "Dispatch and close a reviewer for that reported
generation, or re-run with --no-review-required --reason <why>" — names a first
branch that DOES NOT WORK. Follow it exactly and you are refused again with the
same message.

*Production evidence.* =tx-20260803-orgasmic-4401=, the =reviewer.done= this
manager wrote for TASK-XCJYC, carries =REASON=, =REVIEWED_DIFF=, =CLOSED_TX=,
=MODEL=, =EFFORT= and lifecycle properties and NO =VERDICT=. It is an ordinary,
correctly-formed reviewer close that the new gate rejects. Every historical
reviewer close is the same shape.

** Fix
1. Add a first-class =--verdict= flag to =dispatch-close= for reviewer closes,
   so the value the gate depends on is a documented part of the surface rather
   than an incantation through =--property=. Keep accepting the existing
   =--property VERDICT= spelling so nothing already written breaks.
2. Consider a typed value set (approve / approve-with-follow-ups / reject)
   rather than free text. This also answers the implementer's own declared
   residual risk that any non-empty verdict — including a negative one —
   currently satisfies "a verdict exists". Decide deliberately whether a REJECT
   should unlock a default-branch merge; there is a real argument either way
   (a REJECT the manager then resolved is exactly what happened on TASK-XCJYC),
   so state the reasoning rather than picking silently.
3. Name the verdict requirement IN the refusal text, so the remedy is
   self-contained.

** Ordering
Land this BEFORE any runtime reinstall. The gate is not live until the runtime
is rebuilt, so there is no live breakage today — but the first reinstall after
TASK-YN5FJ without this fix hands the operator a refusal they cannot clear
except by =--no-review-required=, which defeats the feature.

** Acceptance
- A reviewer close can record its verdict through a documented flag.
- Following the refusal's stated remedy actually clears the refusal — pin this
  with a test that walks the full loop: refuse, follow the remedy verbatim,
  succeed.
- Existing =--property VERDICT= closes still work.

* IN_PROGRESS TASK-M47E5 Move dispatch worktrees out of TCC-guarded directories, and give them a prune :daemon:cli:macos:dispatch:
:PROPERTIES:
:ID: TASK-M47E5
:MOTIVATED_BY: TASK-3X5AQ
:PRIORITY: P1
:WRITE_SCOPE: crates/orgasmic-daemon/**,crates/orgasmic-cli/**,shipped/**
:END:

** Description
Implements the fix decided on TASK-3X5AQ. Read that task's two measurement
sections first — "The cdhash measurement" and "Verification and recommended
placement (2026-08-05)". Everything below is already measured; do not re-derive
it, and in particular do NOT revive the shared =CARGO_TARGET_DIR= or the
stable-slot idea. Both are disproved there, with reproductions.

*Why the move works, in one line:* a TCC grant for a linker/ad-hoc-signed binary
is pinned to its CDHASH, so no path scheme can make a grant survive a rebuild.
The only durable answer is to stop needing a grant — put the worktree where
macOS does not guard.

=== Part 1 — move the managed worktree root
Change the DEFAULT managed worktree path from
=<project>/.orgasmic/tmp/dispatch/<task>/worktree= to:

: ~/.orgasmic/worktrees/<project-id>/<task-id>/

- Key on PROJECT ID, not display name — the id is what the CLI and daemon
  already use (=--project <id>=) and names can collide or change.
- MOVE ONLY THE SCRATCH. The dispatch RECORD — brief, =last.txt=, stdout log
  under =.orgasmic/tmp/dispatch/<task>/= — STAYS in the project. It is small,
  durable, written by the already-granted daemon, and leaving it keeps every
  existing brief-path reference in gotchas, briefs and memories valid.
- =orgasmic manager dispatch --worktree <PATH>= already exists as the override,
  so this changes the managed default only and adds no new surface.
- UNIVERSAL, not macOS-gated. Linux has no TCC, but the repo still stops
  accumulating multi-GB build trees and =git status= stays clean. One code path
  beats a platform branch.

Verified already (TASK-3X5AQ): a worktree there resolves its =.git= back into
the Documents-hosted repo, =status=/=log=/=remove= all work, the worktree's own
=.orgasmic/project.org= keeps project resolution working, it is on the same
filesystem, and the toolchain builds and runs from it.

Rejected alternative, for the record: =~/Library/Caches/orgasmic/...= is the
idiomatic macOS location and IS unguarded (zero TCC rows for Cache services) —
but macOS may PURGE it under disk pressure and destroy a worktree mid-dispatch.

=== Part 2 — pruning, which is NOT optional here
This is a REQUIREMENT OF THE MOVE, not a follow-up. Today a stray worktree sits
inside the repo where =git status=, =git worktree list= and the operator's own
eyes find it. After the move it is invisible, so the same leak becomes silent
multi-GB accumulation in =~/.orgasmic=. Shipping Part 1 alone trades visible
garbage for invisible garbage.

What exists today, measured 2026-08-05:
- =dispatch-close --worktree-remove= (DEFAULT TRUE) salvages uncommitted work to
  =refs/orgasmic/salvage/<sha>= and then removes WITHOUT =--force=, so git's
  clean check gates it.
- =dispatch-status --orphans-only= REPORTS dispatches whose run is gone.
- =dispatch-status --cleanup-failed= writes the orphan close tx and clears
  LEASES — not worktrees.

What does NOT exist: any call to =git worktree prune=, any age-based GC, any
boot-time or periodic sweep, any disk budget.

So three leaks survive close today, and all three become invisible after Part 1:
1. *A DIRTY worktree is never removed* — removal is deliberately non-forced.
2. *An ABANDONED dispatch* (worker died, manager never closed) keeps its
   worktree forever.
3. *Stale =.git/worktrees/<name>= metadata* accrues if a directory is removed
   out of band, which the move makes MORE likely because the new root is a
   plausible thing for an operator to =rm -rf=.

And Part 1 introduces a genuinely NEW failure mode to handle: a worktree whose
REPO no longer exists. Today worktrees die with the repo; afterwards they are
orphans pointing at a missing gitdir, and =git worktree remove= cannot help
because there is no git to run it from. Detect and handle this explicitly.

*Design constraints for the prune:*
- NEVER remove a worktree with an open dispatch or a live run. Reuse the
  existing health signals rather than inventing new ones.
- Salvage before removing, reusing the existing =refs/orgasmic/salvage/<sha>=
  path — do not add a second salvage mechanism.
- REPORT WHAT IT SKIPPED AND WHY, and how many bytes it reclaimed. Silent
  truncation reads as "cleaned everything" when it did not; this project has
  been bitten by that shape repeatedly.
- Prefer extending the existing orphan surface (=dispatch-status
  --cleanup-failed= and its health checks) over building a parallel reaper.
  Adding machinery where existing machinery can be made consistent is what took
  a sibling chain five fix rounds.
- Decide deliberately whether prune runs automatically (daemon boot and/or at
  close) or only as an explicit verb, and SAY WHY. An automatic reaper that
  deletes a worker's tree is a much sharper tool than a verb.

=== Acceptance
- A dispatch's managed worktree is created under
  =~/.orgasmic/worktrees/<project-id>/<task-id>/= and nothing under
  =~/Documents= is written by the worker's build.
- The dispatch record (brief, report, logs) still lands in the project.
- =--worktree <PATH>= still overrides.
- Closing a dispatch still removes the worktree, still salvages first, and still
  refuses to force-remove a dirty tree.
- A prune surface reclaims worktrees for closed or absent dispatches, refuses to
  touch live ones, names what it skipped and why, and reports bytes reclaimed.
- A worktree whose repo is gone is detected and removable.
- =git worktree prune= is run so stale =.git/worktrees= metadata does not
  accumulate.
- Gotchas, briefs and any shipped text naming
  =.orgasmic/tmp/dispatch/<task>/worktree= are updated in the same change —
  =cli_parity= resolves shipped invocations against the real binary and is the
  gate that catches a doctrine edit that lags the code.
