** Description

Stage C, part 2 of 2: remove the architecture READ MODEL from the daemon and CLI,
*and land the dangling-edge lint carve-out*. Read =TASK-RQ270= for the staged plan
and the coupling map. TASK-RQ270.3.1 removes the UI and lands first.

** THE ORDERING CONSTRAINT THIS WHOLE EXCISION DEPENDS ON

*The lint carve-out lands HERE and must be on main BEFORE stage D deletes
=.orgasmic/architecture.org=.* If stage D runs first, every =:IMPLEMENTS: arch_=
token in the task ledger becomes a dangling graph edge and the daemon starts
emitting parse errors for the whole board.

Measured at HEAD, not estimated: *141 =:IMPLEMENTS:= lines carrying =arch_=
tokens* across the task files — 138 in =done.org=, 3 in =backlog.org= — bearing
*243 individual =arch_= tokens*. (The parent task says 231; that figure is
approximate and predates this measurement.)

The two sites:

- =crates/orgasmic-daemon/src/index.rs:1255= — =lint_dangling_graph_edges= only
  lints structured-id targets, and =arch_= is one of the four prefixes it checks.
  Dropping =arch_= there is the carve-out.
- =crates/orgasmic-daemon/src/index.rs:1280= — =looks_like_structured_node_id=
  carries the same four prefixes and governs write-time reference validation.

*Decide both deliberately and say why.* Dropping =arch_= from the first stops the
dangling lint firing after stage D. Dropping it from the second stops =arch_=
tokens being treated as resolvable references at write time — which is what a
retired class should look like, but it is a different consequence. Do not assume
one answer covers both.

** Acceptance

- No route, index projection or CLI verb reads the architecture layer.
- The dangling-edge lint does not fire on =arch_= targets, proven by a test that
  constructs an =:IMPLEMENTS: arch_= edge with no resolving node and asserts *no
  parse error*. This is the gate stage D depends on; assert it, do not describe
  it.

  parse.
- =parse_errors= is 0 on this repository's own state after the change.
- =cli_parity= passes — it resolves every =orgasmic ...= invocation in =shipped/=
  against the real binary, so doctrine naming a deleted verb fails there.
