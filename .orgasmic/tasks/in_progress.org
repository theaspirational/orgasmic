** Findings to close
*** P1a (HIGH, bug/operability) — the F3 operator notice is wired to buckets that can never carry it
=crates/orgasmic-daemon/src/api.rs:12084-12090=, =:7552-7569=;
=ui/src/lib/types.ts:445-452=; =ui/src/components/RunsView.tsx:54-62=

The daemon applies =recovery_unobserved*= only to =failed_recoverable= records
and =GET /runs= serializes them under =failed_recoverable=. *=RecoveryInventoryResponse=
does not have that field*, and =flattenRuns= flattens only =live=, =interrupted=,
=reattached=, =ambiguous=, =terminal_noop=. So =recoveryUnobservedNotice= runs
only on classifications that cannot carry the diagnostic, and *the permanently
refused recoveries are absent from the table altogether.* The operator still
cannot see the named file or the documented repair.

*Manager-confirmed independently by reading both files.* This is exactly the
surface round five declared untested ("=ui/node_modules= is not installed …
unchecked by =tsc= … that is an untested surface and I am naming it"). The
declaration was honest; the surface was broken.

*AND — THIS IS THE PART NEITHER THE REPORT NOR THE FINDING SAYS — =tsc= WOULD NOT
HAVE CAUGHT IT.* A field the backend sends and the frontend type omits is not a
type error; TypeScript's structural typing ignores extra properties on the wire.
=npm run typecheck= is therefore NOT the fix and NOT the pin. *Only a component
test that renders a =failed_recoverable= response can hold this.*
