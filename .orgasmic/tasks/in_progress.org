*** F1 (HIGH, BLOCK SHIP) — a silent catalog can hide contradictory authenticated replacements, and the resolver now accepts one
=crates/orgasmic-daemon/src/recovery_claim.rs:1294-1299=

The new branch treats =matching.len() == 0= as non-contradictory and returns the
loaded claim whenever its own transcript verifies. *An empty slice carries no
statement about completeness.* =collect_recovery_origin_index= can return nothing
because:
- a board entry, path, identity or session directory is unavailable;
- a catalog record is absent or lacks =replacement_run_id=;
- a candidate scan rejects the file;
- or — the load-bearing case — =RunCatalog::invalidate_session= removed every
  relevant live entry (=crates/orgasmic-daemon/src/api.rs:11831-11873=,
  =crates/orgasmic-daemon/src/run_catalog.rs:1124-1134=).

*This codebase already rules that two daemon-HMAC-authenticated replacements for
one origin is a safety violation.*
=duplicate_authenticated_replacements_fail_closed= builds both valid transcripts
and REQUIRES =InvalidQuarantined=
(=crates/orgasmic-daemon/src/recovery_claim.rs:2455-2543=).

If both replacement records have been invalidated by lifecycle appends, the
collector supplies no links; the changed branch verifies only the LOADED claim's
transcript, returns =Valid=, and *never discovers the other authenticated
replacement*. =/api/runs/:id/recover= then hands back that one replacement
(=api.rs:9075-9097=) and inventory clears recovery actions
(=api.rs:11780-11801=) — silently choosing authority in exactly the state the
existing regression requires to fail closed.
