** D-1 — BLOCK SHIP — restore the =sequencer= entry, WITH A BETTER MESSAGE
=crates/orgasmic-cli/src/manager.rs:5793-5801= (array), =:5808-5816= (doc).
*MANAGER RULING REVERSED, AND MANAGER-REPRODUCED.*

The previous round dropped =("sequencer", "revert or cherry-pick sequence")= on
my instruction, justified by "every stopped revert/cherry-pick range ALWAYS
carries its own =*_HEAD= marker, so the entry adds no coverage". *That universal
is FALSE.* Counterexample by an ordinary, documented git workflow — resolve the
conflict and =git commit= instead of =git revert --continue=:

#+begin_src bash
git revert --no-edit HEAD~1 HEAD~2      # stops between picks
#   .git -> REVERT_HEAD, sequencer          <- refused, correctly
echo resolved > f.txt && git add f.txt && git commit -qm "resolved by hand"
#   .git -> sequencer ONLY                  <- NO *_HEAD marker
#   .git/sequencer/todo still lists two pending reverts
#+end_src

Manager reproduced this verbatim. The range is NOT abandoned — =git revert
--continue= resumes it from there. In that state the guard now returns =None= and
the close COMMITS the record mid-range, at a point the manager did not choose; if
they later abandon with =git reset --hard <pre-range>= the record dies with it.
*Before that round this state was refused, so the removal is a coverage
regression*, and the acceptance item "a stopped range is still refused via its
=*_HEAD= marker" is falsified.

*THE LATCH IS STILL REAL* — after =git reset --hard=, =.git/sequencer= survives,
=git status= says nothing, an ordinary commit does not clear it, and only
=git revert --quit= does. Reviewer reproduced my measurement. *But the failure
mode was never the ENTRY — it was the MESSAGE*, which told the manager to wait
for a sequence that cannot finish.

*Fix (exit (a), the reviewer's lean and mine):* restore the entry AND special-case
the advice. When the marker that fired is =sequencer= with NO =*_HEAD= beside it,
say: "finish it with =git revert --continue=, or — if you already abandoned this
range with =git reset --hard= — clear the leftover todo list with
=git revert --quit=". That turns a permanent unexplained refusal into a one-command
self-serve fix AND keeps the F-1 state covered. *Pin BOTH:* the abandoned-range
close must name =--quit=, and the manual-commit state must be REFUSED.
