From TASK-5FEN5's report (2026-07-29): every test in
crates/orgasmic-daemon/tests/dispatch_endpoint.rs installs a FRESH fake agent
executable, and on macOS its first exec queues behind a system-wide serialized
Gatekeeper evaluation (recorded in .orgasmic/gotchas.org). Under
suite-concurrent load that queue eats fixed wait budgets and the file's tests
time out in a family:

- `dispatch_system_only_session_without_finalize_orphans_not_scrapes` —
  "timed out waiting for session ready" (dispatch_endpoint.rs:1395). 5FEN5
  reproduced it suite-concurrently (RED 1 of 3 loaded) and raised its 5s bound
  to the file's 30s convention as a MITIGATION, explicitly labelled a bound
  change, not a fix.
- Five siblings seen red with the same fixed-budget shape, "timed out waiting
  for synthetic run_complete in <session>" (dispatch_endpoint.rs:2449):
  `dispatch_subprocess_exit_synthesizes_run_complete_from_system_tail`,
  `dispatch_clean_worktree_protocol_end_without_finalize_orphans`,
  `dispatch_delayed_protocol_end_without_finalize_orphans`,
  `dispatch_cursor_shaped_session_without_finalize_orphans_not_scrapes`,
  `dispatch_early_exit_auto_releases_stuck_lease`.

TASK-STWVB already removed this exact cost from the daemon UNIT tests with one
pre-warmed shared fixture; this file never got the treatment.

=== Ask

Rework dispatch_endpoint.rs fixture installation to use ONE pre-warmed shared
fake-agent executable (exec'd once at fixture setup so Gatekeeper evaluation is
paid before any test budget starts), instead of a fresh executable per test.
This is the durable fix 5FEN5 declined to smuggle into its scope.

=== Acceptance

- One shared, pre-warmed executable serves the file; no per-test first-exec
  remains on any timed path.
- The named family runs green suite-concurrently (dispatch_endpoint beside a
  looping `orgasmic-daemon --lib --test-threads=64` plus cpu hogs — 5FEN5's
  recipe; hogs alone do NOT reproduce this class).
- The 30s bound on wait_for_session_ready may stay as a hang guard; the point
  is that Gatekeeper no longer spends it.
- Injection per TCTTD standard if patch-expressible; if the trigger is load
  itself, pin A/B counts in the report per the 5FEN5 precedent and say so in
  the artifact README.
