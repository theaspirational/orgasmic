** 1. HIGH — the required supervisor-path regression is a surrogate that cannot
   detect a regression (in this diff)

`crates/orgasmic-daemon/src/supervisor.rs:4698,4788,9309`.

`StalledRmuxReapControl::release` waits on a local sleep and then sets
`session_live = false` **itself**. It never constructs `RmuxControl`, never owns
an `rmux_sdk::Session`, never stalls `Session::kill`, never invokes
`run_rmux_cli_os`, and never proves an rmux session disappeared.

So restoring the original `self.session.take()`-before-await bug, deleting the
CLI call from `RmuxControl::release`, or pointing the fallback at the wrong
endpoint would all leave this test **green**. The live test at
`crates/orgasmic-drivers/tests/rmux_release_reaps_session.rs:137` calls
`control.release` directly and covers only the happy path, so the two do not
compose into the acceptance criterion.

The TASK-6FNAY acceptance asked for exactly one thing this does not deliver: a
stalled SDK request driven through the real 5-second `Supervisor::release` path,
with the fallback observed and the real session gone.

Required (reviewer direction 1): replace the `StalledRmuxReapControl` proof with
a test that sends a real `RmuxControl` through `Supervisor::release`. Give it a
controllable SDK endpoint that stalls the kill request and an endpoint-exact CLI
fallback whose argv can be observed. Assert three things: the fallback ran, the
actual session is absent, and `RunComplete` was persisted — after the real
5-second caller boundary, not a simulated one.

** 2. MEDIUM — the fail-closed rmux lane is not wired (in this diff)

`crates/orgasmic-drivers/tests/rmux_release_reaps_session.rs:65-77,109-119`.

The test fails closed only when `ORGASMIC_REQUIRE_LIVE_RMUX=1`. Otherwise a
missing or incompatible rmux, and an inert acquire, still return success. At

script or checked-in gate sets it, and the assigned drivers gate does not either.
A worker without rmux still gets a green skip.

That does not satisfy the acceptance item "at least one test fails, rather than
skips, when rmux is absent in a lane designated as a gate."

Required (reviewer direction 2): wire the absent-rmux failure into a durable
gate. On current main the cheapest correct answer is to explicitly declare
TASK-RRT4T's `required_test_tooling_is_present` sentinel as the lane that
satisfies this task — but *declare* it, in the task or a convention, rather than
leaving it implicit. If you instead keep `ORGASMIC_REQUIRE_LIVE_RMUX`, it must be
set by a checked-in gate that installs rmux and fails if it is absent.

**no regression defines the explicit-release cancellation boundary**. Either
define it with a test or record why those kinds are exempt.
