** Description
Fix round for the BLOCK SHIP that rejected TASK-ZBYH3.

*The origin of this defect is the parent task's own wording, and that should be
said plainly.* TASK-ZBYH3's body told the implementer that rulings A and B
"compose". *They conflict.* The implementer took both, exactly as instructed, and
the result relocates the defect instead of fixing it. This is a manager framing
error, not an implementer miss.

** Why they conflict
- *B* suppresses the stdout mirror only when fd 1 and the durable path share
  *device+inode* (=logging.rs:162= =stdout_same_as_path=, =:181= =resolve_mirror=).
- *A* moves =StandardOutPath= to =logs/daemon.stdout.log= (=daemon_service.rs:372=)
  — deliberately a *different inode*.

B's discriminator is inode equality. A's whole purpose is to break inode
equality. So on any daemon started from a rewritten service definition,
=stdout_same_as_path= returns *false*, =LogMirror::Stdout= survives, and every
tracing line is written twice again:

| file | contents | rotated | pruned | read by |
| =daemon.out.log= | full tracing stream (durable sink) | yes, ~10MiB x 3 | — | operator |
| =daemon.stdout.log= | full tracing stream (mirror, via launchd) | *no* | *no* | *nothing* |

*Total write volume and total disk growth are UNCHANGED from the pre-fix defect.*
Only the distribution moved — into a file that no rotation, no pruning, no
=doctor= check and no error message mentions. ~300MB/year at the measured rate.

Worse on Windows: =same_file_as_path= is =#[cfg(not(unix))] -> false=
unconditionally, so B can never fire there at all. Same for the systemd unit
(=daemon_service.rs:946=) and the Windows wrapper (=:977=).

It looks correct on the operator's box *today* only because the installed plist
has not been rewritten yet and still points at =daemon.out.log=, so B fires.

** The ruling — gate the mirror on a terminal, not on inode identity
Replace the inode discriminator with =std::io::stdout().is_terminal()=. launchd's
stdout is never a tty, so this suppresses the mirror under any service manager
regardless of which file =StandardOutPath= names — it subsumes B *and* survives
A, and it works on Windows where the inode check cannot.

*The caveat that must not be missed:* =init_tracing= (=logging.rs:107=), used by
every non-=serve= CLI command (=main.rs:1347=), passes =LogMirror::Stdout= with
=durable_log = None=. Gating there would silence CLI tracing whenever output is
piped or redirected. *The tty gate must apply ONLY when a durable sink is
present* — exactly where =resolve_mirror= already short-circuits on
=durable_path == None= (=logging.rs:182-184=).

Keeping A (the separate =daemon.stdout.log=) is fine and preferable once the
mirror is correctly gated, because it also keeps stray =println!=/panic output
off the durable inode. If you keep it, the four =bail!= strings in
=daemon_lifecycle.rs= (=:780,:792,:807,:823=) should name it alongside
=daemon.out.log= and =daemon.err.log=. The plist-string test at
=daemon_service.rs:1169-1175= moves with whatever you choose.

** F3 — MEDIUM, and the second thing that must be fixed here
*A failed reopen after a SUCCESSFUL roll silences the durable log permanently,
invisibly.* On the =None= arm of the post-rename reopen (=logging.rs:403=) the
code sets =durable = None= and =bytes_written = 0=. Thereafter:

- =write_all_best_effort= (=logging.rs:283=) is
  =if let Some(file) = state.durable.as_mut()= — with =None= it writes nothing
  *and never calls =record_drop()==. So =dropped_log_writes= stops moving and the
  degradation is invisible *through the very mechanism this task designated for
  it*.
- =maybe_rotate= never runs its body again (=bytes_written= frozen at 0), so
  nothing ever retries the open.

A transient =EMFILE= or =ENOSPC= at the moment of a roll turns the durable log
off until the next restart, silently. Pre-fix that state was only reachable at
startup, where =open_durable_log= at least emits one stderr note; rotation makes
it reachable at runtime, indefinitely, and quietly.

Fix: =record_drop()= in the =durable == None= branch, and make the reopen
retryable — cheapest is to keep counting into =bytes_written= even when the write
is dropped, so =maybe_rotate= fires again and retries =open_durable_log=.

** F4 — silent loss of a retained generation
=logging.rs:372='s =Err(_) => {}= is not a no-op. If =.1 -> .2= fails, the loop
swallows it and the following =current -> .1= rename *overwrites =.1==, so the
generation that should have become =.2= is gone and the effective keep count
silently drops to 1. The final rename already gets both =record_drop()= and an
stderr note (=:379-385=); the intermediate ones need the same two lines.

** F5 — the rotation test would pass on a broken roll
=logging.rs:549= asserts disjunctively —
=rolled_blob.contains("second-content") || rolled_blob.contains("early-content")=
and =current.contains("third") || rolled1.contains("third")=. Swapping the roll
order so =current -> .1= runs BEFORE =.1 -> .2= destroys the newest rolled
generation on every roll, and both assertions still pass. The end state is fully
deterministic — =.1 = third=, =.2 = second=, current empty, =early= evicted at
=keep=2=. *Assert the exact three-file end state.*

** F6 — unvalidated config
=config.rs:39,44=: =log.keep= and =log.max_bytes= are unvalidated.
=logging.rs:366= performs =keep - 1= =rename(2)= calls on EVERY roll regardless of
how many rolled files exist, *while holding the sink mutex every tracing line
needs*. A typo'd =log.keep: 100000= turns each roll into 100k syscalls under the
logging lock. Clamp =keep= to a small maximum, surface out-of-range values
through the existing startup-warning path, and break the loop once a source path
is =NotFound=.

** F7 — the production suppression path is untested
Both the unit test (=logging.rs:481=) and the shipped verify artifact exercise
=LogMirror::Writer= -> =same_file_as_path=. The path that actually decides this in
production is =LogMirror::Stdout= -> =stdout_same_as_path= (=logging.rs:162=).
Whatever discriminator you land on, *test the production path*.

** Acceptance
- Under a launchd-shaped launch (stdout redirected to a file, ANY file), a line
  logged once appears *once* across =daemon.out.log= and =daemon.stdout.log=
  combined. Assert the combined count — that is the claim the previous round
  failed.
- Interactive =orgasmic serve= on a tty still prints to the terminal.
- Non-=serve= CLI commands still trace when piped or redirected (the
  =durable_log = None= caveat).
- A failed reopen after a roll moves =dropped_log_writes= and is retried.
- A failed intermediate rename is counted and noted.
- The rotation test pins the exact end state of all three files.
- =keep= is clamped; an out-of-range value is surfaced, not silently obeyed.

** The bar
The previous round's proof pinned =LogMirror::Writer=, which is not what runs in
production — that is why a fix that relocated the defect still passed its own
gate. *Pin the production discriminator this time*, and prove the combined
two-file count, not the single-file count.
