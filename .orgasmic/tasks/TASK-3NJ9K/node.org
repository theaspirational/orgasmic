** Description

During TASK-95SGV.2 a daemon test (commit =560eb77=, probed on main as
=f215bb7=) called =spawn_worker_run= with a real =StageWorker { driver:
"acp-stdio", harness: "hermes" }=. The author guarded the second call
(after the injected refusal was released) with the assumption that the branch
is *unreachable without a hermes binary*. On CI that holds; on a developer
machine =hermes= is on =$PATH=, so every test execution spawned a real
=hermes acp= subprocess and a billed ollama-cloud turn. The spawned agents
outlived the test (run release does not reap the subprocess), became PPID-1
orphans, mutated main, and re-ran the test — each run spawning another copy
until the hermetic rewrite =184813f= merged as =b510b30= (spawn window
07:22–07:35, 12+ real agent sessions).

The class of defect: nothing in the daemon prevents a test from resolving a
*real* driver/harness. Host-dependent assumptions convert into provider spawns
silently.

** Acceptance

- In the daemon's test profile (=cfg(test)= and/or an explicit test-mode flag
  the API fixtures set), driver/harness resolution must refuse to construct
  any transport that can exec a real subprocess harness: only the stub driver
  (and any purpose-built in-process fakes) are resolvable.
- The refusal is loud: resolving =acp-stdio=, =rmux=, or any future real
  driver under the test profile fails the test with an error naming the
  driver and pointing at the stub, rather than silently substituting.
- Production resolution paths are byte-for-byte unaffected; no runtime check
  is added outside the test profile without justification.
- A regression test proves the guard: a test that requests a real driver via
  the ordinary dispatch surface must get the refusal, on any host, with and
  without a =hermes= binary on =$PATH=.
- Audit the existing daemon test suite for other =StageWorker= constructions
  naming real drivers/harnesses and migrate them to the stub; list the
  migrated sites in the worklog.
- No test in the suite may depend on the presence *or* absence of a
  provider binary on the host.
