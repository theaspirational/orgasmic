<Section title="Final answer">
<RichText>
**Short version: don't.** All three models independently agree that SQLite over NFS or SMB with multiple machines is unsafe: POSIX advisory locking is broken or unreliable on most network-filesystem implementations, so two writers can corrupt the database. WAL mode is ruled out entirely — it coordinates through shared memory (the `-shm` file, via mmap), which cannot work across machines.

What to do instead, in order of preference:

- **Replicate instead of sharing the file.** Run SQLite locally and replicate with Litestream or LiteFS, or step up to a client-server database if you truly need concurrent writers. *(E3)*
- **Single client only:** if exactly one machine ever touches the file, `PRAGMA locking_mode=EXCLUSIVE` plus rollback-journal mode is workable. *(E2)*
- **Last resort:** the `unix-dotfile` VFS replaces POSIX locks with lock files, dodging broken NFS locking at a real performance and robustness cost. *(E1)*

**One claim stayed unresolved:** E2 says NFSv4 with a correctly configured lock daemon is acceptable for low-concurrency use; E1 says no network filesystem is ever safe. Both positions are shown; verify against SQLite's own documentation before relying on either (see "To verify").
