* dec_YKFZX Should a regular install build from source or use prebuilt runtime bundles?
:PROPERTIES:
:ID: dec_YKFZX
:STATUS: accepted
:SUPERSEDES: dec_XSV21
:TAGS: install,runtime,update,onboarding
:END:

Regular install is bundle-managed and separate from any source checkout. A contributor may keep an editable clone anywhere on the machine, including this repo, but that clone is not the regular-user runtime. The installed runtime lives under =$ORGASMIC_HOME/runtimes/<version>-<target>/= with =$ORGASMIC_HOME/current=, =$ORGASMIC_HOME/orgasmic=, =$ORGASMIC_HOME/bin/orgasmic=, and =~/.agents/skills/orgasmic= as managed symlinks. The compatibility =$ORGASMIC_HOME/orgasmic= path is shipped content in bundle mode, not a git checkout.

=install.json= is the authority for install mode. In bundle mode =orgasmic update= fetches a channel manifest, verifies the runtime tarball SHA-256, refuses live runs, swaps only the managed runtime links, refreshes shipped skill/content, and preserves prior runtimes for rollback. It follows the channel's moving =runtime-latest.json= pointer (no newer-than/monotonic guard, so a moved channel can downgrade), but short-circuits as a no-op (=already up to date=) when that pointer already names the installed-and-active runtime for the current target AND no temporary daemon =--from-source= override is set. An active override is never treated as up to date, so update still clears it and returns the daemon to the managed runtime. In source mode, selected explicitly by =scripts/install.sh --from-source <checkout>=, =orgasmic update= keeps the git/cargo rebuild behavior for the contributor checkout.

Install/update never replaces =$ORGASMIC_HOME/user=, =state=, =sessions=, =secrets=, =logs=, =config.yaml=, auth tokens, or registered project =.orgasmic/= files. The desktop app update remains separate internally, but the app presents one visible update action that updates the app shell and then invokes/checks the runtime update.
