* dec_N17XX What operational defaults should v0.0.1 adopt for config, networking, and secrets?    :runtime-defaults:

** Context
Several operational defaults need to be pinned before architecture can split config, auth, and runtime modules. Hardened defaults give a stronger security posture but delay local product proof with keyring, sandbox, and approval work; cloud-ready defaults ease future hosting but violate the single-user local scope.
** Decision
Adopt local-first defaults: =config.yaml= as the config format, localhost default with LAN opt-in, plain-file secrets referenced by path, no telemetry, no auto-git, and no built-in worker sandbox in v0.0.1.
** Consequences
Configuration, auth, and runtime modules can be split against a stable, local-first baseline.
