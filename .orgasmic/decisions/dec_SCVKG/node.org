* dec_SCVKG Who owns the local daemon lifecycle when only the CLI is installed?    :cli:daemon:lifecycle:cross-platform:
:PROPERTIES:

:PARENT:        dec_XV9AK

** Context
The CLI binary already contains the daemon implementation via =orgasmic serve=,
but CLI-only users were still expected to keep a terminal or tmux session alive
to own that foreground process. That is acceptable for ad hoc developer recovery
inside this checkout, but it is not a product lifecycle model for macOS, Linux,
or Windows users who install only the CLI. The desktop app can supervise its own
runtime only if it bundles one, and remote daemon mode is owned by the remote
host, but local CLI-only mode needs the same logical behavior without the app.
** Decision
Make the CLI the local daemon lifecycle owner when no explicit
=ORGASMIC_DAEMON_URL= is set. Add a CLI lifecycle adapter layer with
=orgasmic daemon start|stop|restart|status= and have daemon-backed commands use
an auto-starting client constructor. =orgasmic serve= remains the foreground
debug primitive. The first adapter is a cross-platform detached-process adapter:
Unix detaches with =setsid= and Windows uses detached process creation flags;
the adapter boundary is where launchd, systemd user services, or Windows service
support can replace the spawn strategy without changing command semantics.
Explicit remote daemon targets remain externally owned and are not auto-started.

[2026-06-13 Sat] TASK-R3TWA promotes that adapter boundary to persistent
user-owned service adapters where the host supports them: macOS uses a user
LaunchAgent, Linux uses =systemd --user= when the user manager is available, and
Windows uses a least-privilege per-user Scheduled Task. Linux and unsupported
hosts keep an explicit detached-process fallback instead of reporting
persistence that is not installed.
** Consequences
Local CLI users can run normal commands such as =orgasmic status= without first
starting a daemon terminal. JSON commands keep stdout machine-readable; lifecycle
side effects stay silent or on stderr. =orgasmic restart= becomes a real local
process restart rather than only a daemon API drain marker. Future platform
service integrations should preserve the same logical commands and client
auto-start contract.

Daemon status now reports the selected adapter and whether local persistence is
installed/enabled. When =ORGASMIC_DAEMON_URL= is set, =start=, =stop=, and
=restart= refuse local ownership because that target belongs to the external
daemon owner.
