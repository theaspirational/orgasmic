** Context
Decision, architecture, and glossary records render from =.orgasmic/*.org= but were read-only in the UI, and the detail modal double-sourced its data: daemon summaries plus a second, client-side parse of the raw =.org=. That dual parser is a correctness hazard for editing, and client-side regeneration on save would be lossy — dropping comments, ordering, and unmodeled content. We want in-app editing of these records that lands surgically back in the files, generalizes across record kinds, and gives a reusable basis for future authored surfaces.
** Decision
The Rust core stays the single authority for parse and write; the UI never serializes =.org= text. It reads a generic structured node document (=GET /org/node=) and emits a closed set of structured edit operations (=POST /org/node/:id/edit=) — set/remove property, set/add/remove section, set title, set tags — applied through the byte-stable =OrgRewriter= under the existing role-based write path (advisory flock, atomic write, idempotency, recorded tx, watcher reindex). Optimistic concurrency uses a per-node content hash (=base_version=) with a 409 on drift. The UI is descriptor-driven: each editable view is a declarative =NodeDescriptor= binding fields (title, tags, =**= section, property) to editors (prose, text, chips) over one shared =NodeDocEditor=, so a new authored surface is a descriptor rather than bespoke code. tree-sitter-org is rejected for the substrate — it would reintroduce a second, divergent parser and lossy client-side regeneration — and is admissible only as an optional raw-source escape hatch beside the structured editor.
** Consequences
Decisions, architecture, and glossary are editable in-app with round-trip-stable, surgical writes: only touched byte spans change, sibling records stay byte-identical, and section edits preserve inter-node blank-line separators. Each save records a =graph.<kind>.edited= tx, so edits flow through the daemon audit path, and new editable record kinds cost only a descriptor. The editor is bound to the strict orgasmic Org profile, so constructs outside it (tables, footnotes) are not exposed as structured fields. The modal and list views now read server projections — client-side =.org= parsing is removed from the UI. Pairs with dec_QWZB2 (canonical file substrate) and dec_WH9PD (role-based write authority).
