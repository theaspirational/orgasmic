* dec_PC6T2 Native run evidence and retrospective execution are explicit opt-in operations
:PROPERTIES:
:DECIDED_AT: 2026-07-25
:ID: dec_PC6T2
:SOURCE: operator direction after 2026-07-23 run inventory incident
:END:

** Context
Legacy rmux/tmux screen-redraw capture grew the orgasmic project session history to 2.239 GiB. Harnesses such as Claude already keep richer native JSONL in vendor-owned paths. Retrospectives need selected tool calls, tool results, timing, context churn, and token signals across logically related runs, but automatic copying, conversion, or retrospective dispatch would recreate the storage problem and spend agent capacity without an operator decision.

** Decision
1. Orgasmic session JSONL stores only lifecycle authority and bounded normalized semantic events required for live operation, recovery, and compact history. Rendered TUI scrollback or redraw streams are never persisted. Harness-native transcripts remain immutable in the vendor save path.
2. Native transcript conversion is explicit and scoped. A user, manager, or already-running retrospective agent may materialize evidence for named runs only. The converter produces a bounded, versioned derived cache keyed by source digest and converter version. Derived-native events are diagnostics only: they never establish liveness, recovery, completion, dispatch closure, or task state.
3. Retrospective runs are explicit. A manager resolves selected run ids, task ids, or an ordered task sequence into an immutable scope manifest, then dispatches a read-only retrospector. It may write only derived evidence and its report. No retrospective runs or conversions occur on startup, run completion, task completion, release, or enumeration.
4. Future routines are user-configured invocations of the same manual retrospective path. A routine may choose a selector and schedule or trigger, but there is no shipped default routine and no second automatic execution path.

** Consequences
Operational run listing remains independent of large transcripts and derived evidence. Claude support can start as one small adapter over the existing native-transcript resolver and HarnessEventAdapter concepts; other harnesses add their own adapters without provider branches in central retrospective logic. Reports can audit several runs from backlog to done while evidence materialization stays lazy, idempotent, bounded, and attributable.
