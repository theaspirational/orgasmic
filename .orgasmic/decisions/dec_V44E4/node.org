* dec_V44E4 When does the agent see review comments, and what happens to them on regeneration?
:PROPERTIES:
:GLOSSARY_REFS: term_S45HH term_8CJ8G
:ID: dec_V44E4
:PARENT: dec_GPV4G
:END:

** Context
The plan-host reference loop is pull-based on both edges: the browser polls the plan bundle every ~3s and the agent polls a feedback tool when it chooses. Orgasmic has stronger primitives available — WebSocket push to the UI and event-triggered manager ticks off tx entries — so an auto-launched agent run per new comment was on the table. Regeneration fully rewrites the document, which detaches essentially every comment anchor; plan-host handles this with consumed timestamps and detached-thread flags.

** Decision
The review loop is *human-triggered*: nothing happens to the artifact until a member with edit rights presses Regenerate. The button is simultaneously the review gate and the spend gate. Auto-triggering a run per comment (tx event -> manager tick) is rejected for this feature — deliberately, not as a deferral.
- Comments are *version-scoped*. Regenerate closes version N: vN.mdx is archived together with its comments (marked consumed, browsable per version), and the fresh version starts with a clean comment surface. No anchor re-attachment across versions; the audit trail is the tx log plus the version archive.
- The regenerating agent receives the prior artifact, every current-version comment with author names and resolution state, and an optional extra prompt from the Regenerate dialog.
- Commenting is *locked* while a regeneration runs: the artifact enters a regenerating state pushed live over WebSocket, the comment box is disabled with a banner, and the per-artifact supervisor lease is the mutex. No comment can land unseen on a version that is being closed.
- The browser edge is WebSocket push (as the rest of the UI already is), not polling.
- Comment threads keep the reference implementation's two-axis state: open/resolved is people-facing and settable by any member; consumed is agent-facing and set only by regeneration.

** Consequences
- No buried feedback: every comment either reaches an agent run or is visibly archived with its version.
- The loop is slower than auto-trigger by design; teams batch discussion, then one press produces the next version.
- The per-artifact lease doubles as the concurrency control; two simultaneous regenerations of one artifact are impossible.
