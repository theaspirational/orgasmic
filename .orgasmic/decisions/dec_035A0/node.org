* dec_035A0 Should default workers attach a companion babysitter?
:PROPERTIES:
:ID: dec_035A0
:TAGS: babysitter,workers,dispatch,policy
:PARENT: dec_WC1PW
:END:

Context: companion babysitter attach was re-enabled experimentally after TASK-PGFPM made summary forwarding functional, but the operator direction on 2026-06-13 is to keep babysitter workers disabled rather than spend further effort making the companion path production-ready. The remaining gaps are not just template wiring: record_finding still needs task Evidence write authority, UI watcher-dot verification remains unproven in a live intervening run, and extra companion runtimes add operational capacity and authentication burden.

Decision: shipped worker templates must not declare :BABYSITTER_WORKER:. The babysitter-stall-detector template may remain as dormant shipped content, but no default worker should attach it automatically. Non-completed babysitter-related tasks should be cancelled rather than kept in the active backlog. The deleted task-state auto-spawn watcher from dec_WC1PW remains deleted; this decision also disables explicit-dispatch companion babysitter attach by default through template configuration.

Consequences: operators should not expect companion babysitter JSONL runs from default dispatches. Future babysitter work requires a new explicit decision that justifies the runtime/auth cost and defines the Evidence-writing and UI verification contract before re-adding :BABYSITTER_WORKER: to templates.
