* dec_GPV4G Should team-reviewable visual documents be a plan feature or one artifact noun over the graph?
:PROPERTIES:
:GLOSSARY_REFS: term_S45HH
:ID: dec_GPV4G
:END:

** Context
The team needs to review agent-drafted visual documents — implementation plans, architecture visualizations, decision-cluster maps — with comments pinned to exact spots (a sentence, a diagram node), and have an agent rework the document with that feedback. The Agent-Native visual-plan system (plan-host reference app) proves the loop end to end: structured MDX block documents, anchored comments with a rich anchor shape (PlanCommentAnchor: textQuote, targetNodeId, canvas coords), agent-side feedback tools, regeneration. The initial design ported it as a task-scoped "plan" feature; the review scenarios (generate from a decision page, from an architecture node, from a task) do not fit a task-only noun.

** Decision
One first-class noun: the *artifact* — an agent-generated MDX visual document about a recorded set of graph nodes. "A visual plan for TASK-X" is an artifact whose prompt asked for a plan; there is no separate plan feature. Two format bets lock the architecture:
- Keep the Agent-Native MDX block vocabulary *verbatim*: artifact.mdx is an opaque portable document in the full plan-host format. Org is the index + audit layer only, never the block format.
- Port the *full* plan-host block renderer (~22 block types including wireframe/canvas/prototype) into the embedded UI, rather than a curated subset. Chosen for zero format drift and wholesale reuse of the PlanCommentAnchor shape and the selection-to-pin comment-capture layer. Accepted cost: heavier UI bundle and more render dependencies.

** Consequences
- Single store, renderer, and comment system for every review scenario; artifacts remain format-compatible with plan-host exports and importable there.
- The renderer port is the heaviest single work item in the feature.
- Decisions/architecture/glossary/task nodes all become artifact subjects through the same three entry points (node, page, multi-select).
