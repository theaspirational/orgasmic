* dec_HBK6A Excise the architecture layer: decisions.org is the durable model
:PROPERTIES:
:ID: dec_HBK6A
:RELATES_TO: dec_ZG9B9
:END:

Context: Operator ruling [2026-07-28], confirmed as a GO [2026-08-03]: the
architecture layer (=arch_= nodes, =architecture.org=, the architector
worker/stage, the drift comparator, and the architecture CLI/UI surfaces) adds
redundant bureaucracy on top of =decisions.org= without pulling its weight.
TASK-XYYBT measured the excision rather than estimating it: the runtime ALREADY
treats =architecture.org= as optional (fresh scaffolds ship without it, the read
model guards on =exists()=, and a probe suite passed on a tree with no such
file), history parses without carve-outs except one 4-line dangling-edge lint
change, and the whole removal is ~-3.5k to -4.5k LOC across five independently
landable stages, calibrated against the Graph-page excision (dec_ZG9B9 /
TASK-M6146, which cost -2997/+43 in one round).

Decision: Remove the architecture layer in stages — stop-producing, then drift,
then read model/CLI/UI, then the node class and =architecture.org=, then shipped
doctrine. =decisions.org= is the single durable rationale model; CODE is the
authority on structure; TASKS carry the work graph. The drift comparator retires
with the layer: =// orgasmic:dec_=/=TASK-= markers remain advisory grep hints
with no enforcement. The still-live TARGET constraints of =arch_RN73Z= fold into
dec_PC6T2 / dec_WDR5K, and the two live tasks implementing it repoint their
drawers to =:MOTIVATED_BY:= those decisions.

History is NOT rewritten. tx records, =done.org= and prior decisions keep their
=arch_= references and stay resolvable via git, following the ID-migration
precedent. What changes is that the dangling-edge lint stops treating =arch_= as
a structured class. One ordering constraint is load-bearing: that lint carve-out
must be on main BEFORE the stage that deletes the file.

Supersedes: the four-layer graph doctrine (decisions -> architecture -> tasks ->
code) and the =// arch:= back-edge + drift-comparator doctrine recorded at
=decisions.org:231= and =:263=. Those decisions remain as history.

Consequences: orgasmic loses its only mechanical code<->model link. This is
accepted on the same judgment as the Graph page's unused curation loop — the
overlay never earned its keep. Glossary =:PRIMARY_LEAF:= pointers and the 9
arch-only marker files degrade to inert references, cleaned opportunistically.
The architecture UI tab, the =/architecture*= API family, the =orgasmic
architecture=/=architect= verbs, =WorkerKind::Architector= (retaining a
legacy-ledger PARSE fallback, since historical dispatch records carry the
string) and the shipped architector doctrine are removed. Existing user-project
=architecture.org= files are simply no longer read — orphaned, not migrated,
because the read model ignores unknown files.
=== Stage D amendment 2026-08-06 — no legacy-ledger parse fallback was needed

This decision's Consequences require "full =WorkerKind::Architector= removal WITH a legacy-ledger parse fallback", and TASK-RQ270's plan repeated it, calling =manager.rs:3805-3817= "THE ONE PLACE naive deletion breaks history". Stage D removed the variant with NO fallback, and that is correct. The requirement was wrong on both location and risk.

Traced independently by the stage-D implementer and confirmed by the reviewer:

- =dispatch_record_from_entry= (=crates/orgasmic-cli/src/manager.rs:6907=) reads =extra(entry, "KIND")= into a plain =String= at =:6913=, stored as =DispatchRecord.kind: String=. There is no enum conversion anywhere on the ledger-read path, so a persisted =:KIND: architector= row parses and closes exactly as before.
- The only =WorkerKind::from_str= callers are =crates/orgasmic-daemon/src/governance.rs:312,316,325,328=, reached from =config.rs= parsing the =dispatch:= governance map. An unparseable key is =tracing::warn!= + =continue= (=config.rs:178-188=) — a graceful skip, not a fatal.
- No =WorkerKind=-typed field is deserialized from persisted state; every one is in-memory.
- =manager.rs:3805-3817= is the open-dispatch collision hint in =build_dispatch_plan=. It has nothing to do with architector parsing.

Three tests carry the surviving contract and are green: =historical_architector_ledger_row_still_parses_and_closes=, =closes_architector_lifecycle_to_done=, =fix_round_final_fence_names_aborted_and_architector_closes=.
