* dec_DTJPD How should the manager surface be presented in the UI?    :ui-manager:
:PROPERTIES:

** Context
The user proposed adopting HAR's board-manager pattern: a permanent bottom popover on any page. Manager interaction needs to be available everywhere without consuming a sidebar route or hiding coordination behind a full-page context switch. A dedicated full Manager page adds a nav link the user rejected; a single-size sheet loses an immersive transcript view.
** Decision
Use a permanent bottom popover with two-tier expand: peek (~80px handle showing activity LED + last message line), workbench (~50% viewport, sidebar still visible), and focus (full-viewport takeover). Tick-manager and other deep manager actions live inside the expanded popover; there is no separate Manager nav link.
** Consequences
The manager becomes an always-available operator surface while preserving page context. Tick-manager and needs-you live inside the expanded surface, not on the peek bar. Mobile heights are peek 70px / workbench 80vh / focus 100vh with a 44px touch target on the handle; the implementation must handle drag resizing and transcript rendering in a persistent shell-level component.
