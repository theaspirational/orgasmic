** Context
Worker .org templates conflate four unrelated payloads: dispatch identity, transport binding, run governance, and two prompt slots. User overrides shadow whole files, so any fork silently freezes shipped prose (2026-07 incident: both rmux user overrides missed the dec_3M7M0 finalize contract for ten days). :MODELS: catalogs duplicate per template and rot as providers ship models; mode-contract prose duplicates across templates of the same transport. The 20-file catalog is a partially expanded kind x transport matrix.

** Decision
Remove the worker template concept entirely; no shipped/workers, no user/workers, no workers content family.
1. Transport registry is code: the SUPPORTED (mode, harness) matrix in orgasmic-drivers is the sole authority.
2. A dispatch addresses (kind, mode, harness) plus per-dispatch options. Kind selects the prompt-spec; babysitter is an ordinary kind.
3. Governance defaults (iterations, context budget, timeouts, applicable states, linked skills, babysitter attachment, sandbox) are hardcoded per kind; a sparse overlay in config.yaml overrides taste-driven values. Absent key = code default, so runtime updates land without config migration; startup warns on unrecognized keys; per-dispatch overrides win. Model and effort are NOT governance values (see 9).
4. Custom harnesses: the dispatch payload may carry raw argv; bearer-token authority is sufficient (equivalent power to dispatching an implementer with skip-permissions). The argv is recorded verbatim in the tx log for audit.
5. Prompts compile fully from prompt studio; the worker.persona and worker.operating_rules slots retire. The dispatch finalize contract (dec_3M7M0) is universal worker prose in the base_worker prompt-spec AND a daemon contract accepted from every TRANSPORT a run uses (see 6 for the universal run-shape scope). No prompt-parts/modes/ category; no driver-injected prompt prose of any kind (second amendment 2026-07-18: the EOT marker instruction is removed outright, not kept driver-injected as the first amendment said).
6. Completion (sixth amendment 2026-07-18 — operator-directed "build real finalize contract for all"; supersedes the fifth amendment's narrowing to dispatched-worker runs). Universal worker-declared termination: NO run shape infers success from protocol-end; EVERY run shape ends with an explicit terminal declaration to the daemon, and protocol-end without one is a failure/anomaly everywhere. Per-shape terminal verbs, all writing the same finalize tombstone (finalized_by_worker + reason): dispatched workers (implementer/reviewer/architector) call `orgasmic dispatch finalize`; the artifactor's `orgasmic artifact submit` is promoted to its finalizing terminal call (a successful submit IS the declaration; protocol-end without submit = failed); stage runs (/grill, /plan) gain a finalize terminal call (the CLI accepts finalize for these kinds and their spec + dispatch carry a last_path; protocol-end without it = failed); manager launches use `orgasmic manager release` (already worker-declared, TASK-VKP5T) as the terminal declaration (protocol-end without release = anomaly, not silent success). The per-run capability flag from TASK-P4MGK/TASK-8PXDP flips from "dispatch kinds only" to universal: every run advertises its required terminal-declaration kind at acquire time, and the daemon's Failed-on-protocol-end applies to all shapes uniformly. finalize stays idempotent and daemon-authoritative per run identity (tombstone: a stale-sweep 404 is success only when that same run already declared termination; a protocol-end-without-declaration release never yields a done tx). Stall and max-duration timeouts catch hangs. Failure diagnosis may consult harness-native session logs (last inner message) — never rendered TUI output. No marker fallback exists anywhere. The base_worker finalize instruction becomes genuinely universal prose (resolves TASK-FN18B). Seventh amendment 2026-07-18 (from TASK-S52X9 review): "every run shape" means every AGENT run shape. The `custom` bare terminal (an interactive shell with no agent) is NOT an agent run and is exempt from the terminal-declaration contract — it closes interactively; a bare-terminal `manager`-role launch must be classified so it never demands a declaration. Architect stage runs are included on the same footing as grill/plan (they get last_path + finalize).
7. TUI screen capture is removed: no render-stream or scrollback capture tasks in rmux/tmux drivers. Live viewing and typing remain on the PTY-attach WebSocket (/ws/tmux/:run_id); rmux web-share is unaffected. Session transcripts come from harness-native JSONL located by per-harness transcript finder adapters (deferred work). Custom-harness runs have no transcript until an adapter exists — accepted. (TASK-0SADP review surfaced that cursor-agent and hermes under tmux/rmux record NO session id; capture for such a TUI pair may not be removed until it resolves to a transcript or is documented as an accepted unsupported exception — a hard gate on TASK-AFE5Q.)
8. Prompt delivery: supported TUI harnesses receive the compiled prompt as an initial-prompt argv (claude, codex, cursor-agent all accept one); paste remains only as a fallback and for custom harnesses.
9. Orgasmic maintains ZERO model knowledge (third amendment 2026-07-18; fourth amendment same day sharpens sourcing). No model or effort identifier appears in orgasmic code or config. Structured catalogs come from protocol-level adapters ONLY — the runtime_options_catalog trait method parsing structured protocol responses (codex app-server RPC, hermes inventory; claude/cursor-agent ACP probed at implementation). Adapters NEVER parse CLI text output — that is the model-catalog equivalent of scrollback scraping. Harnesses without a protocol catalog degrade to free-text pickers; the manager may read harness CLIs as judgment, but no orgasmic machinery depends on parsing free-form output. A dispatch without an explicit model passes NO model flag — the harness's own config supplies its default. An explicit override passes through unvalidated; a nonexistent model is the harness's error to raise, surfaced to the manager. Per-kind model preference is manager judgment per dispatch, not configuration.
10. Cutover is hard, in one runtime release, with no alias table: old tx records render historical worker ids as plain strings; the daemon warns-and-ignores a leftover user/workers/ directory.

** Consequences
The whole-file staleness class disappears; users customize only via config.yaml and prompt-studio overrides. Fixes to the completion contract land once, in base_worker, and reach every kind and every mode at once. /content/workers endpoints, worker validation, and UI worker pickers are replaced by kind + transport selection. TUI screen capture and the EOT marker disappear entirely: completion never depends on parsing rendered output, and transcripts are the harness's own lossless logs rather than a lossy screen derivative. Sequencing constraint: transcript finder adapters must land BEFORE capture removal, or continuation runs and the artifactor lose their rmux/tmux session inputs in the gap. Runs that do the work but never call finalize report as failures; the daemon never auto-spawns a continuation — rescue is a manager decision, informed by a rescue-policy convention the manager reads on demand (pointer in the manager prompt-spec, body not inlined). Daemon recovery after a daemon restart stays mechanical and is distinct from rescue. Harness-native truth is the unifying principle: transcripts, model catalogs, and default model choice all belong to the harness — orgasmic stores none of them, so vendor model bumps require no orgasmic change at all (the 2026-07 gpt-5.6-sol override episode becomes structurally impossible). The glossary term worker driver (term_KH8TX) is unchanged; term_5SV2N shipped content needs its definition trimmed at implementation time; "transcript finder adapter" becomes a glossary term when implemented. Prompt-studio overrides retain file-granularity shadowing, accepted at spec/part scope. Implemented by TASK-P4MGK (universal finalize), TASK-0SADP (transcript finder adapters), TASK-AFE5Q (argv delivery + marker/capture removal), TASK-QPKCD (manager-authority rescue), TASK-AYXPB (governance rehoming), TASK-SZEWA (dispatch addressing cutover + live model discovery), TASK-DZ5NM (template removal).
