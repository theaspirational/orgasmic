** Context
Multi-dev same-repo is an assumed topology (dec_SSJVDa, trigger pulled forward): one daemon per clone, =.orgasmic/= synced through git — multi-master, where per-clone max+1 counters collide cross-clone and cross-file filings can merge silently. Candidates weighed: (1) plain TASK-NNN + merge-time repair; (2) git-identity-derived namespace (roster-less; a checked-in actor registry was separately rejected — no people-administration state in the repo); (3a) ULID-only; (3b) short-random-only. The node-class census showed the system already practices both poles: tx/runs are timestamp+random (machine-minted, never spoken — length costs nothing), goals are date+slug, and TASK-NNN + dec_NNN are the only at-risk sequential counters. Shape 1 was chosen first; the operator reversed to 3b (mixed scheme) the same day, then escalated to FULL MIGRATION the same evening — re-key everything, no mixed scheme, extending the grammar to the arch records (17 nodes, ~897 refs) and glossary terms (40 =term:slug= entries) so one identity convention covers every ID-bearing class. Inventory at decision time: 217 task headings (incl. subtasks), 70 decisions, 17 arch records, 40 terms, ~772 dec_ refs, 8 code files with task markers.
** Decision
(a) /All task, decision, arch, and glossary nodes mint short-random IDs/: =TASK-XXXXX=, =dec_XXXXX=, =arch_XXXXX=, =term_XXXXX= — 5 characters, Crockford base32 alphabet (0-9 A-Z minus I, L, O, U; uppercase), minted locally by ANY writer (daemon, CLI, manager, agent) with no coordination; class prefixes keep their existing punctuation. A minted ID MUST contain at least one letter — all-digit mints are re-rolled — so a minted ID can never be mistaken for a legacy sequential numeric. Subtask IDs derive from the parent (=<parent>.k=). (b) /FULL MIGRATION, no mixed scheme/ (operator escalation): every existing TASK-NNN (and =.k= subtask), dec_NNN, arch_NNN, and =term:slug= identity is re-keyed to a minted ID; the mapping lives in GIT, not in live state (operator: no migration scars — a migrated repo must be indistinguishable from a greenfield one): the migration lands as ONE commit tagged =id-migration=, whose diff is the complete old→new mapping; Live references are rewritten mechanically in the same change: org headings, drawers (incl. =DEPENDS_ON=/=PARENT_TASK=/=GLOSSARY_REFS=/=tracked_by=), prose, tx records (re-keying is not falsification — git holds the originals), the structured =orgasmic:task_*= code markers (9 lines), and =shipped/= instruction surfaces (live doctrine agents recall; 50 lines). FREE-TEXT CODE COMMENTS ARE EXEMPT (operator carve-out; 497 mention lines across 61 crates/ui files at decision time): comments are point-in-time annotations like git history — rewriting them buys no identity value and costs blame churn plus string-literal risk. Legacy IDs there (and in any immutable surface) stay resolvable forever via =git show id-migration | grep <old-id>= — documented as one line in conventions; NO resolver verb, NO =:RENAMED_FROM:= drawers, no legacy concept ships in the product. Test fixtures are synthetic org files with self-consistent IDs of their own — they never needed migration; TASK-GBT5W's audit keeps suites green. Git history and =archive/= essays intentionally keep old IDs; the same tagged commit bridges them. Legacy-leftover detection is the migration's ONE-TIME verification (TASK-YRK1V), not a standing product rule — though the standing malformed-ID lint (TASK-QRD3Y) catches any sequential-numeric identity generically (all-digit/wrong-length under the minted grammar), with zero legacy-specific knowledge. Max+1 allocation is abolished. (c) /The random ID is the stable key/ — no separate =:UID:= drawer line. It is high-entropy enough that fabricated or mistyped references dangle detectably, and it never changes except the freak duplicate (32^5 ≈ 33.5M space), which the post-pull lint catches and repairs by RE-MINTING one side and rewriting its in-repo references (TASK-QRD3Y); repair provenance is the repair commit itself — no provenance drawers, same git-is-history rule. (d) /Machine and narrative classes stand/: tx (=tx-<ts>-<rand>=) and runs (=run-<ts>-<rand>=) already carry decentralized collision-free IDs with useful chronology; goals keep date+slug; conventions and workers stay natural-keyed (they are file/path names, not opaque IDs). Glossary headings keep their human slug in the heading TITLE; only the identity moves to =term_XXXXX=.
** Consequences
Execution chain: TASK-GBT5W (mint-on-create everywhere + =orgasmic id mint= verb + code-readiness audit: find and fix every ID-shape assumption — validation regexes, numeric sorting, parsing, fixtures — so all four minted classes are accepted) → TASK-YRK1V (script-driven migration execution; the first minted-ID node in this repo) → TASK-QRD3Y (standing lint: duplicate IDs, malformed mints, legacy-pattern leftovers; re-mint repair). Manager doctrine: hand-filed nodes mint via the verb or any local randomness — never max+1-by-eye again. Extends dec_SSJVD; the registry rejection and reference-profile principle stand (the profile argument is resolved by accepting 3b's costs with open eyes, not by forgetting them).
