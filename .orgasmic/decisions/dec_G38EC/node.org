** Context
Orgasmic needs to know which projects it manages without introducing background auto-discovery or a central database. Auto-scan brings surprise and ambiguous ownership; a central database breaks plain Git collaboration as the primary coordination mechanism.
** Decision
Project add/init is explicit. Each repo opts in with repo-local =.orgasmic/= state, and the home board stores only project pointers. The orgasmic repo is registered as =orgasmic= on the board.
** Consequences
Aggregation is derived from the index rather than stored on the board. There is no auto-scan and no surprise project registration.
