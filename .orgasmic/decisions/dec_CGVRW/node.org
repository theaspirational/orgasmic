* dec_CGVRW Should the Board be a page, or should project context move into the sidebar?    :ui-ia:
:PROPERTIES:
:ID:            dec_CGVRW
:DECIDED_AT:    [2026-05-23 Sat 14:30]
:SOURCE:        archive/2026-05-23_ui-redesign/grill.md
:END:
** Context
The shipped AppShell still treats Board as a page, but the UI redesign needs project context to be ambient while real work surfaces stay prominent. The Board page was judged a placeholder; a bare CLI-only switcher worsens onboarding, and a separate Workspace page is redundant with a switcher footer.
** Decision
Replace the separate Board page with a project selector at the top of the sidebar. The footer carries "+ Add project" (small dialog) and "Manage projects" (large modal reusing the rich BoardView cards). Single-project users never see the modal.
** Consequences
Single-project users avoid a placeholder Board page while multi-project users still have management affordances; the sidebar can promote Decisions, Architecture, Tasks, and Glossary as primary work surfaces. Active project persists to =localStorage.orgasmic.active_project=; the add-project dialog accepts a path, uses =.orgasmic/project.org :ID:= when present, otherwise derives the project ID from the final path segment, and reads repository URL from =git config remote.origin.url=.
