** Context
After dec_A10RB–dec_GG6B9, orgasmic had several parallel user-facing install entry points: the macOS DMG installer (=install-macos-app.sh=), the source/contributor installer (=install.sh=), the README's per-platform curl commands, and the newly skill-bundled scaffold. That is several front doors for one product, and it leaves the user choosing an installer and a platform path before they understand the tool. The skill is already the daemon-free way to scaffold and run projects (dec_RX4DF), and a capable agent can orchestrate the existing, tested install scripts better than a static doc — picking the path, checking prerequisites, and troubleshooting.
** Decision
Collapse onto a single install surface: installing the =/orgasmic= skill is the only thing a user does directly, and everything else is a skill subcommand. Add an =install= subcommand whose body is LLM natural-language guidance that makes the agent orgasmic's installer — it decides what to set up (CLI + local daemon / macOS app / remote Linux daemon), checks prerequisites (asking before touching system toolchains), runs the canonical scripts (=install.sh= / =install-macos-app.sh=) as the source of truth for mechanics rather than reimplementing them, troubleshoots failures, and verifies via =orgasmic status= / =doctor=. =install= and =init= are the skill's bootstrap-from-nothing exceptions (no existing =.orgasmic/= or runtime required). The README "Installation" section is reframed skill-first: two steps (install the skill via the copy-paste prompt, then =/orgasmic install=), with the per-platform mechanics demoted to reference for what =/orgasmic install= runs. The underlying scripts and the contributor/fork path are retained — they are what the subcommand drives — but are no longer presented as independent front doors.
** Consequences
"How do I install orgasmic?" has exactly one answer: install the skill, then =/orgasmic install=. Onboarding is uniform across platforms and adapts via the agent instead of branching docs. The scripts remain the tested mechanics layer (single source of truth), so the skill guidance stays thin and points at them; drift risk is limited to script flags referenced in prose. Re-running =/orgasmic install= (or =orgasmic update=) is the upgrade path. Pairs with dec_GG6B9 (installer + agent both symlink the skill into =~/.agents/skills=) and dec_RX4DF (bundled scaffold). The README "Getting Started" is reordered to the skill-first flow (start a project with =/orgasmic init=, then optional =/orgasmic install=, then the app/CLI). The non-agent install paths are removed as redundant: the README no longer carries hand-run install recipes (the =curl | bash= one-liners, manual DMG drag, =xattr= quarantine fix, =systemd= unit, SSH/profile blocks) — only the skill-first surface plus a short "what =/orgasmic install= provisions" reference remain. The proposed =scripts/scaffold.sh= non-agent curl path (dec_RX4DF) is declined for the same reason. =scripts/install.sh= and =scripts/install-macos-app.sh= stay on disk but only as the mechanics =/orgasmic install= drives, not as advertised entry points; no user-facing install path exists outside the skill.
