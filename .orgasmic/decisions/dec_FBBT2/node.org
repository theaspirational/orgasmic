* dec_FBBT2 How should one UI surface host both manager and worker runs?    :ui-manager:run-dock:
:PROPERTIES:
:ID:            dec_FBBT2
:GLOSSARY_REFS: term_N5SJT term_YC32J
:DECIDED_AT:    [2026-06-05 Fri 00:30]
:SOURCE:        archive/2026-06-04-run-recovery-run-dock-grill.md
:PARENT:        dec_DTJPD
:END:
** Context
The bottom surface (=ManagerPopover= + =ManagerWorkbench=) was manager-only: it fetched =/manager/state=, showed manager runs in a single picker, and owned peek/workbench/focus sizing for that one role. Recovery (dec_GDEXE) now opens both manager and worker runs, and runs are discoverable from a Running Agents list, task badges, and run history — none of which a manager-only popover can host. We need one live transcript/terminal/composer surface that serves a manager run and an arbitrary worker run side by side, without auto-opening a tab for every active worker (which would turn the dock into noise), and that survives reload.
** Decision
Replace =ManagerPopover= outright with a =RunDock= app-shell surface — no compatibility wrapper. The dock owns peek/workbench/focus sizing, tab selection, and persisted open-tab state, and renders Manager as one special tab while worker runs are peer tabs that reuse the same tmux/chat/composer renderers (=ManagerTmuxPane=, =ManagerChatTranscript=, =ManagerComposer=).
- State lives in a single =RunDockProvider= context so badges and recovery results anywhere in the app open a run via =openRun=. Open tabs persist in localStorage keyed by run id and are validated against backend run/recovery state on load (unknown ids are dropped). One browser holds at most one tab per run (dedupe by run id).
- A =Running Agents= menu groups =Running= (live supervisor runs), =Recoverable= (interrupted + reattachable recovered runs, using the same backend =recovery_actions= resolver data the notification bell consumes), and =Recent= (defaults to the current project; global toggle/search deferred). Selecting a running agent attaches and opens a peek window; selecting a recoverable one runs its first =recovery_action= through =POST /runs/:id/recover= and opens the returned target.
- Worker tabs open only through explicit user action or recovery — never automatically for every active worker. Minimizing a peek window turns it into a dock tab. Closing a tab detaches the UI only; it never stops or releases the run (stop/release stays a separate explicit action). Recovery results route by =target=: manager -> Manager tab, worker -> a worker tab/peek.
- Staged recovery prompt drafts returned by =/runs/:id/recover= appear in the shared composer pre-filled and require an explicit user send; composer copy is provider-neutral (=Send to agent=), and every send goes through the TASK-T6AV7 shared recording path (=/runs/:id/input= for tmux/native, recorded as a =composer_send= lifecycle event). Tab labels prioritize readable role/task/provider/transport (e.g. =Manager · Claude tmux=, =TASK-NN3HB · Codex=); the raw run id is secondary (tooltip).
- Task list/kanban rows and the task modal carry running/recoverable agent badges (visually separated). One relevant run opens immediately; multiple relevant runs open a small grouped menu. The same peek opens from task rows/cards and the task modal.
** Consequences
One surface serves manager and worker runs with identical renderers and one composer recording path, so recovery (dec_GDEXE), Running Agents, task badges, and run history all funnel into the dock instead of bespoke viewers. The dock is an app-shell surface, not a card; cards remain reserved for genuinely repeated items. Reload restores exactly the tabs whose runs still exist. Pairs with dec_GDEXE (explicit recovery), arch_MK2Q2 (manager UI surface), and dec_DTJPD/dec_HY3E0/dec_JZDKT.
