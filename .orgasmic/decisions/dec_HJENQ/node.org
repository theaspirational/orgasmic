* dec_HJENQ Which node properties should survive, and what is the canonical edge vocabulary?    :schema:architecture:design:adr:
:PROPERTIES:
:ID:            dec_HJENQ
:DECIDED_AT:    [2026-06-12 Fri]
:SOURCE:        TASK-55DH1 implementer session 2026-06-12
:END:
** Context
A census of 396 property drawers across all org node classes (2026-06-12) surfaced four
redundancy classes: (1) state is carried three times per task heading — heading keyword
(=BACKLOG=/=IN_PROGRESS=/etc.), =:STATE:= property (221 occurrences, written in lockstep by
the manager lifecycle transition path), and file membership (per dec_QQYXM, the pending
canonical copy); (2) several properties duplicate derivable information — =:LAST_UPDATED:=
(221) duplicates git timestamp, =:KIND:= (251 on tasks) is not parsed by TaskHeading in
schema.rs and is largely inferable from =:WORKER:= or pipeline context, =:DECIDED_AT:= (127)
could be derived from git when not semantically distinct; (3) empty placeholder properties
ship on nearly every heading — =:BLOCKED_BY:= (211 total, approximately 50 non-empty),
=:PARENT_TASK:= (167, mostly empty on non-subtasks), =:FIX_SUBTASK:= (mostly blank); (4)
dispatch params are repeated verbatim on all ~220 task headings even when identical to
project defaults — =:WORKER:=/=:WRITE_SCOPE:=/=:READ_SCOPE:=/=:TEST_CMD:=. In addition,
edge-shaped properties (=:DEPENDS_ON:=, =:BLOCKED_BY:=, =:RELATES_TO:=, =:GLOSSARY_REFS:=,
=:IMPLEMENTS:=, =:PRODUCES:=, =:MOTIVATED_BY:=) lack a unified vocabulary, canonical
directions, or an explicit policy on where inverses live.
** Decision
Governing constraints: org files stay human-readable and greppable (dec_X72P5 readability
principle); every structural write goes through the daemon single writer loop (dec_ZQJPA);
the file-per-state topology is the canonical state surface (dec_QQYXM) once TASK-2C3WZ
lands.

Amendment [2026-06-12] — node-identity verdict (TASK-55DH1 amendment, resolved post-close;
the amendment landed in the closing commit after the worker round, so the original ADR text
predates it): =:ID:= is the canonical identity for every node class — required by schema,
wins for all indexing. The ID token echoed in the heading title is a display copy kept for
human readability and grep (same status as the heading keyword in the state×3 verdict).
Both survive. Agreement is enforced by a read-time equality lint riding the
phantom-heading/parse-errors channel (task_HC7PW precedent), not by parse failure or atomic
rewrites: =TaskHeading::from_heading= and the decision/arch equivalents keep their tolerant
=strip_prefix= fallback (schema.rs:288/357/556) so a mismatched heading still parses and
indexes under =:ID:= while the lint flags the drift for repair (dec_MK7AH
detect-and-repair). Glossary terms are exempt — their headings carry the human slug, not
the =term_XXXXX= token (dec_X72P5d). Required tests: =TaskHeading::from_heading= mismatch
fallback, materialized-index task-shape detection under mismatch, phantom-heading lint
equality cases. Implementation: TASK-KY80Q.

*** State×3 verdict
Drop =:STATE:= from task headings. After dec_QQYXM lands, file membership is the canonical
state surface; the heading keyword survives as the sole display copy (org-mode compatibility,
human readability in editors). The daemon atomically rewrites the keyword and moves the file
on every lifecycle transition; keyword and file may never disagree. =:STATE:= as an explicit
property is a third redundant copy that drifts without adding information. Current state:
no schema code reads =:STATE:= directly — LifecycleStage is parsed from the heading TODO
keyword (schema.rs:262); the property is only written in the manager lifecycle transition
path and must be removed there.

*** Per-key verdicts — Task nodes
- =:ID:= — KEEP. Unique node identity; required by schema.
- =:STATE:= — DROP. Redundant third copy once dec_QQYXM file-per-state is live; heading
  keyword is the surviving display copy; file membership is canonical.
- =:KIND:= — DROP. Not parsed in =TaskHeading= (schema.rs:220–245 lists no kind field);
  "largely inferable from ID grammar + file" per census. Worker assignment lives on
  =:WORKER:=. No schema consumer; drop.
- =:PRIORITY:= — KEEP. Explicit operator signal; not derivable from any other source.
- =:WORKER:= — KEEP (optional override). Dispatch param; absent means use project pipeline
  default (dec_DEH2T). Blank values must be omitted on new headings; stripped in migration.
- =:PROVIDER:=, =:MODEL:=, =:REASONING_EFFORT:= — KEEP (optional override). Dispatch params;
  same rule: blank/default-identical values omitted.
- =:WRITE_SCOPE:=, =:READ_SCOPE:= — KEEP (optional override). Blank = no restriction or
  inherits project default; stripped when empty.
- =:TEST_CMD:= — KEEP (optional override). Overrides project config default; stripped when
  empty or identical to the config default.
- =:SANDBOX_PERMISSIONS:= — KEEP (optional override). Stripped when empty.
- =:LAST_UPDATED:= — DROP. Duplicates git; =git log -1 --format=%as -- <file>= is
  authoritative. No code path reads or writes this after migration.
- =:PARENT_TASK:= — DERIVE then DROP. Already derivable from the =.k= subtask ID grammar
  (=TASK-XXXXX.k= → parent is =TASK-XXXXX=); schema.rs:267–285 validates rather than trusts
  the stored value. Blank values on non-subtasks are dead weight; populated values on
  subtasks duplicate the grammar. Drop the explicit property; derive from ID at read time.
- =:BLOCKED_BY:= — EDGE then DROP as property. =BLOCKED_BY(A,B)= and =DEPENDS_ON(A,B)= are
  the same directed edge: A cannot proceed without B. =:DEPENDS_ON:= is the canonical form;
  non-empty =:BLOCKED_BY:= values migrate to =:DEPENDS_ON:= before the property is dropped.
  The "what tasks does X block" query becomes the index-derived inverse of DEPENDS_ON.
- =:FIX_SUBTASK:= — DROP. Mostly blank; any populated value points to a subtask already
  identified via the =.k= grammar. No schema consumer; drop.
- =:DEPENDS_ON:= — EDGE. Keep as the canonical dependency edge (see edge vocabulary below).
- =:IMPLEMENTS:= — EDGE. Keep as the canonical task→arch linking edge.
- =:PRODUCES:= — EDGE. Keep as the canonical task→artifact linking edge.

*** Per-key verdicts — Decision nodes
- =:ID:= — KEEP. Required identity.
- =:GLOSSARY_REFS:= — EDGE. Keep; canonical direction: decision → glossary term. Inverse
  ("term referenced by") is index-derived.
- =:DECIDED_AT:= — KEEP. Semantic timestamp: when the decision was made, not when the commit
  landed. Retains meaning when replayed or backfilled; distinct from the git date.
- =:SOURCE:= — KEEP. Provenance note; not derivable from git log in the general case.

*** Per-key verdicts — Architecture nodes
- =:ID:= — KEEP. Required identity.
- =:KIND:= — KEEP. Component type (crate, module, service, store, etc.); semantic, not
  derivable from node ID or position. This is distinct from the dropped task =:KIND:=.
- =:SEMANTIC_HASH:= — KEEP. Change-detection signal for agent re-evaluation triggers.
- =:MOTIVATED_BY:= — EDGE. Keep; canonical direction: arch node → decision(s). Inverse
  ("decision motivates arch nodes") is index-derived.
- =:GLOSSARY_REFS:= — EDGE. Same policy as decision nodes: arch → term; inverse index-derived.
- =:INTERFACE:=, =:CONSTRAINTS:= — KEEP. Explicit specs; not derivable.
- =:COMPOSES:= — EDGE. Keep; canonical direction: arch node → composed child nodes. Inverse
  ("composed_by") is index-derived.
- =:DEPENDS_ON:= — EDGE. Keep; same vocabulary as task =:DEPENDS_ON:= (arch → arch/artifact).
- =:SOURCE_PATHS:= — KEEP. File path list; not a node ID reference.
- =:TESTS:= — KEEP. Test command list.
- =:DECIDED_AT:= — KEEP. Same semantic-timestamp policy as decision nodes.
- Arch edge properties (=:READS:=, =:WRITES:=, =:EXPOSES_REST:=, =:EXPOSES_WS:=,
  =:SUBSCRIBES_TO:=, =:SPAWNS:=, =:CALLS:=) — KEEP. Already typed as =ArchEdgeKind= in
  schema.rs:404–443.

*** Per-key verdicts — Glossary terms
- =:ID:= — KEEP. Required identity.
- =:CANONICAL:=, =:AVOID:= — KEEP. Term surface spelling policy; not derivable.
- =:DEFINITION:= — KEEP. Term definition.
- =:RELATES_TO:= — EDGE. Keep; cross-link between terms. Treated as symmetric (A relates_to B
  implies B relates_to A); daemon stores one direction as authored, derives the inverse.
- =:DECIDED_AT:= — KEEP. When the term was formally defined.

*** Edge vocabulary (unified)
One canonical direction per edge name; inverse is always index-derived, never stored as a
property on any node.

#+begin_example
DEPENDS_ON    from: task | arch        to: task | arch
              "A cannot proceed without B."
              Inverse (index): blocked_by / what depends on me

IMPLEMENTS    from: task              to: arch node
              "This task implements this architecture node."
              Inverse (index): implemented_by

PRODUCES      from: task              to: artifact | arch node
              "Successful completion yields this artifact."
              Inverse (index): produced_by

MOTIVATED_BY  from: arch node         to: decision(s)
              "This component exists to satisfy this decision."
              Inverse (index): motivates

GLOSSARY_REFS from: task | dec | arch  to: glossary term
              "This node uses or references this term."
              Inverse (index): referenced_by

RELATES_TO    from: glossary term      to: glossary term
              Undirected cross-reference; symmetric.
              Inverse (index): same (symmetric)

COMPOSES      from: arch node          to: arch node (child)
              "This component contains this sub-component."
              Inverse (index): composed_by
#+end_example

*** Migration plan
All steps land as ONE tagged commit using the dec_X72P5 =id-migration= method. The commit
tag is =property-migration=.

Step 1 — Drop =:STATE:= from all task headings (~221 edits; script-driven find-per-file).
Requires manager lifecycle write path to stop emitting the property. Schema impact: none
(not read by schema.rs today).

Step 2 — Drop =:KIND:= from all task headings (~251 edits; script-driven). Schema impact:
none (=TaskHeading= has no kind field).

Step 3 — Drop =:LAST_UPDATED:= from all node types that carry it (~221+ edits;
script-driven). Schema impact: remove =last_updated= from =TaskSummary= (index.rs:64),
=TaskHeading= (schema.rs:240), and all write paths.

Step 4 — Drop =:PARENT_TASK:= from all headings (~167 edits; script-driven). Schema impact:
remove explicit property read at schema.rs:267–268; keep the ID-grammar validation logic.

Step 5 — Migrate non-empty =:BLOCKED_BY:= → =:DEPENDS_ON:=, then drop the property (~211
headings, ~50 non-empty; script identifies non-empty values, merges into =:DEPENDS_ON:=,
strips =:BLOCKED_BY:=). Schema impact: remove =blocked_by= from =TaskHeading= (schema.rs:237)
and =TaskSummary= (index.rs:54); update daemon query API to return blocking tasks as the
inverse of DEPENDS_ON edges in the graph index.

Step 6 — Drop =:FIX_SUBTASK:= (handful of headings; script-driven). No schema impact.

Step 7 — Strip blank/default dispatch params (=:WORKER:=, =:WRITE_SCOPE:=, =:READ_SCOPE:=,
=:TEST_CMD:=, =:PROVIDER:=, =:MODEL:=, =:REASONING_EFFORT:=, =:SANDBOX_PERMISSIONS:=) where
empty. Script emits the list of headings with empty values; batch strip.

Verification: =cargo test -p orgasmic-core --test fixtures= (parser smoke); daemon reload +
=orgasmic task list= (index round-trip); UI board renders correct state counts. Detection
lints TASK-HC7PW and TASK-QRD3Y flag any leftover malformed properties post-migration.
** Consequences
Dead schema weight removed: =:STATE:=, =:KIND:= (tasks), =:LAST_UPDATED:=, =:PARENT_TASK:=,
=:BLOCKED_BY:=, =:FIX_SUBTASK:= are dropped or derived; dispatch params stripped when blank.
New task headings carry 5–7 properties instead of 14+.

Edge vocabulary is unified: =:DEPENDS_ON:= is the single dependency axis; =:BLOCKED_BY:= is
retired; the daemon derives all inverses through the graph index. No stored inverse properties.

Schema.rs consumers updated: =TaskHeading= loses =parent_task= (derive from ID), =blocked_by=,
=last_updated=; =TaskSummary= in index.rs loses =blocked_by= and =last_updated=. The manager
lifecycle write path stops emitting =:STATE:=, =:KIND:=, and =:LAST_UPDATED:=.

dec_QQYXM alignment: file membership is canonical; heading keyword is the surviving display
copy; =:STATE:= property is dropped on migration and not written on new headings thereafter.
dec_ZQJPA alignment: all property mutations go through the daemon write surface after the
verb set is complete (TASK-NP5H6); the migration itself is a one-time script run under human
supervision and lands as a single tagged commit.
dec_X72P5 alignment: migration lands as ONE tagged commit; the migrated repo reads as
greenfield (no =:RENAMED_FROM:= drawers, no legacy-detection standing rules beyond the
existing malformed-ID lint TASK-QRD3Y).
Update (per [[dec_2GQ7Q]]): =:PARENT:= joins the canonical edge vocabulary as the single-value, same-class hierarchy edge for arbitrary-depth decision nesting — the child stores the pointer; the inverse =children=, =depth=, and the =1.1.1= path are index-derived (no new stored fields beyond =:PARENT:=).
