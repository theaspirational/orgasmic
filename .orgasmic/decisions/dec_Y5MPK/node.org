* dec_Y5MPK Transcript ownership: orgasmic records operations, the harness owns the conversation, the operator owns retention
:PROPERTIES:
:ID: dec_Y5MPK
:RELATES_TO: dec_WDR5K
:SOURCE: operator direction 2026-07-25
:END:

** Context
dec_WDR5K item 7 settled where transcripts come from: harness-native JSONL, located by per-harness transcript finder adapters, with TUI screen capture removed. It did not settle who owns those files over time, and the gap became load-bearing once retro (TASK-VBSG2) was designed on top of them.

Measured on one real board, 2026-07-25: orgasmic's own session JSONL held 2.239 GiB across 198 runs, of which rendered TUI capture was 59% (rmux 1.275 GB over 60 runs, ~21 MB per run) while the structured protocol transports cost ~1.5 MB per run across more runs. Independently, the vendor stores already held the same conversations: 1267 files under `~/.codex/sessions`, 908 under `~/.cursor`, 447 under `~/.claude/projects`.

The decisive property is not size, it is resumption. Orgasmic can replay its own record but cannot hand it back to a harness to continue. `claude --resume <id> --fork-session` works only because the vendor file exists. A transcript orgasmic saved itself can never be resumed, so native capture cannot substitute for the vendor file even in principle.

** Decision
Two records with two owners, and orgasmic owns only one of them.

1. Orgasmic's session JSONL is operational truth: lifecycle, tool calls, terminal state — what the daemon observed and what recovery and classification consume. It is orgasmic-owned and must stay bounded.
2. Harness-native JSONL is semantic truth: the conversation as the harness recorded it, including reasoning the protocol stream never exposes. It is vendor-owned, immutable to orgasmic, and is the sole source for retro and for resumption.
3. Correlation is minted, never discovered. Orgasmic pins the native session id before launch and records it in a `NativeRuntime` lifecycle event, so locating the vendor file is deterministic rather than a timestamp or uniqueness heuristic. `modes/tmux.rs` already does this; every transport must.
4. Orgasmic never suppresses vendor persistence. A transport that disables the harness's own session recording is a defect, not a configuration choice.
5. Retention of vendor transcripts belongs to the operator. Orgasmic never prunes, moves, rewrites, or expires a vendor file — not on upgrade, not by policy, not by age. Its obligation is visibility: report per-harness counts, total size, and age distribution through `doctor` so the operator can act with full information.
6. Worker sessions must be distinguishable from operator sessions, and the distinction is minted rather than inferred — the same rule as item 3, applied to attribution instead of location. A vendor transcript is orgasmic-attributed exactly when its native session id appears in a `NativeRuntime` lifecycle record in orgasmic's own session JSONL. Nothing else counts: not the encoded-cwd project directory (a worker without a worktree writes under the repo root like the operator does, and each harness encodes cwd differently or not at all), not file age, not launch-time proximity. Those are the discovery heuristics item 3 exists to forbid.

Owner: `doctor` owns the observable surface. The per-harness report item 5 promises splits into orgasmic-attributed and unattributed, so the operator can see how much of the store their own dispatches produced before deciding what to remove. The operator still owns the deletion — item 5 is unchanged, and a split is a reporting obligation, not a licence to prune.

Answering the question directly: a matching `NativeRuntime` record is the *definition* of the distinction, and it does not on its own satisfy it. The record makes the split computable; `doctor` is what makes it observable. Both are required.

Consequence, and the reason this is worth stating rather than assuming: the split is only computable for a harness whose session id orgasmic minted. Today that is claude alone. Codex, cursor-agent and hermes all learn their session id from a protocol response after launch, so their transcripts cannot be attributed at all, and their share of the store is unattributable by construction rather than by oversight. That is now a named gap with filed follow-ups, not an accident.

** Consequences
Vendor stores grow without bound and orgasmic will not manage that growth; the operator does, with orgasmic supplying the numbers. This is the honest reading of "vendor-owned and immutable" from the retro contract — a runtime that may delete the source a later retro run needs does not own it in any meaningful sense, and a runtime that silently prunes vendor state is indistinguishable from data loss.

The rule makes existing defects legible rather than debatable. The acp-stdio claude adapter passes `--no-session-persistence` and emits no `NativeRuntime`, so its runs have no semantic record at all and cannot be resumed or retro-ed (TASK-VB9DQ). Rendered TUI capture is now clearly the worst option available — lossy, largest, and a strictly inferior duplicate of a vendor file that already exists — which sharpens rather than changes dec_WDR5K item 7's removal (TASK-AFE5Q).

Externally this matches how comparable tools divide the responsibility: t3code requires the operator to authenticate each vendor CLI (`claude auth login`, `codex login`, `cursor-agent login`) and orchestrates the authenticated tool rather than owning its identity or state.

Bounded derived evidence is unaffected: TASK-VBSG2 may convert vendor JSONL into a versioned, size-capped, derived-only cache under `.orgasmic/tmp/retro/evidence`, because that cache is orgasmic-owned and regenerable. Deriving from the vendor file is always permitted; mutating or deleting it never is.
