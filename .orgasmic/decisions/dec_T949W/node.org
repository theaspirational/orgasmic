* dec_T949W What is a workflow: structured lanes the daemon enforces, or prose guidance the manager follows?

** Context
The loop and the tiering are smeared across three places: =config.org='s =:PIPELINE:=, worker =DEFAULT_MODEL=/=DEFAULT_EFFORT=, and ad-hoc per-dispatch overrides. The operator wants adaptive routing by task complexity — a trivial fix implemented by the manager itself on a cheap tier, ordinary work dispatched and manager-reviewed, risky work through grill/plan/implement plus an independent reviewer — without adding moving parts. A structured design (named lanes with per-stage worker+model+effort, a rubric, per-task =:LANE:= stamping, daemon validation) was drafted and rejected as too much edit surface for v1. A prose workflow cannot be the daemon's source for model/effort, so stripping worker defaults (also considered) is unworkable.
** Decision
Workflows v1 are prose-only Org files: =* WORKFLOW <id>= heading plus a free-form guidance body; the daemon parses nothing inside them. Resolution is three-tier per the dec_GRDFB loader rule: =.orgasmic/workflows/<name>.org= (project) → =$ORGASMIC_HOME/user/workflows/<name>.org= (global) → =shipped/workflows/<name>.org=. There is exactly one well-known name, =default=; customization means shadowing that file, not repointing — no selection state exists anywhere. Alternate named workflows are invoked conversationally and session-scoped; nothing is written. Workers keep =DEFAULT_MODEL=/=DEFAULT_EFFORT= as the machine-readable fallback; the workflow prose tells the manager when to send the existing dispatch model/effort overrides. Ship exactly =shipped/workflows/default.org=: complexity guidance (trivial → manager implements directly, cheap tier, keeping the manager-implementer discipline of CLI-only state writes, markers, and reconcile-at-pauses; ordinary → dispatch an implementer, manager reviews the diff; risky → grill/plan/implement + independent reviewer on a premium tier; unsure → ask the user with a suggestion). =orgasmic entry= prints the resolved body. Detached operation is not a workflow — it lives in the stub protocol (dec_YTJ0G).
** Consequences
Workflows v1 needs zero daemon changes: it is a shipped file, a loader path, and an =orgasmic entry= section. The manager-implementer convention retires into =default.org=, update-tracked. Trade-off accepted knowingly: which loop a task actually ran is recorded only in tx/worklogs, not validated or stamped; if reproducibility pressure grows, the rejected lanes+rubric design is the known upgrade path. Rejected alternatives for the record: lanes + rubric with =:LANE:= stamping; machine-readable =:PIPELINE:= in workflow properties; per-task or config-pointer binding.
