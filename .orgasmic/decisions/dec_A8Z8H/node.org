** Context
Orgasmic must decide whether collaboration runs through its own multi-user service or through existing Git workflows. A shared daemon brings real-time team state but multi-tenant identity and conflict policy dominate; a cloud relay eases cross-machine views but violates the local-first scope.
** Decision
Collaboration is per-developer and Git-native. Each developer runs their own instance, commits project =.orgasmic/= state, and resolves conflicts as ordinary Git conflicts. Orgasmic never invokes git automatically.
** Consequences
There is no multi-tenant identity model and no team manager in v0.0.1. Pull, commit, push, and merge-conflict resolution are operator responsibilities.
