** Context
An external architecture critique (rounds 1-3 archived) pressed three claims: incremental human-readable IDs (TASK-NNN, dec_NNN) are a centralized-sequencer anti-pattern versus UUIDs; optimistic concurrency burns LLM tokens on 409 retries versus pessimistic graph locks; and the CLI-absent org-write fallback is fail-open. The same day, two parallel manager sessions both allocated TASK-W43NY by max+1-by-eye — a live instance of the collision the critique predicted, resolved by hand-renumbering the uncommitted duplicate to TASK-HC7PW.
** Decision
(a) Identity: IDs stay human-readable and sequential; allocation authority is the daemon (the existing write authority, dec_WH9PD), not decentralized generation. UUIDs/ULIDs are rejected — readability of diffs, grep, prose cross-references, and operator recovery over plain files is a core product property, and the collision class is closed by sequenced allocation (TASK-GBT5W), not by giving up readable keys. Multi-master merge of task graphs is out of scope; the revisit trigger is the day two daemons must merge graphs — the recorded escalation for that day is a stable surrogate key (ULID) in =:ID:= with TASK-NNN demoted to a display alias, NOT draft-ID reconciliation (round-4 critique, conceded: merging draft-IDs means rewriting every prose cross-reference at integration; a stable key never needs rewriting). Until that trigger fires, daemon-sequenced readable IDs stand — the bottleneck objection fails here because every org write already serializes through the single writer loop, so allocation adds no new synchronization point. TRIGGER PULLED FORWARD [2026-06-11, operator direction]: parallel devs on one repo — disjoint modules, git-synced =.orgasmic/=, one daemon per clone — is an assumed topology, not a hypothetical; per-clone sequencing cannot prevent cross-clone ID collisions (worst case merges silently when filings land in different files). TASK-T2FSY designs the scheme and gates TASK-GBT5W's final shape. ULID stable key in the property drawer is common ground; for the human surface the operator rejected a checked-in actor registry (no people-administration state in the repo), leaving three candidate surfaces: plain TASK-NNN with merge-time mechanical repair (the dec_MK7AH detect-and-reconcile posture), a roster-less namespace derived from git identity, or a single collision-free ID with no sequential ID at all (full ULID, or a short random =TASK-7QK4=-style ID that keeps the decentralized wins at a fraction of the usability cost). The decision is per node class under one principle — ID entropy follows the class's reference profile: tasks and dec_NNN share the conversational profile and get the same surface; tx/runs (timestamp+random) and goals (date+slug) already practice the collision-free pole and stand; repair machinery is built once, generic over classes. (b) Concurrency layering: pessimistic locking happens BEFORE token spend at the orchestration layer — supervisor (task, kind) leases and WRITE_SCOPE overlap rejection at dispatch; OCC (base_version) survives only on fine-grained node edits where the writer is a human and a conflict costs a re-click, not a regeneration. Residual exposure (round-4 critique §4, acknowledged): cross-scope graph mutations — parent-epic flips, cross-links into other tasks — exceed any worker's WRITE_SCOPE; doctrine routes them to the coordinator tier (workers never write org state), so the conflict surface is manager-vs-manager, where a collision costs a re-read under dec_MK7AH's ownership lanes, not a worker token budget. (c) REVERSED [2026-06-12, operator] — see dec_ZQJPA: agents edit org state only through the daemon; the CLI-absent hand-edit fallback and daemon-free bootstrap editing are retired (phased per surface as CLI verbs land). The detection lints stay as the safety net for the human lane.
