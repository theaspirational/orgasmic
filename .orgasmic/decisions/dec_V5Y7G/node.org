** Context
impeccable expects a DESIGN.md capturing the visual system (tokens, typography, spacing, components, motion). orgasmic records it natively. A prior version of this record carried the whole design-system body inline, which forced DESIGN.md and other pointers to cite a project-specific decision id (=dec_V5Y7G=). Decision ids are ordinal and per-project, so they are a fragile anchor for a stable design surface — the same reasoning that put the product baseline in project.org (dec_F2WRW).
** Decision
Record the design system in =.orgasmic/project.org= under =** Design System=, the stable DESIGN.md-equivalent anchor that pairs with =** Product Baseline= (dec_F2WRW). This record keeps only the rationale; the token source of truth (=ui/src/styles.css=, light =:root= / dark =.dark=) and the shadcn primitives (=ui/src/components/ui/*=) are named in that section, not here.
** Consequences
Design pointers — DESIGN.md, future impeccable runs, new surfaces — reference =project.org → ** Design System= by stable section name, never a decision id. Token changes are made in =ui/src/styles.css= and mirrored into that section. Pairs with dec_F2WRW (product baseline).
