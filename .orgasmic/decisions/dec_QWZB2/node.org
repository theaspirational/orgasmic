** Context
The canonical substrate determines whether orgasmic stays inspectable and Git-native. Structured config (JSON/TOML) is easier to parse but less human-editable as project memory, and an Emacs-native org-mode workflow introduces an unwanted editor/runtime dependency.
** Decision
The canonical substrate is an app-owned Org profile. Org-style files are orgasmic-owned application files: plain text remains the source of truth without depending on Emacs runtime semantics.
** Consequences
The parser, writer, schema, and UI editor are orgasmic responsibilities. Org compatibility is useful only where it supports inspectable project memory.
