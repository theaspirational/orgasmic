* dec_NZ9PS How should each desktop surface behave on mobile and touch?    :ui-mobile:

** Context
Mobile access via the cloudflared tunnel was a day-one requirement, so each desktop surface needs explicit touch and breakpoint behavior instead of best-effort responsive wrapping. Forcing kanban on mobile gives rough touch UX; stripping features loses parity.
** Decision
Adopt a locked mobile-behavior matrix (breakpoints sm 640 / md 768 / lg 1024 / xl 1280). Below md: the sidebar becomes an off-canvas Sheet via hamburger; the topbar collapses theme/gear/user into a ⋯ overflow; project dropdown, notification bell, and task/design modals become full-screen Sheets (task modal single-column with subtask sidebar as a tab and activity as a peekable bottom sheet); kanban auto-switches to list. List rows hide kind/priority chips below sm with swipe-left quick-actions; the cross-domain graph uses pinch-zoom and single-finger pan; manager popover heights are peek 70px / workbench 80vh / focus 100vh with a 44px tap target; activity compose is a sticky bottom bar; dropdowns become bottom Sheets; long-press opens the task drawer; list pages support pull-to-refresh.
** Consequences
Mobile keeps functional parity without forcing desktop layouts onto small screens, adopted via TanStack Router and shadcn Sheet primitives. The implementation must handle route state, Sheets, drag handles, row actions, and pull-to-refresh consistently across surfaces.
