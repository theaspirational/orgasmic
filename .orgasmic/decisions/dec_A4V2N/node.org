* dec_A4V2N How should task comments and the activity feed be stored?    :audit-tx:

** Context
The task drawer's activity rail needs human comments, agent completion summaries, state transitions, and run lifecycle events. orgasmic has tx for system events but no comment model. Dedicated comment files per task fragment the single-writer story; inline comments in the heading body force heavy heading rewrites, big diffs, and lock contention.
** Decision
Store comments as a new append-only tx type "comment" (TX_ID, TIME, ACTOR, PROJECT, TASK, optional RUN_ID, ARTIFACTS, optional IN_REPLY_TO, escaped-markdown BODY) on the same daemon-writer/audit path. The index gains an =activity_index: BTreeMap<TaskId, Vec<TxEntry>>= rebuilt on boot and updated on each append; =GET /tasks/:id/activity= returns the merged feed (comments + state transitions + run lifecycle from JSONL). The same projection fills a registered ={{task.activity}}= prompt slot so every agent gets full conversation history before its first turn.
** Consequences
Comments share the existing audit path and remain cheap to project into UI and prompts; append-only gives audit, replay, and conflict-free behavior. Findings from analyzer/explorer agents land in the parent task's =** Evidence= body, and the agent.completed comment links to it via a "View evidence" anchor.
