* dec_R3RE4 How should the Tasks page offer list/kanban views and drag-and-drop transitions?    :ui-tasks:
:PROPERTIES:
:ID:            dec_R3RE4
:GLOSSARY_REFS: term_RG690 term_9B3V8
:DECIDED_AT:    [2026-05-23 Sat 15:10]
:SOURCE:        archive/2026-05-23_ui-redesign/grill.md
:END:
** Context
The Tasks page needs both list and kanban affordances, and drag-and-drop must respect the state machine and the single-writer invariant. A read-only kanban routes all transitions through the manager (worst ergonomics); a DnD-opens-compose popover is slow for trivial moves since state changes are data ops, not intelligent ops (dec_C6510).
** Decision
Offer a List | Kanban view toggle. Kanban columns are the six lifecycle stages from dec_MKC0A (plus blocked/cancelled lanes), fixed regardless of kind. A drop on a column issues =POST /tx type=manager.action= (from_state, to_state, actor, reason="UI manual transition") with an optimistic update that reverts and toasts on validation error; invalid target columns dim. Below 768px the kanban auto-switches to list.
** Consequences
Manual transitions are fast and the tx audit captures who-did-what.
