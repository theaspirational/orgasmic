* dec_P7EY8 What vocabulary should run sub-states use?    :schema:state-machine:run-substate:
:PROPERTIES:
:ID:            dec_P7EY8
:GLOSSARY_REFS: term_VV48W term_X4JGJ
:DECIDED_AT:    [2026-06-10 Wed]

:END:
** Context
TASK-PT2DC verified the six per-kind RUN-SUBSTATE blocks were dead schema: `RunRecord.sub_state` is never assigned in production, `RunSubState::new` validates only namespace shape (agent|human|ci), and the vocabularies were duplicated and asymmetric (planner/analyzer lacked `claimed`, babysitter lacked `ready`/`blocked`, griller had a stage but no vocabulary while already borrowing analyzer verbs via `:APPLICABLE_STATES:`, the manager block listed the stale tick-era `agent.ticking` after dec_WTM5Y, and `human.escalating` named the recipient, not the performer).
** Decision
A run sub-state is `<performer>.<verb>` where the performer namespace is the worker kind doing the run (`griller`, `planner`, `implementer`, `reviewer`, `babysitter`, `manager`, ...), `human`, or `ci` (valid but reserved; no vocabulary uses it yet). The namespace names whoever performs the transition — escalating is performer-owned (`babysitter.escalating`), human verbs are genuine human acts. The verb set is a shared minimal base — `working`, `done`, `blocked`, `cancelled` — with deltas only where a recorded verdict matters: reviewer/human add `approved` and `requested_changes`. There is no `ready` or `claimed`: readiness is the Todo column at task level, and claiming is implicit in run acquisition. The six per-kind vocabulary blocks are deleted, including the manager block; the manager keeps no special vocabulary (its active verb is `manager.working`) and gets no `RunKind::Manager` — `RunKind` stays the tool-policy axis {Worker, Babysitter} (the performer is `RunSummary.role`, the resolved worker's kind), and manager identity stays the `manager.*` task_id/worker_id namespace the UI already keys on (TASK-KC92G).
** Consequences
The vocabulary keys on worker KIND (performer), not lifecycle stage; stage/vocabulary asymmetry dissolves. `session.rs` namespace validation must accept performer kinds, and the supervisor must wire `DriverEvent::TransitionState` into `rec.sub_state` so the schema finally has a consumer. UIs render `<performer>.<verb>` directly.
