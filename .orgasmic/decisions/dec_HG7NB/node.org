* dec_HG7NB Should one-time bootstrap guidance live in the always-on entry point?    :scaffold:onboarding:entry:
:PROPERTIES:
:ID:            dec_HG7NB
:GLOSSARY_REFS: term_CEQFS term_RG690
:DECIDED_AT:    [2026-06-09 Tue 13:58]
:SOURCE:        .orgasmic/entry.org
:PARENT:        dec_ACD08
:END:
** Context
=entry.org= is injected or read at the start of every future session for the life
of a project. dec_ACD08 put a first-run bootstrap pointer there, but bootstrap is
a one-time adoption task. Keeping "start TASK-C9V29" in the permanent entry point
means later agents continue to receive stale cold-start guidance after
TASK-C9V29 has been completed or deleted.
** Decision
Remove the always-on =** Bootstrap= section from =entry.org= and from the
canonical + skill-bundled scaffold entry templates. The entry point stays limited
to routing, the project map, and write rules. Bootstrap remains expressed in the
state that naturally expires: =tasks/goal.org=, =tasks/sprint.org=, and the
scaffolded =dec_K1DR7= bootstrap decision.
** Consequences
Agents no longer get a permanent instruction to start TASK-C9V29 merely because
they read the entry point. A newly scaffolded project still has an explicit
bootstrap goal, sprint task tree, and seed decision, so the first agent can find
the work without polluting every later session's context.
