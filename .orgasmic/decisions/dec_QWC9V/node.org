* dec_QWC9V Should silently-simulating acp-ws codex workers ship as selectable defaults?
:PROPERTIES:
:ID: dec_QWC9V
:PARENT:     dec_ASB1A
:END:

** Context
The codex harness has two transports among shipped workers: =acp-stdio= (spawns a real
=codex app-server= subprocess when =codex= is on PATH) and =acp-ws= (connects to a running
codex app-server over a configured =ws://= endpoint). Per [[dec_ASB1A]], =acp-ws= keeps a
simulated-mode escape hatch: when no endpoint is configured it emits Ready + RunComplete and
writes nothing — intended for supervisor-lease / JSONL CI tests. Two shipped workers used the
=acp-ws=/codex pair with no endpoint and no sandbox permissions: =implementer-codex-appserver=
and the default =reviewer=. Dispatching either out-of-the-box silently no-ops. A simulated
*reviewer* is the worse failure: it can rubber-stamp a change without actually reviewing it.

** Decision
Do not ship =acp-ws=/codex workers as selectable defaults.
- Remove =implementer-codex-appserver=. It is redundant: three real codex implementers already
  ship — =implementer-codex-acp= (acp-stdio), =implementer-codex-rmux=, =implementer-codex-tmux=.
- Repoint the default =reviewer= from =acp-ws= to =acp-stdio= and give it the standard sandbox
  permissions, so a =--kind reviewer= dispatch runs codex for real (matching
  =reviewer-codex-acp=).
- Keep the =acp-ws= driver and adapter in the codebase: it is a real transport for anyone who
  configures a =ws://= endpoint, and the CI tests that build their own =acp-ws= fixture workers
  to exercise simulated mode are unaffected (they write their own worker .org; they do not read
  =shipped/=).
- Update the =parses_every_shipped_worker= fixture count (19 -> 18).

The deeper root cause — =acp-ws= silently simulating instead of failing loudly when no endpoint
is configured — is left as a gated follow-up in the adapter, not done here.

** Consequences
- =orgasmic worker list= keeps showing the old set until the runtime is reinstalled/published
  from this source; the change takes effect on next install.
- No shipped worker uses the =acp-ws=/codex pair anymore; =is_supported_worker_pair= still lists
  it as valid, so the driver and its tests stay green.
- The footgun where a selected worker silently does nothing is closed for the default surfaces.
- Recorded in the same session that hit the simulated appserver run on TASK-2DFTX and filed
  [[TASK-KNENN]] (route work through orgasmic workers, not raw provider CLIs).
