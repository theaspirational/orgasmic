* dec_ACD08 How should a freshly-initialized project bootstrap its own .orgasmic state?    :scaffold:onboarding:bootstrap:tasks:
:PROPERTIES:
:ID:            dec_ACD08
:GLOSSARY_REFS: term_CEQFS term_RG690
:DECIDED_AT:    [2026-06-07 Sun 13:51]

:PARENT:        dec_A10RB
:END:
** Context
A freshly =init=-ed project gets a populated =entry.org= + =conventions/= (dec_A10RB) but otherwise empty/template =.orgasmic/= state: no real decisions, architecture, or tx records. The hardest moment is the cold start — the first agent has no worked example of the project's own =decisions.org= / =architecture.org= / =tx/= shapes to imitate, and the daemon may not be installed, so it can't lean on the manager pipeline. A placeholder =TASK-C9V29 Example task= in the scaffold sprint taught nothing.
** Decision
Ship the scaffold sprint as a self-bootstrapping task tree instead of a placeholder: one umbrella =TASK-C9V29= (KIND griller) with three ordered subtasks (=:PARENT_TASK: TASK-C9V29=) — =TASK-C9V29.1 infer-project= (griller), =TASK-C9V29.2 infer-decisions= (griller, DEPENDS_ON .1), =TASK-C9V29.3 infer-architecture= (architector, DEPENDS_ON .2). Each subtask's body instructs the agent to (1) audit the repo for concrete evidence, (2) grill the operator in small batches, (3) write its one target =.orgasmic/= file with real records (not placeholders), and (4) leave a tx activity record. The headings are fully schema-valid so the daemon can index a just-bootstrapped project, but the task bodies are self-contained so a plain agent can execute them with no daemon/CLI/skill. =entry.org= gains a self-guarding "First run" pointer to TASK-C9V29. The tree is the universal scaffold's sprint, distinct from this repo's own live sprint, which is untouched.
** Consequences
Cold start becomes a guided audit-and-interview that leaves =project.org=, =decisions.org=, =architecture.org=, and =tx/= holding real, repo-specific records — the worked examples later agents (and the manager) extend by imitation, satisfying the daemon-optional contract from the entry point down. The bootstrap order (project -> decisions -> architecture) mirrors how this repo itself was seeded. A new fixtures test (=shipped_scaffold_seeds_bootstrap_task_tree=) locks the parent/subtask structure, KINDs, and dependency ordering. Operators delete TASK-C9V29 once bootstrap completes. Open follow-ups: optional =infer-glossary= / =infer-gotchas= subtasks, and a daemon-path guard so the dispatcher does not double-run the umbrella alongside its subtasks.
