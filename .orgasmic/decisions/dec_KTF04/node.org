* dec_KTF04 Should superseded decisions be deleted or retained, and how is that derived?
:PROPERTIES:
:ID: dec_KTF04
:TAGS: decisions,graph,glossary,convention
:END:

Context: The Graph page shows superseded decisions grayed at the top. Today a superseded decision is deleted when its replacement lands (git is history), so it is no longer a node and cannot render. Decisions also carry no status field, and presence in decisions.org has meant accepted.

Decision: Stop deleting a decision when it is superseded - keep its heading. A decision is superseded iff some present decision's :SUPERSEDES: property points at it; no status field and no tag is added. Redefine accepted = present AND not a supersession target. The Decisions list page hides superseded decisions by default; only the Graph page surfaces them, grayed.

Consequences: decisions.org accumulates superseded records, which is intentional history for the map. The presence = accepted rule is refined to present and not superseded. No schema change: the gray set is a pure read-model over existing :SUPERSEDES: backrefs. This is what makes the Graph page's superseded-decisions band possible (see the graph-overlay decision).
