** Context
`orgasmic update` and `install.sh` run `git stash push --include-untracked` in the source repo (`update.rs`, `install.sh`). For this project the source repo and the orgasmic project are the same tree, so an update between a close and the manager's commit can remove the working-tree copy of a promoted dispatch record from the index/worktree view. TASK-QGWK7.1.1 open question 3 asked for a recorded decision; the defect was not introduced by the staging change.

** Decision
Accepted residual for now. Durability of the promoted record after TASK-QGWK7.1.1 rests on `refs/orgasmic/dispatch-records/<started_tx>`, which stash does not delete. The working-tree copy may disappear or be unstaged by an update; restore with `git show refs/orgasmic/dispatch-records/<started_tx>:.orgasmic/dispatch-records/<started_tx>/last.txt` (or checkout that path from the ref) before the manager commits. Do not teach update/install to special-case dispatch-records in this task.

** Consequences
- Close-then-merge and `git clean -fdx` no longer lose the record: the side ref holds it.
- An intervening `orgasmic update` can still hide the working-tree copy; managers who update mid-integration should restore from the side ref or re-copy before committing.
- A future task may exclude `.orgasmic/dispatch-records/` from the update stash, or restage from the side ref after stash pop; that is out of scope for TASK-QGWK7.1.1.
