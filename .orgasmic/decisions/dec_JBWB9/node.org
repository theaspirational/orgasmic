* dec_JBWB9 What can the artifact-generating worker read and write?
:PROPERTIES:
:GLOSSARY_REFS: term_S45HH
:ID: dec_JBWB9
:PARENT: dec_GPV4G
:END:

** Context
The stress-test scenario is "create a visual plan" pressed on a task node: a useful plan must name real files, symbols, and data shapes, which requires the codebase, not just the task heading. Generation runs on the daemon host and costs real money per run. Orgasmic's write authority must stay with the daemon writer; every worker run today binds to a task heading through the supervisor lease, except the manager, which launches under a synthetic id (manager.launch:{project_id}).

** Decision
The artifactor worker gets *full repo read access like an implementer*, plus the subject nodes' Org content, their graph neighborhood, and — on regeneration — the prior artifact.mdx and all current-version comments with authors and resolution state, plus the optional extra prompt.
- Its only write path is =orgasmic artifact submit=, which validates the MDX against the block registry before accepting; invalid output is returned to the worker to retry and is never written. The worker never touches .orgasmic/ files directly.
- Launch rides the existing dispatch machinery under a synthetic lease id =artifact.generate:{artifact_id}= — the manager.launch pattern — so no task-heading requirement bends and the lease is the per-artifact regeneration mutex.
- The default generating instructions live in a prompt spec (shipped/prompt-studio/prompt-specs/artifact-generator.org) with the block-vocabulary reference baked in, editable in Prompt Studio like every other worker prompt; the short user prompt from the Generate dialog is appended to it.

** Consequences
- Generated plans are grounded in the actual codebase; graph-only artifacts simply do not read the repo they were offered.
- Spend is bounded by the role gate (admin/editor) and the human trigger, not by starving the worker of context.
- A malformed generation cannot corrupt the store: the validation gate rejects it before the writer sees it.
- The worker cannot exfiltrate write access: read-everything, submit-only.
