* dec_C6510 Which UI actions should route through the manager, and which write directly?    :ui-manager:
:PROPERTIES:
:ID:            dec_C6510
:GLOSSARY_REFS: term_X4JGJ
:DECIDED_AT:    [2026-05-23 Sat 15:05]
:SOURCE:        archive/2026-05-23_ui-redesign/grill.md
:PARENT:        dec_DK7AZ
:END:
** Context
UI actions range from deterministic daemon writes to intelligent agent work, and routing everything through the manager would spend tokens on simple data operations. Composing through the manager for most or all actions wastes tokens narrating pure data ops.
** Decision
Use compose-to-manager only for intelligent operations (Start grilling, Architect, Plan, intelligent-Reconcile): these open the manager popover with a templated, editable prompt prefilled. Pure data operations (Take snapshot, Regenerate ADRs, simple-Reconcile) stay direct POSTs with a confirm toast.
** Consequences
The UI preserves manager narration where an LLM is required and avoids token waste where the daemon can act directly. Manager prompts must be templated and editable before send; e.g. the Decisions page "Start grilling…" button opens the popover with a prompt referencing the grill-me skill.
