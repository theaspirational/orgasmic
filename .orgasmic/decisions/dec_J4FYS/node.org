** Context
Strategy 3 of the rmux exploration asked whether =rmux= could honestly become an alternative terminal driver to the tmux+xterm path. The open question was whether the published =rmux-sdk = "0.5"= typed-control crate alone constitutes support, or whether a separately provisioned =rmux= daemon binary is still required, and whether the Web Share spectator/operator URL feature is real today. The risk was claiming a working integration on the strength of a compiling SDK dependency.
** Decision
Land =rmux= as a hybrid SDK-backed mode driver in a strictly bounded smoke posture, NOT as a production driver and NOT as a tmux replacement. The driver uses =rmux_sdk::Rmux::ensure_session= for typed detached-session control while discovering the =rmux= binary separately (=RMUX_SDK_DAEMON_BINARY= first, then PATH). The manager driver catalog reports the rmux mode binary (=mode_binary= / =mode_installed=) independently of the harness binary. When the binary or a capability is missing the driver degrades to an honest inert mode that records the exact reason (=rmux_binary_missing=, =harness_binary_missing:<cmd>=, =sdk_unavailable:<err>=) instead of faking success. Web Share operator URLs and pairing tokens are treated as privileged shell access: only redacted operator material is ever surfaced (=operator_url_redacted=), no token is persisted, and spectator URLs (read-only) may be shown in full.
** Consequences
The tmux default and the manager terminal surface are unchanged. =rmux= appears in =SUPPORTED= as the =("rmux","codex")= smoke pair (mirrored in =orgasmic-core::SUPPORTED_WORKER_DRIVER_HARNESSES=) and ships an =implementer-codex-rmux= worker template, but nothing in the default pipeline routes to it. Live smoke on 2026-06-05 with a =cargo install rmux@0.5.0= binary (via =RMUX_SDK_DAEMON_BINARY=) created a real detached session and minted both a spectator URL and a (redacted) operator URL through the SDK; with the binary absent the same code path degraded to inert with =inert_reason=rmux_binary_missing=. Promotion to a production driver (reattach via =rmux attach-session= through the xterm bridge, supervisor wiring, tunnel/frontend config for shareable URLs) is deferred to a future task.
