### 2. P1b — the fault routed through the production boot decision ✅

`crates/orgasmic-daemon/src/api.rs`,
`boot_reattach_refuses_a_candidate_whose_claim_store_could_not_be_listed`.

The `readdir` seam is now reachable from api tests (`pub(crate)`), plus a sticky
variant so one armed fault covers a whole boot pass rather than disarming after
the first listing. The fixture is the shape the finding names: a pending recovery
claim owns a replacement session file, and that same file is a live boot
candidate (asserted via `boot_reattach_candidate_from_scan` before anything else
runs). Three phases, all through `reattach_live_runs_on_boot`:

1. **Faulted** (`EIO` on the first `readdir`, sticky): the run is absent from
   `supervisor.snapshot()` **and** the session JSONL is byte-identical
   (`std::fs::read` before/after) — the irreversible write is what is asserted,
   not just the absence.
2. **Cleared, claim present**: predicate is `Valid`, boot still skips, file still
   byte-identical.
3. **Claim removed**: predicate is a decided `Invalid`, and the **same candidate
   through the same boot pass** is rehydrated — present in the snapshot and the
   JSONL has grown a `"phase":"reattach"` envelope.

Phase three exists because without it phases one and two would pass against a
candidate that cannot be reattached at all. That required a fixture whose
reattach genuinely completes without a live mux, so `StubDriver::attach` now
answers `Attached` when the persisted `driver_config` carries
`stub_reattachable: true` — `cfg(test)`-only, default unchanged
(`NotReattachable`), every existing stub fixture passes `json!({})` and is
unaffected. Documented at the impl: `arch_010`'s prove-the-handle rule is
untouched for every real driver.

**Red proof (the acceptance).** Changing the boot loop to reattach on
`Unobserved` — `if !matches!(ownership, ClaimEvidence::Invalid)` →
`if matches!(ownership, ClaimEvidence::Valid)` — gives:

```
test recovery_claim::tests::f2_a_failed_readdir_is_not_a_complete_directory ... ok
thread 'api::tests::boot_reattach_refuses_a_candidate_whose_claim_store_could_not_be_listed'
  panicked at crates/orgasmic-daemon/src/api.rs:22532:9:
  boot must SKIP, not reattach, while the claim store is unobserved; live runs were ["run-p1b-replacement"]
test result: FAILED. 1 passed; 1 failed
```

Round five's regression stays green under the defect it names; the new one reds.
That is the finding, measured. Both are kept and the round-five test's doc now
says which is which.

### 3. P2a — the non-UTF-8 assertion made executable on macOS ✅

Chose the **platform-independent raw-dirent seam**, not a Linux job.
`arm_readdir_entry_name(home, nth, bytes)` delivers the fixture the way the
kernel would: a real `libc::dirent` whose NUL-terminated `d_name` holds those
bytes, read back through the same `CStr::from_ptr(..).to_bytes()` the syscall
path uses, without advancing the directory stream. The per-entry decision
(`.`/`..` filter + `OsStr::from_bytes` push) was hoisted into a single `collect`
closure that **both** the injected and the real path call — so a reintroduced
drop has exactly one place to live and the injected test sees it.

Two new tests:

* `f2_an_injected_non_utf8_entry_name_survives_the_collect_on_every_platform` —
  count, exact bytes, no U+FFFD, and the real entries after it still listed.
* `f2_an_undecodable_entry_does_not_freeze_the_ownership_answer` — the injected
  `not-\xffutf8.json` goes through the caller's `.json` filter and
  `pending_recovery_claim_owns_session` still answers `Valid`. A refusal there
  would be an F3-shaped project-wide freeze caused by an unrelated file.

**Red proofs, both on macOS.** Re-introducing the drop in `collect`:

```
panicked at recovery_claim.rs:6932: no entry may vanish from the set — this is the
count a `to_str()` drop makes wrong: ["plain.json"]
test f2_a_non_utf8_entry_name_is_carried_not_dropped ... ok        <- old test, still green
test f2_an_injected_non_utf8_entry_name_survives_the_collect_on_every_platform ... FAILED
```

Making it lossy (`String::from_utf8_lossy`) reds the byte assertion at
`recovery_claim.rs:6938`, old test again green. The pre-existing FS-based test is
kept — it is honest, and it is the one that runs on ext4/tmpfs.

### 4. P2b — derivation self-checks ✅

Every invocation now asserts; `--self-check` prints the audit.

1. **Lexer consumed to EOF** — `strip_noise` length-preserving per file, plus
   **balanced braces after lexing**. That second assertion immediately found a
   real hole: `strip_noise` did not handle **raw strings**, so
   `br#"{"version":1,"tombstoned":{}}"#` in `run_catalog.rs` leaked 11 unbalanced
   braces into the matcher and its `\"` escapes were misread. Fixed with proper
   `(b|c)?r#*"…"#*` handling.
2. **Declaration-vs-body ownership** — new `signature_end()` scans at bracket
   depth zero for whichever of `{` / `;` comes first. 16 declarations now own no
   body, including exactly the two the finding named:
   `supervisor.rs:4834 observe` and `modes/stdio.rs:584 setsid`.
3. **Every indexed item accounted for** — `seen == definitions + declarations +
   bodyless`, `bodyless == 0`, and `len(index) == definitions`. Unbalanced bodies
   are an assertion, not a silent `(open, EOF)` fallback.
4. **`cfg(test)` at any visibility** — `mod` regex takes `pub(crate)`, and any
   module preceded by `#[cfg(test)]` counts regardless of name.
5. **Dynamic call sites from SIGNATURES** — `--report-dynamic` went from **1 row
   to 48**, and now names the binding's trait and the methods called on it. It
   reports the case the finding named:
   `supervisor.rs:1734 Supervisor::acquire_impl [signature] dynamic calls:
   WorkerDriver::acquire, WorkerDriver::harness, WorkerDriver::transport`
   (and `Supervisor::reattach` → `WorkerDriver::attach`).

Receiver-inference residual kept and restated. Boundary NOT re-litigated:
935/96 → **929 reachable names / 96 leaves**, and I diffed the `--json` leaf sets
before and after — **identical, 93 keys, nothing lost, nothing gained**. The
three `ClaimDirectory` leaves are present.

**Rust parser / type-aware graph: not taken this round, and stated in the
docstring.** It is the better answer. Neither `tree_sitter` nor
`tree_sitter_rust` nor any Rust-parsing module is installed in this environment,
and the alternative — a new workspace crate on `syn` plus a build step — is a
larger change than the finding. The self-checks are the bound on the lexer's
honesty until then.

## Residual Risk

* **The `supervisor::tests` probe-child family is unowned and unregistered.** It
  is load-sensitive, isolation-green, and it will keep turning any warm-host run
  RED for the next author. It is out of this round's scope; it deserves a task or
  a registry entry.
* **`StubDriver::attach` is now conditionally reattachable.** `cfg(test)` only,
  opt-in by config key, default unchanged — but it is a new capability in a
  shared test double. If a future fixture sets `stub_reattachable` without
  meaning it, it will get a live run it did not expect.
* **The `readdir` seams are `cfg(test)` branches inside production `names()`.**
  Ruling C5 covers the fault seam; the new name seam is the same shape and adds
  one more test-only branch to a hot loop. It is compiled out of production.
* **`--report-dynamic`'s 48 rows are a list, not a verdict.** Signature scanning
  removes the omission the reviewer found; it does not resolve the edges. The
  receiver-inference residual stands, and a `syn`-backed pass remains the real
  fix.
* **The derivation's brace-balance assertion now depends on raw-string lexing
  being right.** I fixed `r#"…"#`; nested/exotic forms (`c"…"`, byte-raw with
  many hashes) are handled by the same rule but are not separately tested.
* **`RunningAgentsMenu`'s "Recent" list still omits `failed_recoverable`.** That
  list is documented as "terminal/no-op runs from this boot plus any ambiguous
  ones" and omits `interrupted` and `reattached` too, so it is its own stated
  design rather than the P1a defect. Left alone deliberately; flagging it in case
  the manager disagrees.
* **Main still must not be packaged into a runtime until this lands.** The
  operator surface is fixed here and only here.
