## Changed

- `crates/orgasmic-cli/tests/dispatch.rs` — NEW regression
  `worktree_prune_refuses_a_repo_gone_worktree_whose_gitmodules_names_a_populated_directory`
  (F3). `RepoGone` + `.gitmodules` + **no nested `.git`**: a real submodule is
  added and `update --init`'d in the linked worktree, then its `.git` FILE is
  deleted, so `gitmodules_paths` is the only record left. Git's own refusal is
  measured **in that exact post-deletion state** (it still exits 128 over the
  index gitlink), then the admin directory goes away and `--dry-run` pins
  `RepoGone`. Drift-proofing: a local recursive walk asserts NO nested `.git`
  survives, and the `KEPT` line is asserted to be the `.gitmodules` arm's
  (`contains("`.gitmodules`")`) and NOT the nested-`.git` arm's
  (`!contains("nested repository")`, `!contains("vendor/sub/.git")`) — so the
  test fails if the wrong predicate refuses, which is exactly how the previous
  fixture rotted.

## Residual risk / intentional boundaries

1. **The corrected sentence deliberately does NOT mention the walk's blind
   spots** (`MAX_DEPTH = 64`, directories that fail to open). F4 names the
   over-refusal as the operator-visible consequence and that is stated; the
   narrow direction is left out under the brief's ruling 2 — I would rather
   under-describe than write a clause whose exact truth I did not measure. The
   review's C4 answer (the removal path bails symmetrically, so the outcome is a
   `RemovalFailure`, never a silent deletion) makes the omission safe but is
   still argued from source, not exercised.
2. **`cli_parity` shape (2) remains open by construction** — see the table
   above. Disclosed in the test's doc comment rather than implied closed.
3. The new fixture deletes the submodule's `.git` by hand. That is a
   constructed state, not one git produces on its own; it stands in for any
   worktree whose `.gitmodules` names a populated directory with no repository
   in it. Git's own refusal was measured in that state, so the parity premise is
   real, not assumed.
4. `MAX_DEPTH` and `chmod 000` fail-opens are still unexercised by any fixture
   (carried over from the review — not in this round's scope).
5. Non-Unix untested (`#[cfg(unix)]` throughout, unchanged).
6. The workspace suite beyond `-p orgasmic-cli`, `orgasmic-daemon`, and UI
   checks were not run — the brief's gate named `-p orgasmic-cli`.
