## Findings

### P2 MEDIUM (correctness / operator actionability) — `crates/orgasmic-cli/src/manager.rs:3738`

`WorktreeDisposition::UnsafeTraversal` has **two** causes — an unreadable descendant
and the 64-level depth bound (`walk_worktree`, `manager.rs:4092` vs `4123`) — but
`why()` is a single unconditional `format!` with no branch on cause. So the
over-depth refusal tells the operator:

> `... (refusing to descend deeper than 64 directory levels while scanning <prefix>);
> the whole worktree was skipped and nothing within it was deleted; make the offending
> descendant readable (for example with chmod) or remove it by hand, then re-run —
> this verb has no ``--force`` override`

**Impact.** The named first remedy is wrong for that cause: the deep directory is
already readable. An operator who follows the message chmods a directory that has
no permission problem, reruns, and gets a byte-identical refusal. The commit's own
goal — "fully actionable and unambiguous" *refusals*, plural — is met for one of the
two refusals and regressed for the other, because the pre-commit text
("kept before deletion") at least offered no wrong instruction. The help text now
makes this worse by fusing both causes into one sentence
(`manager.rs:427-429`), so nothing in the operator-facing surface distinguishes them.

**Evidence.** `why()` at `manager.rs:3738-3745` has one arm and no conditional;
`worktree_prune_refuses_an_over_depth_tree_before_deletion` passes while asserting
`all.contains("refusing to descend deeper than 64 directory levels")`
(`dispatch.rs:10761`), which is reachable only through that arm — so the chmod
sentence is provably printed on the depth path. (I did not capture the literal line:
the test only prints `all` on failure and I am read-only. The deduction rests on a
single-arm match plus a passing assertion that the arm is reached.)

**Fix direction.** Branch the remedy on cause — carry an enum
(`UnsafeTraversal { detail, cause: Unreadable | OverDepth }`) or split the variant,
and say "flatten or remove the over-deep directory chain by hand" for the depth case.
Keep the whole-worktree guarantee and the no-`--force` sentence shared.

### P3 LOW (test) — `crates/orgasmic-cli/tests/dispatch.rs:10759`

The over-depth regression pins only `SKIP PATH=` plus the depth phrase. None of the
three new contract assertions added to the chmod test (`10666-10684`) — cause chain,
whole-worktree no-delete guarantee, remedy + no-force — exist on the depth path. The
new operator contract therefore has coverage on one of the disposition's two causes.
This is what lets Finding 1 sit green.

**Fix direction.** Hoist the guarantee/remedy assertions into a shared helper and
call it from both refusal tests, with a cause-specific remedy phrase per test.

### P3 LOW (docs / usability) — `crates/orgasmic-cli/src/manager.rs:4202`

`report_managed_worktrees` — documented at `4156` as "the automatic half of the split:
every `dispatch-status` names what `worktree-prune` could reclaim" — prints the same
`why()` under `KEPT_WORKTREE PATH=... WHY=...` (`4205-4209`). In `dispatch-status` no
prune ran, so "the whole worktree **was skipped** and nothing within it **was
deleted**" describes an event that did not occur, "then re-**run**" names a verb the
operator did not invoke, and "**this verb** has no `--force` override" is scoped to the
wrong verb. Pre-commit wording ("kept before deletion") was verb-neutral, so this is a
small regression introduced here. Not dangerous — the direction of the error is
conservative — but it reads as a report of a prune to someone who ran an inventory.

**Fix direction.** Split the tense/verb-scoped remedy clause out of `why()` and append
it only at the `worktree_prune` SKIP site (`5422`), leaving `why()` with the
cause + guarantee.

### P3 LOW (noise) — `crates/orgasmic-cli/src/manager.rs:4124`

The `{err:#}` chain double-names the descendant and surfaces the raw syscall. The two
context layers are `could not open worktree descendant {prefix}{name}`
(`manager.rs:4124-4129`) and `openat {name:?}`
(`manager.rs` `anchored_dir::open_child_dir`), so the rendered detail is
`could not open worktree descendant z-unreadable: openat "z-unreadable": Permission denied (os error 13)`
— the middle frame adds a syscall name and a duplicate quoted path. Brief item 1 asked
for the chain "without exposing irrelevant implementation details". Harmless, and the
tradeoff is defensible (dropping the frame risks losing errno context on some paths);
noting it so the choice is deliberate rather than incidental. The `openat` frame text
is reconstructed from the two context sites, not observed in captured output.

## Fix Directions

Ordered by value, none blocking:

1. Branch the `UnsafeTraversal` remedy on its cause so the depth refusal stops
   prescribing `chmod` (Finding 1). Carry the cause on the variant rather than
   pattern-matching the detail string.
2. Extend the over-depth regression with the same guarantee/remedy assertions the
   chmod one now carries, via a shared helper (Finding 2). This is what keeps
   Finding 1 from recurring.
3. Move the tense-and-verb-scoped remedy clause out of `why()` to the
   `worktree_prune` SKIP site so `dispatch-status` stops reporting a prune that never
   ran (Finding 3).
4. Optionally drop the `openat {name:?}` context frame in
   `anchored_dir::open_child_dir`, since the caller already names the descendant
   (Finding 4) — only if the errno stays attached on every path that uses it.
