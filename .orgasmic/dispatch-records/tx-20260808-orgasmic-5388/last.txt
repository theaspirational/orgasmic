### Acceptance 1 — the class, structurally

`index_recovery_origins_in_session` returned `IndexedRecoveryOrigins`, a struct
with a `links` field and a `Default`, and three error paths spelled failure
`IndexedRecoveryOrigins::default()`. It is now:

```rust
#[derive(Debug)]
#[must_use = "an origin-index pass states its own completeness; dropping it \
              turns `I did not observe` back into `I observed nothing`"]
pub enum IndexedRecoveryOrigins {
    Complete { links: Vec<IndexedRecoveryOrigin>, bytes_inspected: u64 },
    Unobserved { reason: UnobservedSession, bytes_inspected: u64 },
}
```

**What a future call site is prevented from doing, and by what mechanism:**

1. **It cannot return an empty success from an error path.** There is no
   `Default`, so `IndexedRecoveryOrigins::default()` does not compile, and
   `Complete` cannot be constructed without a `links` vector the function
   actually produced.
2. **It cannot reach `links` without naming the failure.** `links` lives inside
   a variant; reading it needs a `match`, and a `match` needs an arm for
   `Unobserved`. Ignoring the unresolved case is still possible — but only by
   typing the word, which is what makes it reviewable.
3. **It cannot silently drop the result.** `#[must_use]` plus the workspace's
   `-D warnings` makes that a build failure.
4. **The unresolved variant carries no links**, so there is nothing partial to
   reach for even after matching.

`AuthoritativeOriginLinks` (the per-project enumeration) has the same shape, and
`ResolvedRecoveryClaim` gained an `Unobserved` variant so every consumer's
exhaustive match forces a decision.

**The pin:** `the_origin_index_result_cannot_spell_failure_as_an_empty_success`
reads the production half of `recovery_claim.rs` (comment lines stripped, so the
forbidden spellings quoted in the doc comments cannot match themselves) and
asserts both types are enums, derive no `Default`, have no `::default()` call
site, are `#[must_use]`, and that their unresolved variants carry only a reason.
Structure is what regressed three times, so the pin asserts structure. It stays
GREEN under this round's injection **on purpose** — the injection changes which
variant the code constructs, not the shape. The pin guards the shape; the six
behaviour regressions guard the use.

### F1 — per-file failures propagate (acceptance 2)

### F2 — the skipped middle is read (acceptance 3)

`complete_session_scan` runs the bounded scan first and escalates to a new
**streaming** full enumeration (`scan_session_lifecycle_complete_reader`) when
the bounded windows truncated *or* errored. Streaming, not a whole-file read:
peak memory is one line plus the retained envelopes, never `file_bytes`.

**Unresolved stays distinct from invalid.** `ResolvedRecoveryClaim::Unobserved`
never quarantines. `an_unreadable_sibling_session_suppresses_authority_without_destroying_the_claim`
proves a transient failure suppresses authority and then the *same* claim
resolves `Valid` once the file is readable.

**F2's production route is confirmed in source, not just modelled:**
`supervisor.rs` `GitDiffSummarizer::summarize` runs `git diff --stat HEAD` with
no cap, that text becomes the `PromptDraft`, and the committed snapshot embedded
in `RecoveryOrigin` repeats it. Nothing bounds the link's line size.

### F3 — one authoritative set on every branch (acceptance 4)

`resolve_authoritative_recovery_claim` takes the authority *before* the branch,
so `Ok(None)` and `CorruptClaim` decide from the same set as `Committed`. The
catalog-derived `indexed_origins` parameter and `collect_recovery_origin_index`
are **deleted** — there is no longer a cache-shaped input to be blinded.
`POST /runs/:id/recover` refuses **503** up front when a failed origin's
enumeration is unresolved, which is the path where `Missing` would otherwise be
read as permission to mint.

### F4 — one snapshot per decision (acceptance 5)

`ProjectOriginAuthority` memoizes per project root for the life of one inventory
or recover decision and is dropped with it, so it can never become the stale
index the task exists to stop trusting. Built **lazily**: a board with no
failed-recoverable run opens no session file, which is the part of
TASK-FZB6T.1's property that was really doing the work.
`InventoryStageMetrics::origin_index_{files,bytes_inspected}` (serialized to the
UI) are now fed from `ProjectOriginAuthority::cost()`.

### Two defects the daemon suite caught, not the unit tests

1. **A torn final line is not a torn middle line.** Reading them as equally
   fatal froze a project's recovery on one junk `.jsonl`
   (`forged_recovery_claim_does_not_suppress_actions_without_session_proof`
   went red). Reading them as equally harmless hides a second authority behind
   one bad line. `scan_session_lifecycle_complete_reader` now *defers* a parse
   error and returns it only if a later non-blank line proves bytes were left
   unread. Pinned by `a_torn_final_line_is_observed_and_a_torn_middle_line_is_not`.
2. **The 503 preempted a more specific 400.** An `O_NOFOLLOW` open of a
   symlinked origin also fails the enumeration, so
   `recovery_post_rejects_origin_symlink_and_rename_swaps_after_authority` got
   503 instead of `origin session authority changed`. The retained origin
   authority is now re-validated before the unresolved refusal is reported.

## Residual Risk

1. **340 ms per decision on a 1.15 GiB board, and the board only grows.** This
   is the honest price of acceptance 4: `Missing` may only be reported by a set
   that has stated its own completeness, and the only such source in-tree is the
   filesystem. It is entered whenever a failed-recoverable run exists in a
   project — including the common case of a failed run with **no** claim — so a
   `GET /runs` poll in that state pays it. It scales with total session bytes,
   not with claims. The reviewer's option 2b (a catalog generation whose
   completeness contract includes invalidation *and* scan failures) is the way
   to get it back to ~49 ms, and it is a design change, not this round's fix.
2. **`remove_recovery_claim` still has zero callers** (manager-verified; I
   re-checked: only the definition). Committed claims accumulate unbounded, and
   each one keeps its project on the slow path forever. Per ruling 3 I did **not**
   add a cleanup caller. It wants its own task.
3. **Torn-line classification rests on a writer invariant.** "A malformed line
   with nothing after it hides nothing" is true because `SessionWriter` appends
   whole `sync_all`-ed lines, so the only partial one is the one being written
   at death. A future writer that buffers partial lines mid-file would break the
   inference. It is stated in the doc comment on
   `scan_session_lifecycle_complete_reader` and pinned by a core test, but it is
   an invariant about a *different* module.
4. **Non-Unix is compile-checked only.** The `#[cfg(not(unix))]`
   `complete_session_scan` mirrors the Unix one and was never executed here.
   MSRV 1.87 was not checked.
5. **The escalation reads whole transcript files.** On a project whose sessions
   directory holds a multi-gigabyte single file, one decision reads that file
   end to end. Memory stays bounded (streaming, one line at a time); wall clock
   does not.
6. **`verify/TASK-2QK4P.1`'s re-authored red count is wider than the original's**
   (5 failures vs 2). I judged that honest rather than weakening — the extra
   three are the uniqueness rule reached through other fixtures, and they move
   only because the insulating parameter is gone — but it is a change to a
   shipped proof and the manager owns whether that trade is acceptable.
