# Findings

## P1 HIGH correctness — a silent catalog can hide contradictory authenticated replacements and the resolver now accepts one

`crates/orgasmic-daemon/src/recovery_claim.rs:1294-1299` treats `matching.len() == 0` as non-contradictory and returns the loaded claim when its own transcript verifies. The empty slice has no completeness provenance. `collect_recovery_origin_index` can omit every matching link because a board entry/path/identity/session directory is unavailable, because a catalog record is absent or lacks `replacement_run_id`, because a candidate scan rejects the file, or—most importantly—because `RunCatalog::invalidate_session` removed every relevant live entry (`crates/orgasmic-daemon/src/api.rs:11831-11873`, `crates/orgasmic-daemon/src/run_catalog.rs:1124-1134`).

The codebase already models two daemon-HMAC-authenticated replacements for one origin as a safety violation: `duplicate_authenticated_replacements_fail_closed` builds both valid transcripts and requires `InvalidQuarantined` (`crates/orgasmic-daemon/src/recovery_claim.rs:2455-2543`). If both replacement records have been invalidated by lifecycle appends, the collector supplies no links; the changed branch verifies only the loaded claim's transcript and returns `Valid`, never discovering the other authenticated replacement. `/api/runs/:id/recover` then returns that one replacement (`crates/orgasmic-daemon/src/api.rs:9075-9097`), and inventory clears recovery actions (`crates/orgasmic-daemon/src/api.rs:11780-11801`), silently choosing authority in a state the existing duplicate regression requires to fail closed.

This is the pre-authorized block-ship condition: a globally contradictory authority set becomes admissible solely because the cache is silent. The safe slow path must distinguish “this one entry is temporarily invalidated” from “the candidate set is incomplete.”

## P2 MEDIUM test — the new unit test bypasses the production component whose blindness is the claimed mechanism

`committed_claim_survives_an_index_blind_to_its_replacement` passes a literal `&[]` directly to the resolver (`crates/orgasmic-daemon/src/recovery_claim.rs:2634-2640`). It does not instantiate `RunCatalog`, invalidate a record, call `collect_recovery_origin_index`, or retain a hidden contradictory replacement. It therefore passes if the production collector is accidentally globally blind, and it passes while the P1 duplicate state is hidden. Restoring the old `matching.len() == 1` predicate would make this test fail by control flow, so it pins the permissive resolver branch, but not whether the silence reaching that branch is safe.

## P2 MEDIUM test/process — green crash-recovery executions are never repeated, so an intermittent P0 can still merge green

The CI suite invokes `scripts/run-tests.sh` once (`.github/workflows/ci.yml:194-207`). The wrapper only re-executes tests that failed in that first run (`scripts/run-tests.sh:944-959,1007-1015`). A green execution of `recovery_faults_kill_real_daemon_and_preserve_original_pane` receives no repetition or pass-rate scoring. That directly explains how an approximately 40%-red crash-recovery defect can pass an ordinary gate roughly three rounds in five. Add a focused repeated canary or pass-rate gate for this recovery test; the existing failure-isolation machinery cannot detect intermittent reds on an initially green run.

# Verdict

`reject` — BLOCK SHIP on P1. TASK-2QK4P (crash-recovery replay 409s) fixes the measured 409 path, but the zero-link branch is broader than the “one live entry temporarily invalidated” state it intends to authorize.

# Open Questions

No unresolved product decision is needed for this review. `matching.len() > 1` is deliberate conservatism consistent with the existing uniqueness regression. The normal commit path also suppresses a duplicate identical `RecoveryOrigin` append (`crates/orgasmic-daemon/src/api.rs:9395-9410`). If the product wants a current claim to supersede historical authenticated duplicates, that would require an explicit authority-ordering rule and replacement of the current fail-closed test; this patch does neither.
