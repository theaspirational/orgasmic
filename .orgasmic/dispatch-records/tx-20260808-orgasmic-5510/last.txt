## Acceptance, point by point

**1. Derive the boundary.** `python3 scripts/derive-observation-surface.py`.
Method: index every `fn` (brace-matched, comment/string/**char-literal** aware);
build call edges resolved by CALL KIND — `name(`→free fns, `Type::name(`→that
type, `.name(`→methods whose owner type is named in the calling file; BFS from
`post_run_recover`, `get_recovery_inventory`, `reattach_live_runs_on_boot`;
report reachable definitions whose own body touches a syscall.
Result: **935 reachable names, 96 syscall-touching leaves.** It finds
`ClaimDirectory::open`, `::read_regular` and `::names` — the three round four
missed — plus `::open_file`, `::rename`, `::remove`, `::sync`,
`SessionDirectory::{open,create_path,open_name,open_name_with_flags}` and
`SessionFile::{read_checked,scan_lifecycle_checked,scan_lifecycle_complete_checked}`:
**19 leaves in `recovery_claim.rs` alone that round four's 16-row table did not
contain.** They were invisible because round four's first line was a hand-written
path definition that named the resolver's five callees and stopped there; these
sit one call below `load_recovery_claim` and `pending_recovery_claim_owns_session`.

Two bugs in my own first pass are worth naming, because both made the boundary
too SMALL and both were found by running it, not by reading it: `IMPL_RE` had no
`re.MULTILINE`, so every method got `owner=None` and no `ClaimDirectory::*` was
reachable; and the lexer treated the `"` inside `b'"'` as a string opener, which
swallowed the rest of `session.rs`.

**Residual, stated:** the `.name(` rule is the one inexact edge — a receiver's
type is not recoverable without inference, so it over-approximates (superset,
the safe direction) and it *under*-approximates only if a receiver's type is
never named in its file. `--report-dynamic` reports the `dyn`/function-value
edges this pass cannot follow (2 rows). `#[cfg]` is not evaluated. Making it
exact needs `rust-analyzer`/`rustc_middle` call-graph output, not regex. **This
is still an approximation and I am not claiming otherwise** — but it is a
mechanical, rerunnable one that demonstrably catches what the hand-drawn one
missed.

**2. Errno policy, once, next to the type.** `ObservationClass` +
`classify_observation` + `claim_io_error`, beside `RecoveryClaimError`. ENOENT →
`Absent`; ELOOP/ENOTDIR/EISDIR/ENAMETOOLONG → `Decided`; everything else,
**including every errno not named**, → `Unobserved`. Pinned by
`the_errno_policy_is_stated_once_and_defaults_to_unobserved`.
Applying it found one more divergence the findings did not name:
`enumerate_recovery_origin_links` mapped `ENOENT` on the sessions directory to
`Unobserved`, so a project that has never written a session refused recovery.
An absent sessions dir is now `Complete([])`.

**3. F1.** `ClaimDirectory::open` and `::read_regular` carry access failures as
`Unobserved`, never `CorruptClaim`; 503, no quarantine.
`f1_an_unreadable_pending_claim_is_unobserved_and_never_quarantined` (real
`chmod 000`) asserts no `Valid`, no quarantine file, claim bytes byte-identical,
then normal resolution after repair. `f1_an_unreadable_claim_store_...` covers
the store. Red proof: injected → `got Missing` (the quarantine *removed* the
pending claim — permission to mint).

**4. F2.** `names()` clears errno before `readdir` and reads it after,
propagates `closedir`, and returns `OsString` so a non-UTF-8 entry is carried
rather than dropped. Regression is on the production boot routing predicate
(`boot_reattach_ownership`, extracted from `reattach_live_runs_on_boot` so the
test exercises the real expression): injected nth-entry EIO → `Unobserved`, not
`Invalid`; session file byte-identical; normal routing after repair. Red proof:
`got Invalid` — boot would have reattached.
**Non-UTF-8 decision:** an entry name is bytes. Carried unchanged; the `.json`
filter then decides about it. Lossy conversion was rejected because the mangled
name opens as `NotFound`, i.e. "absent" — the same collapse one layer down.
**Platform gap, reported:** APFS/HFS+ reject non-UTF-8 filenames with `EILSEQ`,
so the byte-preservation half of that test **cannot run on macOS**. The test
detects this, asserts `EILSEQ`, prints a note, and still enforces the type-level
pin. The byte assertions run on Linux.

**5. F3, and the design question answered.** `UnobservedEvidence { reason,
subject, remediation }` travels from the failing leaf through enumeration,
inventory, logs, the 503 and `ui/src/lib/types.ts` + `RunsView`.
**Recommendation: project-wide refusal STAYS.** Isolating a malformed session as
a per-file fault means dropping it from the set and calling the remainder
complete — bit-for-bit the defect rounds one through three closed, and the file
that could not be read is exactly where a second authenticated replacement could
be. What was actually broken is that the refusal was anonymous and had no exit.
**Repair path shipped:** `Remediation::hint()` — for a malformed session,
"move that one named file out of `.orgasmic/sessions/`" — delivered in the 503
body, the inventory record, the log line and the UI. Regressed end to end in
`forged_recovery_claim_does_not_suppress_actions_without_session_proof`: the
diagnostic names the file, the documented repair is performed, and the whole
project's recovery resumes.

**6. F4.** No wildcard on the resolver enum — every `ResolvedRecoveryClaim` and
`RecoveryClaimError` arm written out. Read-side claim IO answers a retryable 503.
Both boundaries regressed (`f4_a_claim_io_failure_is_retryable_not_an_internal_error`
red at 500-vs-503; `f4_the_helper_never_spells_could_not_decide_as_decided_no`).
**Honest note:** restoring the wildcard TODAY changes no observable answer,
because after F1 every unobserved path is already converted to
`Ok(ResolvedRecoveryClaim::Unobserved)` before reaching the helper — I checked by
injecting it and the behaviour test stayed green. The guarantee is therefore
compile-time, and it is pinned as such: the structural pin now forbids `_ =>`,
`_ if`, `Err(_)` and `Ok(_)` in that function (and reds when the wildcard
returns).

**7. F5.** The probe is split into `token_is_present`, and the regression uses
**no hook at all**: search permission removed from the token's parent so the real
`stat` fails while the token survives. Asserts `load_or_generate` NOT reached (a
dedicated counter, not just byte equality), token bytes unchanged, decision
`Unobserved`/`RepairAuthKey`, retry succeeds. **Red proof with `try_exists`
replaced by `exists`: FAILED — `an unstattable token must be unobserved, got
Err(CorruptClaim)`** (i.e. it minted).

**8. Gate — INCONCLUSIVE, not green.** See below.

## Residual risk

1. **`ClaimDirectory::{rename, remove}` and `write_claim_atomic` still return raw
   `Io`.** Deliberate: they are WRITE-side, and the findings and acceptance are
   scoped to the read side. The derivation surfaces them; a future round should
   classify them. Not widened here.
2. **`SessionDirectory::*` and `SessionFile::*`** are on the derived surface and
   were not re-classified this round. Their failures already reach `ClaimEvidence`
   via `session_read_evidence`, which now applies the one policy — but the leaves
   themselves have not been individually audited against it.
3. **`tmux_session_exists`, the non-unix collapse, and
   `recovery_origin_authority`'s 400-instead-of-503** are out of scope by ruling
   and were not touched.
4. **`errno` is a new direct dependency** of `orgasmic-daemon` (already present
   in `Cargo.lock`; vendored). Chosen over hand-rolled `__error`/`__errno_location`
   cfg arms so the Linux runtime build cannot break on platform detection.
5. **`ClaimEvidence` and `UnobservedEvidence` are no longer `Copy`** (they carry a
   `String` subject). All call sites compile and clippy is clean, but this is the
   widest-blast-radius part of the change.
6. **Not run:** the workspace suite, MSRV 1.87, non-unix, real-board latency,
   `orgasmic verify` replays other than the five above, the 10/10 recovery-fault
   repetition, and the UI typecheck — `ui/node_modules` is not installed in this
   worktree, so `ui/src/lib/types.ts` and `RunsView.tsx` are **unchecked by
   `tsc`**. They are type-only additions plus one helper function, but that is an
   untested surface and I am naming it.
