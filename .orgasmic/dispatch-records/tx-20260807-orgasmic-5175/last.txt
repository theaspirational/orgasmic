## The completeness argument (the manager's first question)

The ladder at `scripts/run-tests.sh:1312-1394` is an `if/elif` chain terminating
in `else`, so **no cell is double-owned and no cell is unowned by construction**.
The question is only whether each cell's owner is the *right* one.

**The mode dimension collapses.** `live` vs `--classify` does not select
different arms: every input to the ladder is derived from the log text
(`FAIL_COUNT`, `CRASH_COUNT`, `REAL/FLAKE/LOAD`, `BUILD_BROKE`, `HOST_*`) except
`SUITE_EXIT`, and `--classify` reads that from the stamp the live run wrote
(`:568`). Mode therefore only decides **which exit column you land in**: a
stamped log lands in the same column as the live run; only a pre-stamp log lands
in `?`. `read_suite_exit_stamp` also rejects a non-numeric stamp, so a corrupt
stamp lands in `?` too. That reduces 5 dimensions to 4.

Owners, in ladder order (first match wins):

| # | arm | owns |
|---|---|---|
| 1 | `BILLED_RAN` | billed test ran — any cell |
| 2 | `BUILD_BROKE` | `error: could not compile` / `error[E…]` |
| 3 | `CRASH_COUNT > 0` | **crash = some**, all 24 remaining cells |
| 4 | `SUITE_EXIT_ANOMALOUS` | **exit = other**, crash = none, all 12 |
| 5 | `REAL_COUNT > 0` | exit ∈ {0,101,?}, crash none, an unexcused failure |
| 6 | `LOAD_COUNT>0 && calm` | interlock breach — **provably unreachable** |
| 7 | B2 `FAIL_COUNT==0 && exit∉{?,0}` | reachable population is now **exactly `exit==101`, no listed failures, no crash** |
| 8 | `HOST_DEGRADED` | exit ∈ {0,101,?}, no crash/real, degraded |
| 9 | `FAIL_COUNT > 0` | exit ∈ {0,101,?}, all-flake, calm/unknown → `GREEN modulo N` |
| 10 | `else` | exit ∈ {0,?}, nothing listed, calm/unknown → `GREEN` |

**I ran the grid, not just read it.** 72 `--classify` cells — exit {0, 101, 137,
unstamped} × failures {none, registered flake, unregistered real} × crash {none,
one SIGABRT} × host {calm, degraded, no stamp}. Every cell produced a verdict
line and an exit code; no cell fell through, no cell produced an empty verdict.
Full table in Verification Notes. The two cells whose owner I would argue with
are F-7 and F-8 below; every other cell's owner is the one I would have chosen.

**Arm 6 is unreachable, not dead-by-accident**: `LOAD_COUNT` is incremented only
inside `if [ "$iso" -eq 0 ] && [ "$HOST_DEGRADED" -eq 1 ]` (`:1023`), so
`LOAD_COUNT>0 → HOST_DEGRADED==1` and arm 6's second conjunct is false whenever
the first is true. It is a live assertion that the interlock held, which is what
its comment claims. Correct as is.

## Findings

### F-6 — LOW (robustness) — the one parser dependency that fails GREEN
`scripts/run-tests.sh:850`. Answering the manager's claim 8.

The new detector rests on four string shapes. Three fail **loudly**:

- `^[ \t]+Running …(bin)` (`:849`) — if this breaks, every target's `matchbin`
  becomes `?`, nothing can claim, **every failing target becomes a crash**. False
  RED. Loud.
- `^[ \t]+Doc-tests ` (`:854`) — same direction.
- `Caused by:` / `process didn't exit successfully` (`:869`) — display only now.
  Breakage costs a cause line, nothing else. This is exactly what F-2's fix
  bought and it is the right trade.

One fails **silently, green-ward**: `^error: [a-z]+ failed, to rerun pass \``
(`:855`). If a future cargo rewords it, `TARGETS_TSV` is empty, `CRASH_COUNT` is
0, the `CRASHED` section vanishes, and the only remaining witness is exit 101 —
which arm 7's `FAIL_COUNT` guard swallows the moment one registered flake fires.
That is R-1's exact shape, re-armed by a cargo upgrade rather than by an edit.
The implementer names the `Running`/`Doc-tests` shapes as assumed (residual risk
2) but not this one, and it is the only one of the four whose failure direction
is green.

**MEASURED, cargo 1.94.1, my own throwaway crate:** cargo emits an *independent*
second count of failing targets, and it does so for N=1 as well as N>1 —

```
error: test failed, to rerun pass `--lib`
error: 1 target failed:
    `--lib`
```
```
error: 3 targets failed:
    `--lib`
    `--bin crashdemo`
    `--doc`
```

**Fix direction:** cross-check. `grep -E '^error: [0-9]+ targets? failed:'` yields
a target count parsed from a *different* sentence. If it disagrees with
`TARGETS_FAILED`, the parser has drifted — RED with its own line. One grep, and it
converts the single green-ward dependency into a loud one. (The summary block is
emitted under `--no-fail-fast`, which `run-tests.sh` always passes.)

### F-7 — LOW (latent, pre-existing) — a cargo error line in a test's own stdout invents a target and reddens a target that reported
`scripts/run-tests.sh:855`.

The crash awk has no notion of the `---- name … ----` capture region that the
failure parser at `:733` maintains. A line at column 0 matching
`error: <kind> failed, to rerun pass \`…\`` **inside a test's captured stdout** is
therefore read as a real failing target by one awk and as detail text by the
other.

**REPRODUCED** (probe P4) — one registered flake whose captured panic block
contains `` error: test failed, to rerun pass `--bin phantom` `` and nothing else
changed:

```
  failures : 1
  crashed  : 1 target(s) died without reporting a failure list
CRASHED (1) — target died without reporting a failure list:
  -p orgasmic-daemon --lib
      note     : libtest dies with the process, so this target reported NO
                 failures. It cannot be classified, registered, or excused.
verdict: RED — 1 crashed test target(s)                                   exit 1
```

The phantom claims the reporting binary, so the target that **did** report its
failures is the one printed as crashed — F-2's symptom by a fourth route — and
`--bin phantom` appears nowhere.

**Classification: pre-existing, not a regression.** Round 5's
`grep -c '^error: test failed, to rerun pass'` counted the same phantom into
`TARGETS_FAILED` and produced the same false RED. **Not live here**: `grep -rn
"to rerun pass" crates --include="*.rs"` and the same for `Running unittests`
return nothing. The one non-zero reachability route in *this* repo is a test that
captures a spawned agent's or a nested cargo's stdout. Direction is RED, so it
cannot mint a green.

**Fix direction:** give the crash awk the same `capturing` flag the failure
parser already has — set on `^---- .* ----$`, cleared on `^failures:$` /
`^test result:` / `Running` / `Doc-tests` — and ignore `error:` lines while it is
set. Same three anchors, already proven in the sibling awk.

### F-8 — LOW (pre-existing, unreachable from cargo) — exit 0 with listed failures still returns GREEN modulo N
`scripts/run-tests.sh:1391`. Answering the manager's claim 5 — **no, this is not
the next adjacent branch.**

Confirmed reachable *in the model*: sweep row `exit 0 / flake / no crash / calm`
→ `GREEN modulo 1 registered flake(s)`, exit 0.

**But it is not reachable from cargo, by construction.** libtest prints a
`failures:` block only on a run it fails, and cargo exits 101 if any target fails
— I re-measured both halves on 1.94.1. So exit 0 and a non-empty `failures:` list
cannot co-occur in a log cargo wrote. The only routes are a hand-assembled or
concatenated `--classify` log (`read_suite_exit_stamp` takes `tail -n1`, so
appending a green log's stamp to a red log's body produces this exactly).

I would **not** spend a round on it. If it is taken, it is one `elif` above arm 9
— `FAIL_COUNT > 0 && SUITE_EXIT == 0` → RED, "cargo exited 0 but the log lists
failures; this log is not internally consistent." It costs nothing and it closes
the last cell where the exit code and the failure list disagree without anyone
saying so.

## Rulings on the manager's specific claims

**1. Row 7 — anomalous exit on a degraded host: `INCONCLUSIVE`(4) → `RED`(1).
CORRECT AS SHIPPED. Not BLOCK SHIP, not a follow-up. Do not move the line.**

The manager's objection is the right one to raise and it does not survive, for a
reason neither side stated: **`HOST_DEGRADED` is not evidence that the kill was
jetsam.** It is measured from the syspolicyd CPU-seconds-per-wall-second rate
(`:1213` block, threshold `rate>=1.50`) — a *contention* proxy. Jetsam is a
*memory-pressure* kill and need not move that rate at all; conversely a thrashing
host can be measured degraded while cargo dies of something else entirely.
Routing the verdict through it would make a truncated suite's diagnosis depend on
an unrelated measurement — which is the founding sin in its other direction.

The asymmetry of costs settles it. RED on a real jetsam costs one re-run, and the
verdict line says so honestly: `RED — cargo exited 137: neither 0 nor libtest
101, so the suite did not finish`. That sentence attributes nothing to code — it
is host-neutral, unlike arm 5's "This red means something". INCONCLUSIVE on a
non-jetsam truncation (a runaway test OOMing the box, an operator `^C` masking a
hang, a signalled runner) labels a genuine defect "host, re-run when calm" and it
is never investigated — the exact class of error this chain exists to eliminate.

And `ci.yml:197-199` confirms both codes fail the lane ("exit 4 (INCONCLUSIVE)
fails this lane deliberately"), so only the diagnosis differs, and the summary
block still prints `host : DEGRADED` beside the RED — I confirmed that in probe
P3. The reader loses nothing.

**2. The positional `Running`-line join — MIS-NAMES, NEVER LOSES. Verified both
by construction and by probe.**

By construction: `claimed ⊆ reported`, and `reported` is the set of distinct bins
in `FAILURES_TSV`, each of which belongs to a target that printed a failure list.
Each bin is claimed at most once (`:898`). So crashes = N − |claimed| ≥ N − A.
The floor is exact, not approximate.

Probe P2 — 3 failing targets, 1 reporting binary, **zero** cause lines anywhere:
`crashed : 2`, both vanished targets named, `failing : 3 target(s) per cargo; 1
produced a failure list`, exit 1. The floor survived the rewrite.

Probe P1 — the adversarial mis-join, crashed target with **no `Running` line of
its own** and its `error:` line placed *before* the reporting target's:
`crashed : 1` (count correct, nothing lost) but the target named is `-p
orgasmic-daemon --lib`, the one that reported, and `--bin vanished` appears
nowhere. So the failure mode is exactly what the implementer claims.

**Can cargo produce P1's ordering? No.** `Running` and `error:` are both cargo's
own stderr and are therefore mutually ordered; the test binary's stdout is a
different stream but cargo *waits* for the child before printing anything
further, so the child's output is flushed and complete before the next `Running`
line exists. My real-cargo capture confirms the ordering
(`error: … --lib` immediately followed by `Running … (crashdemo)`). Residual risk
1 is correctly bounded and correctly ranked.

One cheap hardening if a future round touches this: when a named crash's
`matchbin` **is** in `reported`, the `note : … this target reported NO failures`
line is a false statement of fact about that target — the same falsehood F-2 was
filed for. Softening it costs one condition. Not required now.

**3. The cardinality floor survived — YES, by construction.** Argued above from
`claimed ⊆ reported` and claim-once, then confirmed by P2. `max()`, `CRASH_NAMED`
and `CRASH_UNACCOUNTED` are gone with no dangling reference
(`grep -n 'CRASH_NAMED\|CRASH_UNACCOUNTED\|TARGETS_ACCOUNTED'` → only a comment at
`:802`).

**4. The doctest special-case removal — SAFE. Verified against real cargo, not
against a fixture.** My own throwaway crate (lib red + `std::process::abort()`
bin + failing doctest, cargo 1.94.1) classified through the merged script:

```
  failures : 2
  crashed  : 1 target(s) died without reporting a failure list
CRASHED (1) — target died without reporting a failure list:
  --bin crashdemo
      why      : process did not exit successfully (signal: 6, SIGABRT: process abort signal)
  failing  : 3 target(s) per cargo; 2 produced a failure list
verdict: RED — 1 crashed test target(s) and 2 real failure(s)             exit 1
```

The doctest target claimed the `doctests` bin by identity and was **not** counted
as a crash; the SIGABRT bin was, and it is the one named. Identity matching
handles `Doc-tests <crate>` / `error: doctest failed` correctly with no
special-case.

**5. Row 4 — see F-8.** Not the next adjacent branch; not reachable from cargo.

**6. B2 left un-narrowed — DEFENSIVE DEPTH, AND LIVE. Not dead code.** My sweep
shows arm 7 firing and uniquely owning its cell: rows `exit 101 / no listed
failures / no crash` → `RED — cargo exited 101 with no per-test failure list`,
exit 1, on **all three** host states (it sits above `HOST_DEGRADED`, unchanged).
The real population is cargo refusing an argument, or a runner dying before
printing. The condition is broader than that population, but the excess is
unreachable while arm 4 stands — which is precisely what "backstop, not hole"
means. Correct as shipped.

**7. `.orgasmic/project.org:23` — TRUE of the shipped behaviour, and more precise
than what it replaced.** I checked the new sentence clause by clause against the
sweep. "0 and 101 … classify as usual, so a registered flake still returns GREEN
modulo N" — matches rows `0/flake/calm` and `101/flake/calm`. "any other exit …
RED (exit 1) in its own arm whatever else the run classified" — matches all 12
`137` rows including the degraded ones. The narrowing of the old sentence from "A
non-zero cargo exit that names no failing target" to "A **101** exit that names
no failing target" is the correction that makes the paragraph accurate, since
every other code is now owned above; I confirmed 101-with-no-listed-failures is
exactly arm 7's reachable population. This is not R-3's shape — it understates
nothing and overstates nothing. In scope call was right.

**8. What the real-cargo measurement settled — I re-ran it independently and it
holds.** Ordinary failing target: bare `error: test failed, to rerun pass
\`--lib\``, **no `Caused by:` block at all**. Cause line path absolute
(`/private/tmp/…/deps/crashdemo-19579ac6da30fc68`), `Running` line path relative
(`target/debug/deps/crashdemo-19579ac6da30fc68`) — so joining on the cause line
would indeed have matched nothing and called every target a crash. The
implementer's account of what changed the fix is accurate. Beyond the two shapes
they name, the dependency they did **not** name is F-6 above, and it is the only
one that fails green.
