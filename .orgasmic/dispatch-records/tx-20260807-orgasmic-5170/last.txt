## The measurement first (Open Question 1) — ANSWERED, and it changed the fix

Throwaway two-target crate in my own temp dir, `cargo test --no-fail-fast`,
**cargo 1.94.1 (Homebrew) / rustc 1.94.1**. Verbatim, the whole failing-target
tail:

```
test result: FAILED. 1 passed; 1 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s

error: test failed, to rerun pass `--lib`
     Running unittests src/bin/crashdemo.rs (target/debug/deps/crashdemo-19579ac6da30fc68)

running 1 test
error: test failed, to rerun pass `--bin crashdemo`

Caused by:
  process didn't exit successfully: `/private/tmp/.../target/debug/deps/crashdemo-19579ac6da30fc68` (signal: 6, SIGABRT: process abort signal)
   Doc-tests causeprobe
...
error: doctest failed, to rerun pass `--doc`
error: 3 targets failed:
    `--lib`
    `--bin crashdemo`
    `--doc`
```

**No. Real cargo does NOT emit `Caused by: … (exit status: 101)` for an
ordinary failing target — it emits no `Caused by:` block at all.** Only the
target that actually died got one. So on this cargo the `(exit status: 101)`
exclusion at `:841` was **dead code**, not the load-bearing guard on every red;
F-2's false RED was unreachable by that route here, exactly as the reviewer
bounded it. Claim 9's string is also settled: a failing doctest prints
`error: doctest failed`, never `error: test failed`.

**This measurement changed the fix.** The reviewer's fix direction — join NAMED
to UNACCOUNTED — needs a key, and the obvious key is the binary in the cause
line. That would have been wrong: cargo prints the binary **relative** on the
`Running` line (`target/debug/deps/crashdemo-…`) and **absolute** in the
`Caused by:` line. Joining on the cause line would have matched nothing and
called *every* target a crash. The join uses the `Running` path, which is the
key the failure blocks are already filed under. I would have shipped the
absolute-path join if I had not run this.

I then classified the real log through both the old and new script. Both give
`crashed : 1`, name `--bin crashdemo`, treat the doctest as reporting, exit 1.
The new detector reproduces the right answer on a real cargo log.

## Changed

`scripts/run-tests.sh`

1. **F-1 — a new RED arm for an anomalous suite exit**, beside the crash arm and
   above `HOST_DEGRADED`. `SUITE_EXIT_ANOMALOUS` is set from the **code**:

3. **F-2/F-3 — the crash detector unions by TARGET IDENTITY.** One row per
   failing target (`target`, match-binary from the `Running`/`Doc-tests` line,

   binary produced no parsed failure block; the cause line now only *explains* a

## Residual Risk

1. **The positional `Running`-line join.** A failing target with no cause line
   is matched to the most recent `Running (bin)` line. If cargo ever interleaves
   those out of order (merged stdout/stderr), a crash could be matched to a
   reporting binary and missed. Mitigated by claim-once — N targets against A
   reporting binaries still yield N−A crashes — so the count can never fall to
   zero while a target is unaccounted, but the *named* target could be wrong.
   Not observed: ordering was correct in the real cargo log I captured, and
   `cargo test` runs target binaries sequentially.
2. **One cargo version, one platform.** All of the above is cargo 1.94.1 on
   macOS. The `(exit status: …)` handling is now version-independent (it only
   explains, never decides), which is the point, but the `Running`/`Doc-tests`
   line shapes are still assumed.
3. **Open Question 2 is still open** — I did not determine whether anything in
   this workspace aborts today. The budget forbids running the suite, and the
   fix does not depend on it.
4. **Exit 0 with listed failures** (row 4) stays GREEN modulo N. That is
   contradictory input and pre-existing behaviour; my change does not touch it
   and I did not widen scope to it. It is the one remaining place where the exit
   code and the failure list can disagree without anyone saying so.
5. `SUITE_EXIT` is not validated as a signal-vs-status; 137 is reported as a
   number, not decoded as `SIGKILL`. Deliberate — decoding invites the SIGKILL
   carve-out F-5 said to leave alone.
