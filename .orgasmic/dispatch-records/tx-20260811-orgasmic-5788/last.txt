# Changed

- Replaced the fixed first-load waiter deadline with a production-derived coordinator budget: `ceil(active lane depth / lane permits) * (effective scan timeout + 200 ms coalescing) + 3 s`. With the default five-second scan timeout and two core permits, one wave is 8.2 s and five queued targets receive 18.6 s. Queue-delay diagnostics now state that the request is queued behind slow scans and explicitly avoid path or macOS permission claims.
- Added a per-`RefreshTarget` blocking-scan registry. A timed-out `spawn_blocking` scan remains guarded until the OS work really exits, retries do not create another blocking scan, late results cannot publish, and `/daemon/status.index_refresh` exposes `stale_blocking_scans` plus the effective `scan_timeout_ms`.
- Added the supported daemon environment override `ORGASMIC_PROJECT_SCAN_TIMEOUT_SECS`. Default is 5 seconds; accepted values are whole seconds from 1 through 300; zero, invalid, and out-of-range values are ignored with the bounded default retained. `orgasmic serve --help` documents it, and coordinator budgets derive from the effective value.
- Made full marker coverage attempt every authorized project. `GET /graph/markers/{node}` now returns aggregate `files`, successful per-project match counts in `projects`, and per-project error strings in `failures`. Scoped requests retain fail-fast behavior. CLI `status --errors` and Status/Notification UI retain successful parse errors and name skipped projects.
- Made unscoped `GET /tx` continue across project load failures while retaining successful project and admin home rows. The JSON array body is unchanged; `x-orgasmic-project-coverage` reports `complete|partial; loaded=[...]; failed=[...]`. Scoped filtering and failure behavior are unchanged. CLI and notification consumers surface partial coverage.
- Corrected project-local blocked-task counts: an active task is blocked only when a dependency is missing or not Done/Cancelled. Done and Cancelled dependencies are resolved without loading another project.
- Made `orgasmic reindex` print its useful partial JSON response and then exit non-zero whenever whole-board `failures` is non-empty.
- Changed only the 11 in-scope daemon, CLI, and UI source/test files shown by `git diff --name-only`; no supervisor, flake-registry, manager-owned ledger, live daemon, or LaunchAgent changes were made.

# Residual Risk

- `spawn_blocking` filesystem work is still intrinsically uncancellable; the bounded behavior is now that one stale thread per target is observable and prevents same-target retry fan-out until it exits. A permanently stuck OS call therefore keeps that target guarded, intentionally, rather than consuming unbounded threads.
- Partial transaction failure reasons are retained server-side while the compatibility-preserving array response exposes failed project IDs in the coverage header; consumers can identify skipped projects without a breaking body-shape change.
- Final commit SHA is produced and recorded by the atomic `orgasmic dispatch finalize --commit` call; see its terminal response.
