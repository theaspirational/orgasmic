## Changed

`crates/orgasmic-cli/src/manager.rs`

- **F1 — source of truth.** `worktree_submodule_refusal` now derives candidate
  submodule paths from the ANCHORED WORKTREE INDEX (`worktree_index_gitlinks`,
  `index_gitlink_paths`, `index_entries`, `index_varint`) — every mode-0160000
  cache entry, which is what git's `validate_no_submodules` reads. `.gitmodules`
  is kept as an ADDITIVE second source, never a substitute, and the admin
  `modules/` check stays as git's conservative first branch. Candidates are
  unioned, deduped, and each checked handle-relatively by the unchanged
  `nonempty_dir_under`, so git's `!is_empty_dir` rule (and therefore ruling 4)
  is preserved.
- **Fail CLOSED.** `worktree_index_gitlinks` returns three outcomes, not two:
  `Recorded(paths)`, `NoRepository`, `Unreadable(detail)`. `Unreadable` is a
  REFUSAL — the index did not open, did not parse, has an entry with no path
  (how a split index defers to a shared index), declares an unsupported version,
  or its entries do not land exactly on a well-formed extension chain and
  trailing hash. `gitmodules_paths` now returns `Result` for the same reason: a
  `.gitmodules` that EXISTS and cannot be read is a refusal, where it previously
  read as "no submodules".
- **Where the index is.** A linked worktree keeps its OWN index under the admin
  directory its `.git` file names — measured on git 2.52.0:
  `<project>/.git/worktrees/<id>/index`, NOT `<project>/.git/index`. The two
  cases are resolved separately: `.git` a real directory → `.git/index` opened
  `openat`-relative to the worktree handle; `.git` a `gitdir:` file → the admin
  directory is outside anything this verb anchors or deletes, so it is resolved
  by pathname, the same boundary `worktree_repo_state` and
  `worktree_admin_dir_holds_modules` already take. Proof that this is the right
  file: the F1 regression's gitlink exists ONLY in the linked worktree's index,
  and the refusal fires (it would not if the project index were read — the
  project's own worktree is not what is being classified) — plus the unit test
  `worktree_submodule_refusal_fires_on_a_populated_gitlink_and_not_a_placeholder`
  runs the predicate against a real linked worktree through the anchored handle.
- **F2 — placement.** The categorical refusal moved ABOVE the `RepoGone` early
  return in `reclaim_managed_worktree`, so it precedes every destructive branch
  rather than only `Unclaimed`. No product ruling was encoded: `RepoGone` still
  reclaims, it just cannot reclaim a populated submodule.
- **F3 — comment vs code.** CHOSE: rewrite the statement to match the code.
  Reason: the narrower guarantee the old wording claimed is not one this shape
  can offer. Taking the asserts down to every path-resolving `execve` would not
  close the window the reviewer actually demonstrated — that one is BETWEEN two
  subprocesses of a single call (`git worktree list`, then `git status`), so an
  actor never has to hit an assert-to-`execve` gap at all. The comment now names
  the three real windows (`worktree_head_oid` with no assert of its own; six-plus
  salvage subprocesses behind one assert; the list-then-status ordering) and
  states the bound that IS real: the deletion is identity-anchored and cannot be
  redirected, but the inode removed can be the dirty unsalvaged one.
- **F4.** The cfg-off proof's comment named `scripts/run-tests.sh
  --release-gates`, which does not exist. It now names the real invocation:
  `scripts/run-tests.sh -p orgasmic-cli` (or `--workspace`), which runs the leg
  automatically as a second `cargo test -p orgasmic-cli --bin orgasmic` under
  `RUSTFLAGS=-C debug-assertions=off`.
- **Operator help.** `after_help` said a repo-gone worktree "is removed with NO
  salvage" with no refusal named; it now says the submodule refusal is
  CATEGORICAL, runs before every removal including the repo-gone one, reads the
  worktree's INDEX plus `.gitmodules`, and that an unreadable record is itself a
  refusal.

## Residual Risk

**A THIRD DIVERGENCE, reported rather than folded in.** Ruling 1 says an index
that "cannot be opened" must refuse. Taken literally that also covers a
`RepoGone` orphan, where the index is gone WITH the repository — and that would
make `RepoGone` reclamation impossible in every case, since the classification
IS "the admin directory the `.git` link names is absent". Measured, not argued:
that reading takes the shipped acceptance test
`worktree_prune_removes_a_worktree_whose_repo_is_gone` red.

So `worktree_index_gitlinks` separates "unreadable" from "there is no repository
at all", and only the first refuses. In the `NoRepository` case the predicate is
the admin `modules/` check plus `.gitmodules` — which is why the F2 regression
(ordinary submodule + RepoGone) is refused, since `.gitmodules` is a working-tree
file that survives the admin directory going away.

**The gap this leaves:** a submodule recorded ONLY in the index AND whose
repository is gone is not seen — the F1 shape and the F2 shape at the same time.
It is not reachable from either new regression, git itself has no verdict there
(it cannot run `worktree remove` without the repository), and closing it would
need a disk-only heuristic (refuse any nested `.git`), which would refuse
vendored repositories under `node_modules` and is the "round five from the other
side" ruling 4 warns about. **This is a product call I do not have.** If the
ruling is that unknown-means-keep must win over `RepoGone` reclaimability, the
change is one line — make `NoRepository` refuse — plus retiring
`worktree_prune_removes_a_worktree_whose_repo_is_gone`.

**Other residuals.**

- F3's window is narrowed and now honestly described, not closed. Closing it
  needs git to accept a directory handle, or the clean decision computed from
  the handle the way the submodule refusal now is.
- The index parser picks the object-hash length by trial (SHA-1, then SHA-256),
  validated by requiring the entries to land exactly on a well-formed extension
  chain and trailing hash. Both formats are covered by git-written fixtures, but
  a future index format git introduces would be `Unreadable` — i.e. a refusal,
  which is the safe direction, though it would make the verb refuse until taught
  the format.
- The refusal reads the index through a pathname when `.git` is a `gitdir:`
  file, because the admin directory is outside the anchored tree. That is the
  pre-existing boundary of `worktree_repo_state` and the admin-`modules/` check,
  not a new one, and nothing there is ever deleted by this verb.
- No runtime malicious-`.gitmodules` traversal test was added (the reviewer
  cleared C2 at source level and scoped it out); the same anchored walk now also
  carries index-derived paths, which are equally rejected on `..` and resolved
  with `openat(O_NOFOLLOW|O_DIRECTORY)`.
- The runtime was NOT reinstalled and `~/.orgasmic/bin/` was not touched, per
  the assignment. The shipped operator binary still carries the un-gated verb
  until someone reinstalls.
