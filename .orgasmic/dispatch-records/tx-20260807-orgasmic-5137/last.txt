## Changed

### `scripts/run-tests.sh`

1. **Crash detection from the log (R-1).** New section after `FAIL_COUNT`,
   independent of both `SUITE_EXIT` and `FAIL_COUNT`. Two derivations, unioned:
   - **NAMED** — the `error: <kind> failed, to rerun pass \`<target>\`` →
     `Caused by:` → `  process didn't exit successfully: \`<bin>\` (<cause>)`
     sequence, which yields the target, the binary and the signal. **`(exit
     status: 101)` is explicitly excluded**: 101 is libtest's own "tests failed"
     code, and counting it would redden every ordinary red — M-1 by another
     route. This exclusion also makes the detector correct whether or not cargo
     emits a `Caused by` for ordinary 101 failures, which I did not need to
     settle empirically.
   - **UNACCOUNTED** — `count(error: test failed, to rerun pass)` minus
     `count(distinct non-doctest binaries that produced a parsed failure
     block)`, floored at 0. Doctests are excluded from both sides (a failing
     doctest prints `error: doctest failed`, so it is on neither side).
   - `CRASH_COUNT = max(NAMED, UNACCOUNTED)`.
2. **`CRASHED (n)` section** naming target, binary, signal, and why it cannot be
   classified; plus an unnamed remainder block when UNACCOUNTED exceeds NAMED.
3. **An always-present `crashed  :` summary line**, because `failures :` counts
   listed failures only and a crash is invisible there *by construction*.
4. **A new RED arm** above `REAL_COUNT`, above `FAIL_COUNT > 0` and above
   `HOST_DEGRADED` (below only the billed-test and build-failure arms). It names
   the real count too when both are present.
5. **Suite-exit stamp (R-2).** `write_suite_exit_stamp` / `read_suite_exit_stamp`
   mirroring `write_host_stamp`; `# orgasmic-suite-exit: <n>` is appended by both
   live branches, and `--classify` reads it instead of `?`, falling back to `?`
   only for pre-stamp logs.
6. Header docs + the B2 arm comment updated to say what is now true.

**The `FAIL_COUNT` guard on the B2 arm is untouched** — same line, same
conjunct. The crash arm is a separate arm above it.

## Residual Risk

1. **The B2 arm is now narrow.** It fires only on a non-zero exit that names no
   failing target. I judged that right — a named failing target is either
   accounted for or a crash — but it is a genuine narrowing, so I pinned it
   (case 4) rather than leave it to inspection.
2. **The UNACCOUNTED cardinality diff is conservative.** A failing target whose
   failures the parser fails to attribute reads as a crash. That direction is
   RED, never green, and I preferred it that way — but a future parser change
   could produce a puzzling `CRASHED` line where the truth is "unparsed".
3. **`open_owner()` picks the first open task id in `backlog.org`.** Deterministic
   and self-healing, but the fixture's owner id now varies between runs on
   different boards. Two assertions interpolate `$FIXTURE_OWNER` rather than a
   literal, which is slightly less legible than the old hardcoded string.
4. **I did not run the real suite**, so I have no evidence about the reviewer's
   open question ("does any test in this workspace actually abort today?"). The
   fix does not depend on the answer.
5. **Not verified against a real `cargo` binary.** Every case runs a stub. The
   log shapes are taken from the reviewer's verbatim cargo output in the round-4
   review, and the `(exit status: 101)` exclusion is what makes the detector
   correct regardless of whether cargo emits a `Caused by` for ordinary reds —
   but the first real crashed binary is still the first true end-to-end test.
