## Decided rule for `dispatch-close --property` (tx metadata, not a drawer)

Tx metadata is an OPEN annotation vocabulary, unlike the schema-read task
drawer: `TxHeadingView::from_heading` passes every non-KNOWN key through as
extras, and readers (`extra()` in manager.rs:9765, first-wins) match keys
byte-for-byte — the same case-sensitivity trap as `Heading::property`, so a
miscased key would be RECORDED on the ledger and never read. Therefore the
correct boundary rule is exactly what the CLI already enforced: refuse any key
that is not UPPERCASE snake at parse time (an open key set with a closed case
rule). TASK-ZKZBF only made that refusal name the canonical spelling instead
of a bare pattern. The one silent drop on the surface (aborted status
discarding every `--property`) is now a by-name refusal, because the abort tx
has no generic property channel and inventing one would widen the task;
manager-owned-key precedence (first-wins override, TASK-4WKNX.1.1) was
measured, is deliberate/documented, and was left untouched.
