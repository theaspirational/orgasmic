# Changed

- Replaced per-mutation refresh amplification with a detached 50 ms trailing-edge coordinator keyed by project/home tx. It deduplicates tx ids, serializes each target, limits global project scans to two, discards stale required generations, keeps watcher follow-ups background-only, and owns convergence after waiter cancellation.
- Moved project/home snapshot construction to `spawn_blocking` private snapshots and reduced index write-lock publication to board verification plus atomic project/tx/parse-error replacement. Preserved last-good behavior and rebuilt activity from the current tx set at publication.
- Removed the `TxAppended` index listener and duplicate API refreshes. All node/task/goal/graph/artifact/raw-tx paths now await one `refresh_after_tx(..., tx_id)` before success and publish mutation events afterward.
- Kept Git probes asynchronous and outside normal refresh/mutation metrics; registration and explicit reindex schedule probes while preserving prior repo URLs.
- Added committed-but-refresh-failed HTTP 503 JSON and CLI reconciliation wording that forbids blind retry.
- Added boot-local writer/index refresh status metrics and >=1s slow-operation logs.
- Added deterministic coordinator, cancellation, stale-generation, read-responsiveness, global-limit, stalled-Git, 503, CLI, last-good, watcher, idempotency, and immediate-visibility coverage plus `verify/TASK-K9WWM/README.md`.

Measured root cause: timeouts were refresh-path amplification exposed by concurrency, not an intrinsically insufficient client budget. The generic 10s and release 30s budgets stayed unchanged; five parallel reviewer-close repetitions were 25/25 green (4.64-7.16s per five-test filter), and five 16-request batches each measured requests=16/scans=1/coalesced=15 (0-4ms scans).
