# Changed

- Made `walk_worktree` propagate its existing depth, directory-listing, and child-open failures. `scan_managed_worktrees` now converts any incomplete preliminary traversal into an explicit non-reclaimable `UnsafeTraversal` disposition, so `worktree-prune` prints `SKIP` before reservation or deletion.
- Kept the anchored directory-handle traversal, `anchored_dir::MAX_DEPTH`, and removal error propagation unchanged. Added direct parity tests proving both chmod-000 and generated over-depth trees are also refused by `remove_dir_all_at` with `touched == false` in pure-chain fixtures.
- Added production-path CLI fixtures for a chmod-000 descendant and a generated tree beyond the 64-level bound. Both assert the real verb reports the unsafe candidate, reclaims nothing, emits no `PARTIAL`, and preserves sentinels sorted before and inside the unsafe branch. The permission fixture uses a Drop guard to restore mode and deliberately fails under a privileged account instead of returning a meaningless pass.
- Made operator semantics explicit in `manager worktree-prune --help`: preliminary traversal failures are skipped untouched; `KEPT` means deletion removed no content; `PARTIAL PATH=...` is a failed incomplete removal after content deletion and is not reclaimed.
- Split `PRUNE_SUMMARY` into truthful `PARTIAL` and `KEPT` counters instead of counting partial removals under `KEPT`. Extended the existing partial-removal regression and help parity test.
- Changed only `crates/orgasmic-cli/src/manager.rs`, `crates/orgasmic-cli/tests/dispatch.rs`, and `crates/orgasmic-cli/tests/cli_parity.rs`. No destructive command was run against an operator worktree, and no daemon install/restart was performed.
