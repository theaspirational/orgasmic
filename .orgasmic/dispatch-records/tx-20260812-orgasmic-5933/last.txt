## Changed

- Added `TxWriter::sync_data`, which calls `sync_data` on the append descriptor retained by `TxWriter`.
- Replaced both daemon post-append pathname reopens with `sync_tx_writer`, which finds the cached writer and syncs its retained descriptor. The existing unique-path `HashSet` still gives one sync per tx path per coalesced batch; `before_sync`/`after_sync`, pre-append inode validation, acknowledgement denial, and transaction rollback ordering remain intact.
- Added regressions for retained-descriptor sync after the pathname is renamed away, rewrite rollback after injected tx-sync failure, and the exact `cached mutation lacks its recorded identity` per-request error followed by a successful next writer command.
- Reconciled the broader TASK-BX5SR acceptance against the current tree: the historical cached-transaction success/error `continue` paths that exited the writer loop were already replaced by non-exiting match arms in `fa12132`, and `/api/daemon/status` already exposes `writer.liveness` plus queue/in-flight/failure metrics.

## Unmet Criteria

- `orgasmic doctor` does not currently deserialize or report the status response's `writer.liveness`; that implementation is in `crates/orgasmic-cli/src/doctor.rs`, outside this dispatch's declared write scope.
- The writer task is not restarted/supervised in place. A dead writer is visible as `writer.liveness: false` in status, but the daemon can continue serving reads. Adding daemon fail-fast or safe restart ownership is a separate recovery/supervision change beyond the retained-descriptor correction.
- The source-level producer of `cached mutation lacks its recorded identity` is a cached `WriterHandle::transaction` result (`mutation_id: None`) replayed as an identity-returning mutation with the same semantic identity. The regression proves that exact writer-loop error is now request-local. The current `manager dispatch-close` source uses distinct deterministic IDs for its close tx and lifecycle leg, so the exact historic request sequence that reached this error from the 2026-08-02 call is not reproducible from the current tree/logs inspected here.
- No durable daemon-independent fallback was added for `dispatch finalize`; it remains a broader CLI/runtime contract and is outside the two-crate write scope.

## Residual Risk

- This intentionally preserves the pre-append pathname/inode validation but does not solve an external atomic replacement after validation. The retained descriptor makes the already-appended bytes durable without a second blocking `open`; it does not promise that the pathname cannot be replaced concurrently.
- No live daemon/service was restarted, installed, or otherwise mutated during implementation.
