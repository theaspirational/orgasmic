## Changed

- Chose a production deadline/coordination fix; added no flake-registry entry.
- `crates/orgasmic-daemon/src/supervisor.rs`: `probe_command_stdout` now starts its enforceable child-runtime deadline immediately after successful `Command::spawn`, so synchronous warm-host spawn latency cannot consume a deadline that cannot yet kill anything. Process-group kill, wait/reap, and stdout-drain semantics are unchanged.
- Reworked the hung-mux supervisor regression to assert the safety contract instead of a host-sensitive `< WORK_PROBE_TIMEOUT` wall clock: the stalled run is released, its bare `stall_timeout_exceeded` tombstone proves `WorkEvidence::Unknown` supplied no false work credit, and the concrete hung child disappears.
- `crates/orgasmic-daemon/src/api.rs`: the rmux recovery test now holds the test-environment lock, pins the process to `own_rmux_server_for_tests`, registers that endpoint with `live_guard.owns_runs_on(server)`, and confirms the fixture session exists on that owned server.
- Captured source-of-truth failure evidence: exact panics were `the stub recorded its \`sleep\` pid` and `the sweep must be bounded`. They occurred across eleven warm-host runs while `syspolicyd` rate climbed 0.36 to 1.46 and did not recover after five minutes idle; every failure passed in isolation, an ignored new API test did not remove them, and interleaved unmodified baselines were green. A rested-host control was green at syspolicyd rate 0.1070 and load 1.69.
- Landing order: TASK-4BBA6 (put the syspolicyd watchdog in `run-tests.sh`) should land before TASK-P4XKT (repeat passing tests), because repetition deliberately raises execution load and must first be guarded. This fix should be present before P4XKT repeats this probe family, so repetition measures the repaired invariant instead of amplifying the old false-red cost.
