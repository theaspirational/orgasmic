# TASK-2QK4P.1.1.1 — a predicate that could not look must not answer "false"

Round four on one generating shape: **a `bool` that means "I verified and it is
false" and also means "I could not check."** The deliverable asked for is the
enumeration, so it leads.

## Acceptance 1 — THE ENUMERATION (the completeness argument)

Every predicate on the recovery-authority path returning `bool` or `Option`,
with what it does when it *cannot observe*. Line numbers are post-fix.

The path is what `POST /runs/:id/recover` and `GET /runs` reach when deciding
recovery authority: `post_run_recover` → `recovery_status_inner` →
`apply_recovery_claim_to_run` → `resolve_authoritative_recovery_claim` →
`{ProjectOriginAuthority, index_recovery_origins_in_session,
load_recovery_claim, verify_committed_claim_against_session,
reconstruct_or_quarantine}`, plus boot reattach's routing hint.

### A. Pure over already-observed bytes — cannot fail to observe. UNCHANGED.

The envelopes were already read; a `false`/`None` here is a decided fact about
their content. Every `serde_json::from_value::<Lifecycle>(..).ok()` inside these
is the same: a line that does not deserialize as a lifecycle event *is* not one.

### C. Fallible — deliberately NOT changed, with the reason stated.

- **`tmux_session_exists`** (orgasmic-drivers `modes/tmux.rs:879`) — collapses a
  spawn failure into "no session". It is on the path
  (`reconcile_pending_claim`), and it *is* the class. It is left alone because
  its negative fails **closed**: `claim.spawn_started && !tmux_live` →
  `DeadPlannedHandle`, a refusal that never quarantines, never mints and never
  writes. Fixing it means giving the sync probe a `Result` (the async
  `has_tmux_session` already has one) and threading it through
  `reconcile_pending_claim`, which is a driver-API change outside this task.
  **Residual: a transient tmux failure turns a live rescue into a permanent
  `DeadPlannedHandle` refusal rather than a retryable one.**
- **`#[cfg(not(unix))]` `Path::exists()`** in `load_recovery_claim` (:1279),
  `quarantine_invalid_claim` (:1322) and the non-unix
  `pending_recovery_claim_owns_session`. Unix is the shipped target and every
  unix branch is classified; the non-unix fallbacks keep the old collapse.
- **`recovery_origin_authority`** (api.rs:8834-8880) — `canonicalize()`,
  `read_existing_project_identity()`, `SessionDirectory::open()`,
  `read_checked()` all `.map_err(|_| bad_request(...))`. Every negative is a
  **refusal**; none mints or quarantines. The defect here is only that a
  transient failure is reported as 400 (your request is wrong) rather than 503
  (retry). Not safety; not fixed this round.

## Findings

### F1 — reproduced first, red before the fix

Both halves were built as running reproductions before the fix, as the brief
required (the review derived them and built none).

- **(a)** `an_authority_key_read_failure_cannot_hide_a_second_authenticated_replacement`
  (recovery_claim.rs). Two daemon-HMAC-authenticated replacements for one
  origin; every file readable; the enumeration completes; ONE `authority_key`
  read fails. The fault is swept across read positions because `read_dir` order
  is not ours to choose. **Red under the injection**: the resolver quarantined
  the loaded claim and returned
  `Reconstructed(RecoveryClaim { … replacement_run_id: "run-hidden-second" … })`
  — the daemon silently changing which replacement holds the lease. It was
  wider than "returns `Valid`".
- **(b)** `a_read_failure_after_a_cached_complete_enumeration_never_quarantines`.
  The enumeration completes and is **cached** first (asserted as a premise), so
  none of round three's machinery is involved; then the replacement session, and
  in a second pass the origin session, is made unreadable (`chmod 000`, real
  fault, no hook). **Red under the injection**: `InvalidQuarantined`.
- Test-only fault injection added for the key read only
  (`arm_authority_key_fault`, keyed by token path so concurrent tests cannot
  consume each other's arming). No filesystem fault can fail the *nth* read of
  one file and not the others, and the finding is about position.

### F2 — one POST, one enumeration

`recovery_status_inner` now takes `&mut ProjectOriginAuthority` instead of
building one. `post_run_recover` builds it once and hands it to both the
inventory classification and the claim/mint decision.

**Cost of every pass, reported:** `ProjectOriginAuthority::cost()` is written
into `inventory.origin_index_files` / `origin_index_bytes_inspected` at the end
of `recovery_status_inner`; every later `links_for` in the same POST is a cache
hit costing zero, so that metric is now the decision's **complete** cost. Before
this, the second pass was invisible to `cost()` and absent from the metrics.

Endpoint-level scan-count test: `one_recover_post_enumerates_the_project_once`
(api.rs), counting through `recovery_claim::origin_enumeration_passes` — a
counter outside both authority objects, keyed by project root.
`one_authority_serves_every_claim_in_a_project` cannot see this defect because
it hands both callers the same object; the new test's red is `left: 2, right: 1`.

### F3 — ordering, not relaxation

Authority-independent validation (unknown action → 400, unnamed action with
several available → 409, terminal-Failed `reattach_tmux` → 400) now runs before
the completeness 503. The completeness check stays **immediately** before the
claim branch, which is the first thing that can accept or mint authority.

Two subtleties, both load-bearing:

- Validation uses the **un-suppressed** action set. An unresolved enumeration
  empties `recovery_actions`, so validating against that would just move the
  defect. `RecoveredRun` gained `recovery_unobserved` and
  `suppressed_recovery_actions` for exactly this.
- An **empty** offered set is deliberately not validated early: it also means
  "an authoritative committed claim suppressed the actions", and that request is
  an **idempotent replay** which must answer with the existing replacement.
  Missing this broke
  `recovery_faults_kill_real_daemon_and_preserve_original_pane` on the first
  attempt (400 "recovery action start_recovery_run is not valid") — caught and
  fixed; 10/10 green after.

`an_invalid_action_answers_400_even_while_the_enumeration_is_unresolved` asserts
both directions, so an injection that merely deleted the refusal fails it too.

### F4 — the tear shape is checked at the boundary

`scan_session_lifecycle_complete_reader` now records whether the malformed line
was newline-terminated and tolerates only a **non-terminated** final fragment.
The regression uses the production tear shape (`{TEAR}` with no `\n`, where
round three supplied `{TEAR}\n` — a shape the writer cannot produce as a torn
append), plus a newline-terminated-corruption case that stays unresolved, plus a
third case proving the tolerance is for the tear and not for "the last line".

## Acceptance 3 — the pin the review defeated

The old pin asserted `code.contains("Unobserved {\n        reason:
UnobservedSession,")` — a **prefix**, so adding a `links` field after it kept the
pin green — and inspected two declarations.

- Renamed to `the_recovery_authority_types_cannot_spell_failure_as_a_decided_negative`.
  It extracts each unresolved variant **whole** (brace-matched) and compares for
  **equality** against the exact payload each type is allowed. Probed: with the
  expected payload set to round three's prefix, the assertion fires and prints
  `left: "Unobserved { reason: UnobservedSession, bytes_inspected: u64, }"` /
  `right: "Unobserved { reason: UnobservedSession, }"`. It is not a prefix match.
- Four declarations, not two: `IndexedRecoveryOrigins`,
  `AuthoritativeOriginLinks`, `ClaimEvidence`, `ResolvedRecoveryClaim` (the last
  gained `#[must_use]` so the pin can hold all four to one rule).
- It also asserts the three named predicates have not gone back to `-> bool`.
- **And it says plainly what a source-text pin cannot express**, in its own doc
  comment: the property is "no predicate answers a decided negative when it
  could not look", which is a claim about ~20 call sites, not a shape.
  `no_observation_failure_on_the_authority_path_confirms_or_destroys` is the
  **behavioural** pin — a table of five injected observation failures (unreadable
  auth key, replacement, origin, sessions directory, torn sibling) against a
  fixture that resolves `Valid` with nothing injected, demanding of each: never
  `Valid`, never a quarantine, claim byte-identical, normal resolution after
  repair.
- The structural pin stays **GREEN** under this round's injection, deliberately:
  the injection changes which variant the code constructs, not any type's shape.
  A red pin there would mean it has started measuring behaviour and stopped
  guarding structure, which is how round three's pin came to pass on its defect.

## Acceptance 7 — the two regressions

- `an_nth_authority_key_read_failure_never_quarantines_a_healthy_claim` — sweeps
  the fault across read positions against a healthy claim; for every position
  that fires, asserts `Unobserved(AuthorityKeyUnreadable)`, no quarantine, claim
  file byte-identical; then repairs and asserts `Valid`. Also asserts the fault
  fired at least once, so the sweep cannot pass vacuously.
- `a_read_failure_after_a_cached_complete_enumeration_never_quarantines` —
  asserts additionally that the session directory still holds exactly two files
  ("origin plus one replacement, and nothing minted") and that the cached
  enumeration was reused rather than rebuilt.

"No new replacement" is also proved on the production path by
`recover_refuses_to_mint_while_a_session_file_is_unreadable` (unchanged) and by
the new F3 test's 503 arm.

## Residual Risk

1. **F4 widens what suppresses recovery.** Any `.jsonl` in a project's sessions
   directory whose final line is complete-but-malformed now makes that project's
   enumeration `Unobserved` until the file is repaired — previously such a line
   was forgiven at EOF. The refusal is non-destructive and retryable (503, no
   quarantine), and acceptance 6 asked for exactly this, but it is a real
   liveness change and it is what broke the forged-claim test. Note
   `line_is_lifecycle_relevant` treats *any* line whose header is not
   `"kind":"driver_event"` as relevant, so the class of files that can do this is
   wider than "session envelopes".
2. **`tmux_session_exists` is still the class**, deliberately unfixed (section C).
   A transient tmux failure turns a live pending rescue into a permanent
   `DeadPlannedHandle` refusal rather than a retryable one. Fail-closed, never
   destructive; wants a follow-up that gives the sync probe a `Result`.
3. **Boot reattach now skips on `Unobserved`.** An unreadable auth token at boot
   makes `pending_recovery_claim_owns_session` unobserved for every candidate, so
   no run in that project is reattached until the next boot. Fail-closed and
   retried, but it is a behaviour change with a cost.
4. **`RecoveredRun` gained two serialized fields.** `recovery_unobserved` and
   `suppressed_recovery_actions` are additive and `skip_serializing_if`-guarded,
   but the UI does not render them yet — an operator seeing empty actions still
   has to read `reason` to learn why.
5. **The non-unix branches keep the old collapse** (section C). Unix is the
   shipped target; nothing in CI exercises the others.
6. **The 340 ms full scan stands**, per the reviewer's ruling — F2 removed the
   duplicate POST pass, not the pass itself. A completeness-generation design is
   still wanted before release.
7. **`remove_recovery_claim` still has no caller.** Left alone per the brief's
   ruling 5; not a performance fix.
